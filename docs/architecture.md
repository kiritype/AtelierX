# 구조

AtelierX의 프로그램 구조와 기술 선택을 정한다. 데이터 형식은 [data-model.md](data-model.md), 기능의 동작은 [features/](features/README.md).

## 전체 모습

```text
┌──────────── 데스크톱 창 (개발 중에는 브라우저) ────────────┐
│ 화면: 빌드한 정적 파일 (TypeScript + React, Vite 빌드)       │
│   ├─ 편집기 (CodeMirror 6)                                   │
│   └─ JSX 미리보기 (격리된 iframe)                            │
└───────────────▲──────────────────────────▲──────────────────┘
                │ HTTP(JSON) · 이벤트 스트림(SSE)            │
┌───────────────┴──────────── 로컬 서버 (Python) ─────────────┐
│ 인증·세션 │ 작품·파일 │ 스냅샷 │ 검사 │ LLM │ 작업 대기열·GPU │
│ 금고      │ 파일 감시 │ 내보내기 │ 설정 │ (7단계) 이미지 생성 │
└───────────────┬──────────────────────────┬──────────────────┘
                │ 파일                      │ HTTP
        앱 폴더 (config, state, data, output)   로컬 LLM 서버 · 이미지 생성 서버
```

- 서버와 화면은 같은 PC의 `127.0.0.1`에서만 이야기한다. 서버가 화면 파일도 함께 제공한다(웹·데스크톱 창 같은 방식).
- 데이터는 모두 서버가 읽고 쓴다. 화면은 파일 시스템에 직접 손대지 않는다.

## 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 서버 언어 | Python 3.12 | 이미지 생성·학습 도구와 같은 생태계. 로컬 LLM·토크나이저 라이브러리가 많다 |
| 서버 틀 | Starlette + uvicorn (비동기) | 응답 스트림(SSE), LLM 스트리밍, 파일 감시 이벤트를 다루기 쉽다. 의존성이 작다 |
| 화면 언어·틀 | TypeScript + React | JSX 미리보기가 어차피 React를 쓰므로 한 생태계로 맞춘다 |
| 화면 빌드 | Vite | 결정 0004 |
| 편집기 | CodeMirror 6 | Markdown·JSX 강조, 큰 문서, 확장성. 무겁지 않다 |
| JSX 변환 | 미리보기 iframe 안의 Sucrase | 미리보기 직전에 JSX → JS. 서버에 Node가 필요 없다 |
| YAML | ruamel.yaml | 키 순서·모르는 필드 보존(결정 0005) |
| 암호화 | 표준 `hashlib.scrypt` + `cryptography`(AES-GCM) | 결정 0011 |
| 파일 감시 | watchfiles | OS별 감시 기능을 하나로. 안 되면 주기적 확인으로 대신 |
| 토크나이저 | `tokenizers`(Hugging Face) | `tokenizer.json` 형식 |
| 데스크톱 창 | pywebview | Python 하나로 묶을 수 있다. Windows는 WebView2 사용 |
| 배포 묶음 | 포터블 폴더(내장 Python + 빌드한 화면) | 결정 0010. `app/`만 바꾸면 업데이트 |

- 테스트: 서버는 pytest, 화면은 Vitest. 코드 형식 검사: ruff, Prettier.

## 서버

### 요청과 이벤트

- API는 `/api/…` 아래 JSON. 오래 걸리는 일은 바로 작업 ID를 돌려주고 진행은 이벤트로 알린다.
- 이벤트 스트림 `GET /api/events`(SSE) 하나로 작업 진행, 알림, 파일 변경, 잠금을 보낸다. LLM 응답 스트리밍(테스트)은 요청별
  스트림을 쓴다.
- 서버 오류 메시지는 `Msg(key, 영어 문장, 값…)`로 만들고, 화면이 언어에 맞게 보여 준다. 예외 문장을 그대로 보내지 않는다.

### 인증과 세션

- 금고를 열면 서버가 무작위 세션 토큰을 만든다. 토큰은 HttpOnly·SameSite=Strict 쿠키로 화면에 준다.
- 인증 관련 요청 외에는 모든 요청에서 세션을 확인한다. 이벤트 스트림도 마찬가지다.
- 요청의 `Origin`·`Host`가 앱 자신이 아니면 거절한다(다른 웹 페이지가 로컬 서버를 부르는 것을 막음).
- 서버는 `127.0.0.1`에만 묶는다. 다른 PC에서 접속하는 기능은 두지 않는다.
- 잠그면 세션을 지우고 금고 내용을 메모리에서 지운다.

### 저장소

- 모든 쓰기는 임시 파일 → 바꿔 넣기. 작품마다 쓰기 잠금 하나로 같은 파일을 동시에 쓰지 않는다.
- 항목 ID 색인(ID → 경로, 종류, 해시)을 메모리에 두고 파일 감시로 갱신한다. 색인은 다시 만들 수 있는 파생 데이터라 디스크에 둘
  때는 `cache/`에 둔다.
- 저장 요청은 디스크 해시를 함께 받아, 그사이 바뀌었으면 충돌로 거절한다([02](features/02-editor.md)).

### 작업 대기열과 GPU

- 작업: 종류, 대상, 상태(대기, 실행 중, 완료, 실패, 취소), 진행률, 결과(임시 항목 ID 등). `state/queue.json`에 남긴다.
- GPU는 한 번에 한 쪽만 쓴다: 이미지 생성, VLM 검수, 학습, 이미지 서버 제어, 이 PC의 GPU를 쓰는 LLM 요청.
  - LLM 요청은 진행 중인 이미지가 끝난 뒤 시작하고, 요청이 모두 끝날 때까지 새 이미지는 시작하지 않는다. 같은 쪽 LLM 요청끼리는
    함께 보낼 수 있다(순서는 LLM 서버가 정한다). 기다리는 동안 대화·에이전트 화면에 무엇을 기다리는지 보인다.
  - 대화 테스트·에이전트처럼 흘려 받는 응답도 같은 규칙을 따른다. 멈추거나 실패하면 바로 GPU를 돌려준다.
- 그 밖의 LLM 요청(외부 API)은 GPU를 기다리지 않고, 설정의 동시 실행 수(`jobs.api_concurrency`)만큼 함께 보낸다.
- 잠금 중에는 외부 API 작업을 시작하지 않는다([00](features/00-shell.md)).

## 화면

- 단일 페이지 앱. 화면 상태는 작품 단위로 나눈다(열린 탭, 선택, 패널).
- 서버 데이터는 요청 캐시 라이브러리(TanStack Query 등)로 다루고, 이벤트 스트림으로 무효화한다.
- 문장은 모두 i18n 키로 쓴다. 카탈로그는 언어별 JSON(`ko.json`, `en.json`).
- 데스크톱 기능(폴더 고르기, 알림, 창 제목)은 작은 다리 하나로 감싼다. 데스크톱 창이면 pywebview API를, 브라우저면 대체 화면을 쓴다.

### JSX 미리보기 격리

- 미리보기는 `sandbox="allow-scripts"` iframe(같은 출처 아님)에서 돌린다. 앱 화면·쿠키·서버 API에 닿을 수 없다.
- iframe 문서에 콘텐츠 보안 정책을 걸어 외부 네트워크를 막는다. React 등 실행 환경은 앱에 들어 있는 파일만 쓴다.
- 화면과 iframe은 메시지로만 이야기한다: 소스(변환된 JS), props, 플랫폼 제공 함수 목록 → iframe, 렌더링 오류·대역 호출 기록 → 화면.
- 일정 시간 응답이 없으면 iframe을 새로 만든다(무한 반복 대비).
- 미리보기는 별도 페이지(`preview.html`, 빌드 때 따로 묶음)다. 출처가 없는(opaque) iframe이 앱의 스크립트 파일을 모듈로 읽으므로,
  서버는 `/assets/`에 `Access-Control-Allow-Origin: *`를 붙이고(번들 파일만, 비밀 없음) 개발 서버는 `Origin: null`을 허용한다.
- 일부 내장 브라우저는 sandbox iframe을 막는다. 미리보기가 열리지 않으면 화면에 그 사실을 알린다.

## 앱 시작

1. 실행 파일이 내장 Python으로 서버를 띄운다. 앱 폴더 기준으로 `config/`, `state/`, `data/`, `output/`을 확인하고 없으면 만든다.
   처음이면 기본 가이드라인·이미지 라이브러리·로컬 LLM 연결을 `data/`에 복사한다.
2. 단일 실행 잠금(`state/` 안의 잠금 파일 + 포트 기록). 이미 실행 중이면 그 창을 앞으로 가져오라는 신호를 보내고 끝낸다.
3. 비어 있는 포트를 골라 서버를 연다.
4. 데스크톱 창을 열어 서버 주소를 보여 준다. 개발 중에는 브라우저로 연다.

## 배포 묶음

```text
AtelierX/                       앱 폴더 (사용자가 고른 곳에 풀거나 설치)
├── AtelierX.exe                시작 프로그램
├── app/                        업데이트 때 이 폴더만 바뀜
│   ├── python/                 내장 Python + 의존성
│   ├── server/                 서버 코드
│   ├── web/                    빌드한 화면
│   ├── defaults/               기본 가이드라인, 기본 이미지 라이브러리, 기본 토크나이저
│   └── samples/                샘플 작품
├── config/ state/ data/ output/  처음 실행 때 생김
```

- 저장소의 `defaults/`, `samples/`가 빌드할 때 `app/defaults/`, `app/samples/`로 들어간다.
- 업데이트: 새 `app/`으로 바꾸고 시작 프로그램을 교체한다. 데이터 형식 변환이 필요하면 시작할 때 제안한다([data-model.md 버전](data-model.md#버전)).
  - 앱 안 업데이트(도움말 → 업데이트 확인, 패키지 실행만): 최신 릴리스의 Windows ZIP과 `.sha256`을 받아 대조 → `state/update/new/`에 풀기 →
    `config`·`data`·`state`(캐시·로그 빼고)를 `state/update/backup-before-<버전>-<시각>.zip`로 백업 → "다시 시작해 설치"를 누르면
    PowerShell 스크립트(`state/update/apply.ps1`)가 앱이 끝나기를 기다려 프로그램 항목(실행 파일, `_internal`, 설명서 …)을 `<이름>.old`로
    옮기고 새 것을 넣은 뒤 새 버전을 연다. 사용자 데이터 폴더는 건드리지 않는다. 교체가 실패하면 `.old`로 되돌리고 이전 버전을 연다.
    새 버전은 시작할 때 `.old`를 지우고 결과를 화면에 알린다. 진행 중인 이미지·학습·설치·LLM 작업이 있으면 시작하지 않는다.
- 첫 배포 대상은 Windows. 서버·화면은 OS에 묶이지 않게 쓰고(경로는 `pathlib`, 암호화는 OS 기능을 쓰지 않음), 다른 OS용 묶음은
  필요할 때 만든다.
