# Frontend 현행 사양

표기: **[확정]** 사용자 확정·Accepted ADR, **[구현]** 현재 코드 동작(초기 운영값 포함), **[제한]** 미구현·미검증·알려진 한계. 날짜별 검증 기록은 로컬 전용 `docs/history/`에 있다. 코드는 `frontend/`이며 Core가 `/ui/`로 제공한다. 사용 API는 [REST API](../api/rest-api.md)를 따른다.

### 공통 셸·탐색
- [구현] 상단 메뉴 7개: 조각 관리 / 캐릭터 관리 / 이미지 생성 / 작업 현황 / 검토 / 갤러리 / 설정. 기본 진입은 캐릭터 관리. hash 라우팅 `#page/id`, 상세는 뒤로가기로 복귀.
- [구현] 메뉴 이동 시 화면별 선택·필터·스크롤을 현재 탭 메모리에 유지. 미저장 변경은 이동 전 확인, 새로고침·닫기 전 경고. 새로고침 후 초안 영속 저장은 아님.
- [구현] 화면 모듈 로드 실패 시 Access 로그인·연결 확인 안내와 수동 새로고침 버튼(자동 새로고침 없음).
- [구현] `/`·`/ui`는 GET/HEAD만 `/ui/`로 리디렉션, API 인증 경계 유지.
- [확정] Frontend는 REST 호출·표시만. 프롬프트 합성·계획 고정·생성/검증/재생성 조정은 Core. 응답 유실 시 같은 멱등 키·같은 요청만 재전송, 자동 재전송 없음.

### Core 연결(설정 > Core 연결)
- [구현] 시작 시 `/health` 성공이면 연결됨(Access 자동 연결 포함). 401/403이면 `/v1/frontend-connection` 조회로 서버 저장 연결 여부 판정, 404면 수동 Bearer, 그 외 연결 불가 안내 후 설정의 Core 연결로 이동. 상단 연결 버튼도 이 섹션을 연다. 인증 전에도 연결 입력·도움말 접근 가능.
- [구현] 서버 저장 연결은 상태(configured/connected·인증 방식·토큰 저장 여부·공개 주소)만 표시, 토큰 저장/교체 입력값은 즉시 삭제. 서버 저장이 없으면 Bearer는 현재 탭 메모리 연결임을 표시. 토큰은 화면·브라우저 저장소·URL에 노출하지 않고 토큰 파일 위치만 안내. 연결 표시에 health version/build.

### 조각 관리
- [확정] 전역 공유 조각. 캐릭터 작업과 분리된 화면에서 CRUD. 태그 대신 사용자 관리 단일 계층 카테고리. 이미지별 조각 번호는 사용자가 입력·수정(ADR-0026), 공통 적용 조각은 번호 없음.
- [구현] 번호 입력은 필수·1~32자, 파일명 금지 문자(`<>:"/\|?*`)·제어 문자·앞뒤 공백·끝 마침표·Windows 예약 이름을 화면에서 먼저 막는다. 저장 전 `number-check`로 중복을 조회해 확인 창(같은 번호로 저장/번호 수정)을 띄우고, 저장 응답 `warnings`도 알림으로 표시한다. 목록은 번호와 포함 부위를 표시.
- [구현] 카테고리 / 검색·페이지 목록 / 편집·변경 이력. 모바일은 카테고리 접고 목록↔상세 전환. 카테고리 `⋯`로 이름 수정·보관/복원. 카테고리 보관은 소속 조각 연쇄 보관·삭제가 아니며 새 조각 분류 선택에서만 제외.
- [구현] 유형: 이미지별 조각(상의·하의·액세서리·손 포함 체크, 액세서리·손 기본 true, 과거 기록의 손 누락은 포함으로 취급) / 공통 적용 프롬프트(번호·포함 입력 숨김, 본문만 덧붙임).
- [확정] 행 클릭=상세, 체크박스=선택. 화면 순번과 고유 번호 구분.

### 캐릭터 관리
- [확정][구현] 작품 > 캐릭터 > 의상 트리. 작품 이름은 프롬프트에 미삽입. 캐릭터: 외형(`appearance_prompt`, 항상 포함)·검사용 핵심 특징(`check_features`, 한 줄에 하나, 빈 줄 제외, 최대 50개·200자, ADR-0025)·캐릭터 Negative. 의상: 상의 / 하의(풋웨어 포함) / 액세서리 / 손(ADR-0026, 과거 기록 누락은 빈 값).
- [구현, 2026-09-24] 기존 의상을 편집할 때 `frontend/reference-sets.js`(`mountReferenceSetPanel`)가 참조 세트 영역을 추가로 붙인다(ADR-0027). 상태 배지(없음/유효/재확인 필요)와 바뀐 항목(`stale`), 현재 확정 세트의 전신·얼굴 썸네일(`lightbox.js` 재사용)·revision·확정 시각·`settings_summary`, `needs_review`일 때 "변경 확인 후 유지" 버튼을 보여준다. 샘플 생성 폼은 Seed(-1 무작위/고정)·모델 설정·공통 적용 프롬프트 선택·쌍 개수(1~4, 개별 API 호출)를 받아 `POST /v1/outfits/{id}/reference-samples`를 호출하고, 완료될 때까지 4초 간격으로 폴링하며 `ctx.signal` abort 시 멈춘다. 샘플 쌍 목록에서 전신 하나·얼굴 하나(다른 쌍이어도 됨)를 선택해 확정하거나, 여러 쌍을 선택해 새 Seed로 다시 생성할 수 있다. 확정 이력은 접었다 펼치는 최소 목록이다(전체 이력 화면은 범위 밖).
- [구현] 선택과 편집 대상/모드 분리(새 항목 POST, 기존 id+revision PATCH). 행의 `⋯` 메뉴와 PC 우클릭이 같은 추가·수정·보관 제공. 보관/복원은 화면 내 확인, 영구·연쇄 삭제 없음, 과거 그룹·이미지·이력 보존.
- [구현] 긴 이름 한 줄 말줄임(전체 이름은 title·접근성 이름). 펼친 대상의 자식만 조회, 재방문 시 캐시 재사용. 모바일은 분류↔편집 전환.
- [구현] 기존 의상 외형 불일치는 사용자가 후보를 명시 선택해야 저장되고 Core가 캐릭터로 이전. 해소 전 의상 저장·새 고정본 차단. revision 충돌 자동 덮어쓰기 없음.

### 이미지 생성
- [확정][구현] 3열: 작품>캐릭터>의상 체크 트리 / 카테고리>조각 체크 트리(이미지별·공통 적용 분리) / 생성 설정 + 하단 예정 목록. 모바일은 의상/조각/설정 단계 전환.
- [구현] 이미지별 조각 행과 예정 목록은 `#번호 이름`과 포함 부위(상의·하의·액세서리·손)를 표시. 고급 직접 입력에도 손 포함 체크, Core 미리보기는 부위별 포함/제외 표시.
- [구현] 상위 체크는 활성 하위 전체 선택·부분 선택 표시, 하위 없으면 비활성. 접기 중 선택 유지. 체크 22px·터치 행 44px, 체크와 이름 같은 행. 보관 항목 제외, 미분류·보관 카테고리 조각은 별도 가지.
- [확정][구현] 총 예정 장수 = 의상 수 × 이미지별 조각 수, 50개씩 표시, 재생성 횟수와 구분, 제품 상한 없음. 공통 적용은 장수·상의/하의/액세서리 포함을 바꾸지 않음.
- [구현] 선택 확인(설정·검사 선검증 → 의상별 고정 그룹 생성·잠금) → 항목별 Core Prompt 확인 → 생성 준비(그룹별 제작 계획, 멱등 키 유지, 부분 실패 같은 키 재시도) → 전부 접수 후 생성 시작. 새 준비는 기존 계획을 삭제하지 않음.
- [확정][구현] Seed 기본 -1=이미지별 무작위, 0 이상=지정값. 실제 값은 Core가 고정·기록, 계획 항목·갤러리 상세에서 조회. 프리셋 지정 Seed는 유지.
- [구현] 모델·encoder·VAE·업스케일 모델은 `/v1/generation/resources` 드롭다운, 누락 시 자동 대체 없음. LoRA 행 추가·삭제·순서 보존. 예상 최종 해상도 = 실제 크기 × 최종 배율(모델 고유 배율 추정 안 함), 입력 중 갱신. 후처리 기본(1.5배·WebP)/없음 `{}`/직접/Preset 구분, 같은 종류 Preset·직접 동시 전송 없음.
- [확정][구현] 검사: 검사 없이 생성 / Single(기본, 2026-09-24 ADR-0027 P6) / Single+묶음. 미검사는 통과로 취급하지 않음.
- [구현, 2026-09-24] 생성 설정에 일관성 방식 선택을 추가했다(ADR-0027 P3). `GET /v1/generation/resources`의 `consistency_methods`(모델과 함께 이미 불러오는 자원)로 방식을 드롭다운에 나열하고, 미등록(`available:false`)이면 사유와 함께 비활성 표시한다. 선택한 방식의 `params` schema(`number`/`boolean`, `min`/`max`/`default`/`warn_below`)로 폼을 그리며 `warn_below` 미만 값은 경고 문구를 보여준다. 방식을 고르지 않으면 요청에 `consistency`를 아예 보내지 않아 Core 기본값(참조 세트가 유효하면 자동 적용, 아니면 미적용)을 따른다. 예상 시간은 별도 추정치가 없어 "참조 적용 시 장당 약 30초(현재 약 9초, 약 3.3배)" 안내문만 표시한다.
- [구현, 2026-09-24] 의상 트리에 캐릭터·의상별 참조 세트 상태 배지(없음/유효/재확인 필요)를 표시하고, 유효하지 않은 의상은 체크를 막은 채 "의상 관리에서 만들기" 안내로 캐릭터 관리 화면 이동을 제안한다(선택 상태까지는 아직 자동 전달하지 않음). `POST /v1/production-plans`의 409 `CORE_REFERENCE_SET_REQUIRED`는 대상 의상 목록을 포함한 안내 문구로, 409 `CORE_REFERENCE_SETTINGS_MISMATCH`는 `diff` 표를 `window.confirm` 대화상자로 보여주고 "그래도 진행" 확인 시 같은 본문에 `accept_reference_settings_mismatch:true`를 더해 새 멱등 키로 재접수한다(본문이 달라지므로 새 키가 필요).

### 작업 현황
- [구현] Task·일괄·독립 후처리·제작 계획 목록/상태 필터, 상세(시도 lineage, 단일 검증 상태, 결과 링크), 취소, 기준 저장과 Batch 재개를 별개 명시 동작으로.
- [구현] 활성 화면만 5초 poll, 중복 poll 없음, 실패 시 최대 30초 backoff, 숨김 시 중지·복귀 즉시 갱신. SSE 미사용. 계획의 총 대기 수와 실제 실행 수 구분, Batch 완료≠묶음 합격, 퍼센트 진행률 없음.
- [구현] 기존 일괄 생성 폼(그룹 1개, 1~32행)은 "호환용"으로 잔존.

### 검토
- [구현] 단일 검사 결과는 불합격 근거를 출처 라벨(외형 특징/외형 설명/상의/하의/액세서리/손/조각)과 함께 표시하고, `not_assessable`은 접힌 "판단 불가 항목"으로 따로 보여 불합격으로 세지 않는다. `diagnostics.regeneration_proposal_dropped`가 있으면 "재생성 제안 형식 오류로 제안을 생략했습니다"를 표시(ADR-0025).
- [확정][구현] 검토와 갤러리 분리, 수동 승인 의무 없음. 검토: 단일 검사 이력·재요청, 현재 그룹 일관성, 기준 후보 조회(변경 없음)·대표 1+보조 최대 2 저장, 선택 대상 묶음 재검증, mismatch 교체 재생성.

### 갤러리
- [구현] 분류 탐색 + 단일/묶음/형식 필터. 초기 필터 단일 통과. "통과 결과만"=단일 통과+현재 기준 일치, "미검증 보기", "전체 결과". 단일·그룹 판정 별도 배지.
- [구현] 상세: `output_path`가 있으면 "파일 경로"(ComfyUI 출력 기준 상대 경로) 표시, 원본 내려받기, 당시 Prompt·후처리(접힘), 단일 검사 이력, 조각 번호·당시 revision, 독립 후처리(원본·판정 불변 파생), 수동 재생성, 이미지 다시 불러오기.
- [구현] 미리보기는 화면 근처에서만 요청, 동시 Blob 3개, 늦은 상세 응답 무시. 모바일은 목록↔상세.
- [확정] 이미지셋 = 캐릭터·의상별 기존 결과 조회. 수동 컬렉션·파일 복사 없음, 기준·검사 오류를 품질 통과로 합치지 않음.

### 설정
- [구현] 섹션: Core 연결 / 전역 Prompt(Negative는 생성 전용) / 참조 템플릿(2026-09-24, ADR-0027) / 자동 재생성(새 최초·수동 요청부터 적용) / 생성 Preset / 후처리 Preset / 단일·묶음 검사 Profile / 검사 Provider / 실행 환경 상태.
- [구현, 2026-09-24] 참조 템플릿 섹션은 `settings.reference_templates`의 전신·얼굴 구도 Prompt와 상의/하의/액세서리/손 포함 체크를 기존 일반 폼+draft/revision 패턴으로 편집하고 `PATCH /v1/settings`로 저장한다. 데이터 URL로 단독 로드하는 `tests/test_settings_forms.mjs`와의 호환을 위해 이 폼의 순수 변환 로직은 `frontend/settings.js`에 자체 보관하며(가져오기 없음), `frontend/reference-sets.js`의 동등한 함수는 `tests/test_frontend_reference_sets.mjs`가 별도로 검증한다.
- [구현] 일반 폼+고급 JSON. 초안은 원래 revision과 보존, 409 자동 덮어쓰기 없음, 최신값 불러오기는 명시 동작. Preset에 Prompt·endpoint·secret·경로 미저장, API key 입력·표시 없음. 자원 목록 실패 시 현재값 유지. 체크박스는 작은 체크+별도 터치 레이블.
