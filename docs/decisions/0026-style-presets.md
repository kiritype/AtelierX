# 0026. 생성 프리셋을 그림체 프리셋으로 바꾸고, 화풍 조각은 프리셋의 artist 태그로 흡수한다

- 날짜: 2026-10-07
- 상태: 채택

## 결정

- **그림체 프리셋**이 생성 프리셋을 대체한다. 전역에만 두고(`data/image/presets/<id>.json`), 프롬프트 라이브러리와 생성 화면에서 고른다.
- 그림체 프리셋 하나는 다음을 묶는다.
  - **서비스**(`comfyui`·`novelai`·`pixai`)와 모델 계열. ComfyUI면 `anima`·`sdxl`, 인터넷 서비스면 서비스 자신이다.
  - 그 서비스의 생성 설정(ComfyUI: 모델·LoRA·샘플러·스텝·CFG·크기·shift·업스케일·디테일러, NovelAI·PixAI: 그 서비스의 설정).
  - **artist 태그**(positive·negative): 그림체를 정하는 작가·앞머리 태그. 서비스의 문법 그대로 쓴다.
  - 사용자 **태그**(거르기·찾기용)와 기본으로 켤 공통 프롬프트.
- 프리셋은 그 서비스에서만 고를 수 있다. 생성 화면은 지금 서비스의 프리셋만 보여 준다.
- 샘플러·스케줄러는 이미지 생성 서버의 기본 목록에서만 고른다. 커스텀 노드는 쓰지 않는다(#178을 되돌림).
- **화풍 조각(`styles.json`)을 없앤다.** 화풍이라는 이름 대신 프리셋 안의 "artist 태그"라고 부른다.
  - 앱을 처음 켤 때 한 번 옮긴다. 프리셋이 고른 화풍은 그 프리셋의 artist 태그가 된다.
  - 어느 프리셋도 고르지 않은 화풍은 각각 artist 태그만 있는 프리셋이 된다. 설정은 비어 있어 생성 화면의 값을 쓴다.
  - 작품 범위의 화풍은 `<작품 ID>_<id>` 전역 프리셋이 된다.
  - 옛 파일은 `styles.migrated.json`으로 이름만 바꿔 남긴다.
- 조합 순서의 `style` 자리는 `artist`가 된다. 생성 화면은 프리셋의 artist 태그를 채우고, 이번 생성에만 고쳐 쓸 수 있다.

## 이유

- 그림체는 모델·LoRA·샘플러·작가 태그가 한 묶음이어야 재현된다. 지금은 생성 프리셋·화풍 조각·공통 프롬프트에 흩어져 있어,
  어디에 무엇을 넣어야 하는지 헷갈린다. 생성 프리셋과 그림체 프리셋을 따로 두면 같은 혼란이 남는다.
- 화풍 조각을 프리셋 위에 덧붙이는 기능으로 남기면 그림체를 정하는 곳이 두 군데가 된다.
- NovelAI의 작가 프롬프트처럼 서비스마다 문법과 설정이 달라서, 프리셋이 서비스 하나에 묶여야 그대로 쓸 수 있다.
- 커스텀 노드를 고르는 화면은 사용하기에 너무 복잡했다(#178).

## 결과

- 형식: [데이터 형식 — 그림체 프리셋](../data-model.md#그림체-프리셋). schema 2, 이전 형식은 읽을 때 ComfyUI 프리셋으로 본다.
- 서버: `library.preset_doc`, `library.migrate_styles`(시작할 때), 조합 `artist` 부분, 생성 요청의 `preset_id`·`artist`.
- 생성 기록에는 `artist`(그때 쓴 artist 태그)가 남는다. 이전 기록의 `style_ids`·`parts.style`은 그대로 읽는다.
- 이어서 할 것(#169): 미리보기 한 장과 탐색 화면, EXIF 뷰어 → 새 그림체 프리셋, 꾸러미 공유.
