# 0024. 마스터 비밀번호는 8자 이상, 실패 대기는 다시 켜도 이어지고, 자동 잠금은 두지 않는다

- 날짜: 2026-10-07
- 상태: 채택

## 결정

- 새 마스터 비밀번호(첫 실행, 변경, 재설정)는 **8자 이상**이다(이전 4자).
- 그보다 짧은 기존 비밀번호도 그대로 열린다. 그 비밀번호로 열면 **바꾸기를 권하고**, 사용자는 **나중에**를 고를 수 있다(강제하지 않음).
- 잠금 해제에 실패하면 4번째부터 2, 4, 8 … 초를 기다리게 한다. 최대 30초, 10번이 넘으면 최대 5분.
  실패 횟수와 다음 시도 가능 시각은 `state/auth.json`에 남겨 **앱을 다시 켜도 이어진다**. 성공하면 지운다.
- **자동 잠금은 두지 않는다.** 잠금은 사용자가 잠금 버튼(Ctrl+Shift+L)으로 한다. 설계 문서에 있던 자동 잠금 설정을 뺀다.

## 이유

- 앞으로 서버로 띄워 다른 기기에서 접근하게 되면 비밀번호가 더 중요해진다. 8자는 일반적인 최소 기준이고 기존 사용자의
  부담이 작다.
- 이미 쓰는 비밀번호를 강제로 바꾸게 하면 앱을 못 여는 상황이 생길 수 있다. 권하는 것으로 충분하다.
- 앱을 다시 켜는 것으로 실패 대기를 건너뛸 수 없어야 한다.
- 이 앱은 한 PC에서 한 사람이 쓴다. 자동 잠금은 잠긴 동안 작업(인터넷 이미지 서비스의 키, 저장하지 않은 화면)을 어떻게 할지까지
  다뤄야 해서, 실익에 비해 복잡하다(#82에서 검토 후 제외).

## 결과

- 금고: `MIN_PASSWORD = 8`(`core/vault.py`). 서버는 잠금 해제 때 비밀번호가 짧았는지 기억하고 `/api/auth/status`의
  `password_change_suggested`로 알린다.
- 세션: 실패 대기를 `state/auth.json`에 둔다(`core/auth.py`).
- 원격 접근을 열게 되면(별도 이슈) 루프백 밖 주소 경고, 세션 쿠키(`HttpOnly`, `SameSite=Strict`, 원격이면 `Secure`), Origin 검사,
  HTTPS를 그 이슈에서 정한다.
