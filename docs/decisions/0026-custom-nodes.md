# 0026. 커스텀 노드는 모델 패치와 샘플러 이름으로 지원하고, 라이선스가 분명한 것만 설치 목록에 넣는다

- 날짜: 2026-10-07
- 상태: 채택

## 결정

- 생성 그래프에 넣을 수 있는 커스텀 노드는 두 종류다.
  - **모델 패치**: 모델을 받아 모델을 돌려주고, 나머지 입력이 모두 설정값(숫자·켜기/끄기·선택지·글)인 노드.
    shift 다음, 샘플러 앞에 적힌 순서대로 끼운다. 본 생성·업스케일 다시 그리기·디테일러가 모두 패치된 모델을 쓴다.
  - **샘플러·스케줄러 이름**: 노드 팩이 이미지 생성 서버의 목록에 더한 이름(`res_3m`, `beta57` …). 목록에 있으면 그대로 쓴다.
- 모델 패치는 노드마다 코드를 두지 않는다. 설정에는 노드 이름과 입력값만 저장하고, 화면은 이미지 생성 서버의
  `/object_info`에 있는 입력 정의로 설정 칸을 만든다.
- 기본 노드로 똑같이 만들 수 있는 이름은 노드 팩 없이도 쓴다. 지금은 `beta57`(기본 Beta 스케줄러 alpha 0.5, beta 0.7 +
  사용자 지정 샘플러)이다.
- 샘플러 자체를 바꾸는 노드나 모델 밖의 연결(CLIP, 조건 등)이 필요한 노드는 지원하지 않는다. 같은 기능의 모델 패치가 있으면 그것을 쓴다.
- 필요한 노드가 없을 때:
  - 생성 화면은 대기열에 넣기 전에 묻는다: **설치**(설치 목록에 있을 때만) / **빼고 생성** / **취소**.
  - 빼고 생성하면 패치는 빼고, 샘플러·스케줄러는 설정의 `fallback`(없으면 기본값)으로 바꾼다. 뺀 것은 생성 기록 `skipped`에 남긴다.
  - 이미 대기열에 들어간 작업은 묻지 않고 빼고 생성한다(이미지 생성 서버를 다시 켜는 사이에 노드가 사라진 경우).
- 설치 목록(결정 0019)에는 라이선스가 분명한 노드만 커밋 고정으로 넣는다. 라이선스가 불분명하거나 제한이 있는 노드는
  사용자가 직접 설치했을 때만 감지해 쓰고, 출처와 라이선스를 안내한다(`comfy_nodes/nodes.json`의 `known`).

## 이유

- 그림체 레시피에는 커스텀 샘플러·가이던스 패치가 자주 들어간다. 노드마다 화면과 코드를 만들면 새 노드가 나올 때마다 앱을 고쳐야 한다.
  모델 패치는 입력 모양이 같아서 범용으로 다룰 수 있다.
- 샘플러를 바꾸는 노드는 입력과 출력이 노드마다 달라, 범용으로 다루면 그래프가 깨지기 쉽다.
- 노드 하나가 없다고 생성을 막으면 공유받은 프리셋을 쓰기 어렵다. 묻고 빼는 쪽이 낫고, 무엇을 뺐는지는 기록에 남긴다.
- 라이선스가 불분명한 코드를 앱이 받아 주면 배포 책임이 생긴다. 사용자가 직접 설치한 것을 쓰는 것은 문제가 없다.
- 노드 기능을 앱 노드 팩에 다시 만드는 것은 최후 수단이다. 원본 코드를 참고하면 파생물이 되고, 새로 구현하는 비용이 크다.

## 결과

- 서버: `server/atelierx/image/extensions.py`(패치 노드 찾기, 값 확인, 별칭, 없는 노드 처리), 그래프 조립 `workflow.py`.
- 생성 설정 형식: `patches`, `fallback`, `missing`, `skipped`([데이터 형식](../data-model.md)).
- API: `POST /api/image/generate/check-nodes`.
- 설치 목록 후보: Skimmed CFG(Apache-2.0), Spectrum(MIT). 감지만: RES4LYF(자체 라이선스, 상업 서비스 제공 금지), DCW(라이선스 파일 없음).
