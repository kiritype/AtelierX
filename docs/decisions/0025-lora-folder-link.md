# 0025. 학습한 LoRA는 앱 폴더에 두고, 이미지 생성 서버에는 폴더 링크로 보인다

- 날짜: 2026-10-07
- 상태: 채택

## 결정

- 학습한 LoRA 파일의 원본은 **앱의 LoRA 폴더**에 둔다. 기본은 `output/loras/`이고, 설정 → 이미지 → LoRA 학습의
  LoRA 폴더로 다른 곳을 고를 수 있다. 폴더가 없으면 만든다(이전에는 설정하지 않으면 학습을 시작할 수 없었다).
- 이미지 생성 서버(ComfyUI)에는 그 LoRA 폴더 안에 **`atelierx`라는 폴더 링크**를 만든다. Windows는 디렉터리 정션
  (관리자 권한 불필요), 그 밖의 OS는 심볼릭 링크다. 새 LoRA는 복사 없이 바로 `atelierx\<파일 이름>`으로 보인다.
- 링크는 학습 환경 자동 준비가 만들고, 설정 화면의 **[연결]·[다시 연결]**로도 만든다.
  - 앱 폴더를 옮겨 링크가 다른 곳을 가리키면 "끊김"으로 보이고, 다시 연결하면 **링크만** 바꾼다(가리키던 폴더는 건드리지 않음).
  - 서버 쪽에 같은 이름의 실제 폴더나 다른 링크가 있으면 덮어쓰지 않고 알린다.
- 이전 설정처럼 LoRA 폴더가 이미 서버의 LoRA 폴더 안이면 링크가 필요 없다. 설정 화면의 **[AtelierX 폴더로 옮기기]**로
  파일을 `output/loras/`로 옮기고 링크를 만들 수 있다. 캐릭터의 LoRA 등록(`file`)은 새 이름(`atelierx\…`)으로 바뀐다.
- 0007(큰 파일은 출력 루트·LoRA 폴더, 작품에는 참조)은 그대로다. LoRA 폴더의 기본 위치가 출력 루트 안이 된 것뿐이다.

## 이유

- 포터블 원칙(0010): 앱이 만든 결과는 앱 폴더 안에 있어야 함께 옮기고 백업할 수 있다.
- 학습 결과를 서버 폴더에 직접 쓰면 서버를 지우거나 다시 설치할 때 함께 사라지고, 어느 파일이 앱이 만든 것인지 구분하기 어렵다.
- 복사는 용량이 두 배가 되고 두 곳이 어긋난다. 링크는 한 벌만 두면서 서버에서는 평소처럼 고를 수 있다.
- 서버 설정 파일(`extra_model_paths.yaml`)을 고치는 방법은 서버를 다시 켜야 하고 다른 도구의 설정과 부딪힐 수 있다.

## 결과

- `server/atelierx/image/lora/link.py`: 상태(`linked`·`missing`·`broken`·`conflict`·`inside`·`no_comfy`), 연결, 옮기기.
- API: `GET/POST /api/image/training/lora-link`, `POST /api/image/training/lora-link/move`.
- 한계와 주의(설명서에 적음):
  - 정션은 두 폴더가 모두 로컬 드라이브에 있어야 한다.
  - 서버 쪽에서 `atelierx` 폴더 안의 파일을 지우면 원본이 지워진다.
  - 서버 폴더까지 백업하는 도구는 같은 파일을 두 번 셀 수 있다.
