# 0021. LLM 작업은 오른쪽 "에이전트" 패널에서 지침 기반 대화로 한다

- 날짜: 2026-10-05
- 상태: 채택
- 관련: 0012(로컬 LLM 우선, 가이드라인, 작품×연결 동의), 0008(파일 트리 = 디스크), 0013(예약 참조), 0017(테스트 화면)

## 결정

### 패널

- 오른쪽 보조 패널에 **"에이전트"** 탭을 더한다(검사·검토 옆). 대화 목록과 새 대화, 모드 카드, 범위, 연결·모델 선택, 입력창이 있다.
- 새 대화는 **모드 카드**에서 시작한다(아이디어 정리, 시작 상황 쓰기, 캐릭터 다듬기, JSX 만들기, 압축, 모순 찾기 등).
  카드 목록은 지침 파일에서 만든다(아래 "지침"). 카드 없이 자유 대화도 할 수 있다.
- 편집기에서 글을 고른 뒤 `Ctrl+L`(또는 첨부 버튼)로 대화에 첨부한다. 첨부는 경로·줄 범위와 함께 들어간다.

### 범위와 맥락

- 첫 질문을 보내기 전에 **범위**를 정한다: 현재 파일(기본), 고른 파일·폴더, 작품 전체. 모드 지침이 기본 범위를 정할 수 있다.
- 앱이 보내는 맥락: 앱 고정 지시 → 모드 지침 → 플랫폼 규칙 요약(용량 제한, 응답 속 컴포넌트 표기) → 범위의 파일 목록
  (경로·종류·ID·크기) → 범위의 본문. 본문이 맥락 예산을 넘으면 목록만 보내고, 사용자가 파일을 더 첨부하면 그 파일을 넣는다.
- 맥락 예산은 연결 카드의 모델별 맥락 길이(정하지 않았으면 8192 토큰)에서 응답 몫(40%)을 뺀 값이다. 파일 전체 교체를 기본으로 하므로
  응답 몫을 넉넉히 둔다.
- 보내기 전에 "파일 n개, 약 x 토큰"을 보여 준다. 외부 LLM 연결이면 결정 0012의 작품×연결 동의를 그대로 거친다.
- 모델이 스스로 파일을 찾는 도구 호출(목록·읽기·검색)은 다음 단계로 미룬다. 처음에는 위의 첨부 방식만 쓴다.

### 결과는 제안으로

- 에이전트는 **파일을 직접 고치지 않는다.** 바꿀 내용은 응답 속 "제안"으로 나오고, 사용자가 "검토로 보내기"를 누르면 임시 항목으로
  들어간다. 검토 탭에서 차이를 보고 덩어리(hunk) 단위로 골라 채택한다. 채택할 때 원본이 바뀌었으면 막는다(`base_hash`).
- **제안의 기본 형식은 파일 전체 교체다.** 모델은 바꿀 파일의 새 내용 전체(머리 메타데이터 포함)를 아래 표지 사이에 쓴다. 바뀐 부분은
  앱이 기존 파일과 비교해 계산한다.

  ```text
  <<<file path="인물/한서윤.md">>>
  (새 내용 전체)
  <<<end>>>
  ```

  - 표지는 마크다운 코드 울타리(```)를 쓰지 않는다. 본문(로어북, JSX)에 코드 울타리가 들어 있어도 깨지지 않게 하기 위해서다.
  - 작품에 없는 경로면 새 파일 제안이 되고, 머리 메타데이터의 `kind`로 종류가 정해진다. 채택해야 파일이 생긴다.
  - 응답이 길이 한도로 끊겨 `<<<end>>>`가 없으면 "끊긴 제안"으로 표시하고 검토로 보낼 수 없다(이어 쓰기 요청 버튼).
  - 새 내용이 기존보다 크게 줄었거나 "(이하 동일)", "…생략" 같은 생략 표시가 있으면 경고한다. 머리 메타데이터의 `id`·`kind`가
    바뀌었으면 검토 탭에서 따로 표시한다.
  - 제목 단위·찾아 바꾸기 같은 부분 교체는 기본으로 두지 않는다. 큰 파일은 범위를 좁히거나 파일을 나누도록 안내하고, 필요하면
    다음 단계에서 제목 단위 교체를 더한다.
- 정해진 결과 형식이 필요한 작업(압축의 목표 크기와 용량 계산, 모순 검사 목록, 관계 찾기, JSX 문구)은 지금의 작업을 그대로 실행한다.
  에이전트는 대화로 옵션을 정하고 "실행"을 제안한다. 결과는 지금처럼 검토 탭으로 간다.

### 지침 (설정에서 편집)

- 모드마다 지침 마크다운 하나를 둔다: `agent/<모드>.md`. 머리 메타데이터에 카드 이름·설명·기본 범위·순서를 두고, 본문은 대화 방식
  (무엇을 먼저 묻는지, 어떤 순서로 정리하는지, 끝에 무엇을 내놓는지)이다.
- 앱이 기본 지침을 함께 배포한다. 사용자는 고칠 수 있고, 가이드라인 겹침 규칙(결정 0012: 작품 → 플랫폼 프리셋 → 전역)을 그대로 따른다.
- 설정의 **"압축 지침"을 "지침"으로 넓혀** 전역 지침 전체(에이전트 모드, 작업 지침, 이미지 프롬프트)를 다룬다. 플랫폼 프리셋과
  작품의 지침도 같은 구성 요소로 다룬다.
- 화면은 **접기(collapse)** 로 짠다. 지침이 많아도 한 화면에서 훑어보고 하나씩 고치게 하기 위해서다.
  - 맨 위: 검색 칸, "바뀐 것만 보기".
  - 묶음(접기 가능): 에이전트 모드 / 작업 지침 / 이미지 프롬프트 / 앱 고정 지시(읽기 전용, 기본으로 접힘). 묶음 머리에 개수와
    "수정됨 n" 배지.
  - 접힌 줄: 이름, 설명 한 줄, 출처 배지(기본 / 수정됨 / 사용자 추가, 프리셋·작품 화면에서는 상속 / 덮어씀).
  - 펼치면 그 자리에서 편집한다: 머리 메타데이터는 폼, 본문은 마크다운 편집기. 버튼은 저장, 기본값과 비교, 기본값으로 되돌리기,
    지우기(사용자 추가 모드만).
  - 한 번에 하나만 펼친다. 저장하지 않은 변경이 있으면 접거나 다른 항목을 펼칠 때 묻는다. 펼침 상태는 보는 사람의 브라우저에만 기억한다.
  - "새 모드 추가"는 에이전트 모드 묶음 끝에 둔다. 기존 모드를 복제해서 시작할 수 있다.
- 앱 고정 지시(사용자가 바꿀 수 없음): 파일을 직접 고쳤다고 말하지 말 것, 바꿀 내용은 제안 형식으로 파일 전체를 낼 것, 범위 밖 내용을
  지어내지 말 것, `{{user}}`·`{{char}}` 예약 참조를 지킬 것(결정 0013).

### 기록

- 대화는 작품의 `.atelierx/agent/<대화 ID>.jsonl`에 둔다(질문, 첨부 목록, 응답, 제안과 그 처리 결과, 쓴 연결·모델). 내보내기·스냅샷에는
  넣지 않는다. 자동으로 지우지 않고, 대화 목록에서 이름 바꾸기·지우기를 한다. 사용량은 작업 `agent`로 기록한다.

### 기존 기능

- 뼈대 작성, LLM 도구(압축·내용 검토·모순 검사·형식 정리), 관계 찾기, JSX 문구 만들기는 모드 카드와 지침으로도 쓸 수 있게 한다.
- 상단 메뉴와 편집기의 기존 진입점은 당분간 남긴다. 없앨지는 사용해 본 뒤 정한다.

## 이유

- 질문 양식을 채우는 정해진 흐름은 작품마다 다른 상황에 맞추기 어렵다. 대화로 되묻고 다듬는 쪽이 실제 작업 방식에 가깝다.
- 지침을 사용자가 고칠 수 있으면 플랫폼·장르·개인 작업 방식에 맞춰 에이전트를 바꿀 수 있다. 이미 있는 가이드라인 겹침 구조를 쓰면
  새 규칙을 만들지 않아도 된다.
- 작품 전체를 한 번에 넣는 것은 로컬 모델의 맥락 한도와 외부 전송량 때문에 어렵다. 범위를 먼저 정하고 필요한 파일만 넣는 것이
  두 문제를 함께 줄인다.
- 파일 전체 교체는 로컬 모델도 지키기 쉽다. 찾아 바꾸기는 원문을 글자 그대로 옮겨야 해서 작은 모델이 자주 틀리고, 틀리면 제안 전체를
  쓸 수 없다. 전체 교체는 차이를 앱이 계산하므로 사용자는 바뀐 덩어리만 보고 고를 수 있다.
- 파일을 직접 고치게 하면 잘못된 변경이 바로 작품에 들어간다. 검토 흐름(차이 보기·부분 채택·충돌 검사)을 거치면 안전하다.

## 결과

- 화면: 보조 패널 "에이전트" 탭, 모드 카드, 범위 선택, 첨부(`Ctrl+L`), 제안(파일 전체 교체) → 검토로 보내기. 설정의 "지침" 화면(접기).
- 서버: 대화 저장소(`.atelierx/agent/`), 맥락 조립(지침 겹침·범위·예산), 스트리밍 응답, 제안 블록 해석(끊김·생략 검사),
  작업 `agent`의 연결·사용량.
- 데이터 형식: 지침 머리 메타데이터, 대화 기록, 임시 항목 종류 `agent_file`을 [data-model](../data-model.md)에 더한다.
  기능 문서는 [11-agent](../features/11-agent.md).
- 기본 지침 묶음을 함께 배포하고, 실제 로컬 모델로 모드마다 대화를 돌려 보며 다듬는다.
