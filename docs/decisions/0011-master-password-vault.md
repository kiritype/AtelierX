# 0011. 마스터 비밀번호로 실행 인증과 인증 정보 암호화를 함께 한다

- 날짜: 2026-10-02
- 상태: 채택

## 결정

첫 실행 때 마스터 비밀번호를 정한다. 이후 실행할 때마다 이 비밀번호로 인증하고, 같은 비밀번호로 API 키 등 인증 정보를
담은 금고(`config/vault.json`)를 연다. 암호화 대상은 인증 정보뿐이고, 작품 데이터는 평문으로 둔다.

## 이유

- 앱이 키를 쓰려면 복호화해야 하므로, 복호화 열쇠가 앱 폴더 안에 있으면 실제 보호가 되지 않는다. 열쇠가 사용자의
  머릿속(비밀번호)에 있어야 앱 폴더가 유출돼도 키가 지켜진다.
- OS 보관소(DPAPI, 키체인 등)에 의존하지 않으므로 OS에 묶이지 않고, 앱 폴더를 다른 PC로 옮겨도 비밀번호만 알면 열린다.
- 인증과 복호화가 같은 동작이라 비밀번호 해시를 따로 관리하지 않아도 된다.
- 작품까지 암호화하면 사람이 읽을 수 있는 파일, 파일 트리 = 디스크, 다른 편집기·git 사용 원칙이 깨진다.

## 결과

- scrypt(표준 라이브러리)로 비밀번호 열쇠를 만들고 AES-256-GCM으로 암호화한다. 데이터 열쇠를 비밀번호 열쇠로 감싸는 두 겹
  구조라 비밀번호 변경이 가볍다.
- 비밀번호를 잊으면 금고를 초기화하고 인증 정보를 다시 입력한다. 작품 데이터는 영향이 없다.
- 실행 인증은 서버에서 확인한다(세션 토큰). 상세는 architecture.md.
- 형식과 규칙은 data-model.md의 "금고" 절.
