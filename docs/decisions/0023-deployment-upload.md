# 0023. 채택 이미지를 배포 대상(R2)에 올리고, 경로에는 표정·의상의 배포 코드를 쓴다

- 날짜: 2026-10-06
- 상태: 채택

## 결정

- 갤러리의 채택 이미지를 **배포 대상**에 올리는 기능을 둔다. 지금은 Cloudflare R2(S3 호환 API) 하나다. 배포 대상은
  **설정 → 배포 대상**(앱 전체, 여러 개)에 두고 키는 금고에 둔다. 작품은 대상을 골라 쓴다.
- 기본 경로는 `작품 ID/캐릭터 ID/의상 코드/표정 코드.webp`. 설정에 기본 경로 형식을 두고, 업로드 미리보기에서 고칠 수 있다.
- 표정과 의상에 사용자가 정하는 **배포 코드**를 둔다. 자릿수·문자 종류 제한이 없고, 같은 코드는 막지 않고 알린다. 비어 있으면
  내부 id로 대신 채우지 않고 미리보기에서 표시한다. 기본 표정은 `001`~`008`. 표정·의상의 내부 id는 바꾸지 않는다.
- 올리는 형식은 WebP + 메타데이터 지우기. 크기·용량 제한은 두지 않는다. `Cache-Control`은 붙이지 않는다(Cloudflare 기본값).
- 같은 경로는 덮어쓴다(URL 유지). 덮어쓴 파일이 있으면 Cloudflare에서 캐시를 지우라는 안내와 URL 목록을 보여 준다.
  내용이 같은 파일은 건너뛴다. 원격 파일은 지우지 않는다.
- 업로드 범위는 채택 이미지만, 갤러리의 지금 범위. 등급 필터는 있지만 기본은 전체.
- URL을 작품에 넣는 것은 사용자가 한다. 앱은 URL 목록(복사·파일 저장)만 준다.
- 공개 버킷의 위험(누구나 접근, 짐작 가능한 경로, r2.dev의 한계, 콘텐츠 정책)은 안내만 하고 막지 않는다.
- S3 서명(SigV4)은 직접 구현한다(boto3를 쓰지 않음).

## 이유

- 챗봇 작업의 마지막 단계는 이미지를 플랫폼에서 쓸 URL로 만드는 일이다. ZIP으로 받아 따로 올리던 것을 앱 안에서 끝낸다.
- 표정 id(`smile`)는 출력 폴더·검수 기록·채택 키의 식별자라 바꾸면 전체 변환이 필요하고, 겹칠 수도 없다. 배포에 쓰는 이름은
  플랫폼 사정에 따라 바뀌고 겹칠 수도 있으므로 별도 필드로 둔다.
- 경로를 그대로 덮어쓰면 프롬프트·JSX에 넣은 URL을 고치지 않아도 된다. 캐시는 사용자가 지울 수 있다.
- boto3는 포터블 패키지를 크게 키우는데, 필요한 요청은 올리기·확인·목록 세 가지뿐이다.

## 결과

- 데이터 형식: 표정·의상의 `code`, `<데이터 루트>/image/deploy.json`, 작품의 `.atelierx/image/deploy.json`([data-model](../data-model.md)).
- 기능 설계: [25-deployment](../features/25-deployment.md).
- 실제 R2 확인은 사용자의 버킷과 키로 한다. 개발 중에는 가짜 S3 서버로 시험한다.
