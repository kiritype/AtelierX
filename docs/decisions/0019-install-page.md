# 0019. 외부 의존성은 앱에 넣지 않고 설정 → 설치에서 영역별로 받는다

- 날짜: 2026-10-04
- 상태: 채택

## 결정

- 이미지 기능이 쓰는 외부 구성 요소(이미지 생성 서버 확장 노드, 모델 파일, LoRA 학습 도구와 그 Python 환경, 이를 받는 데 쓰는
  보조 도구 uv·Git)는 배포 패키지에 넣지 않는다.
- 설정에 **설치** 화면을 두고 영역별로 나눈다: 보조 도구, 이미지 생성 서버 확장 노드, 모델(묶음별), LoRA 학습 도구. 영역마다 무엇이
  있고 무엇이 없는지 보여 주고, 사용자가 버튼을 눌러야만 받거나 설치한다. 진행은 로그로 보여 주고 멈출 수 있다.
- 받는 판은 앱이 정한다(노드·학습 도구는 커밋, 모델은 공개된 sha256). 보조 도구는 PC에 있으면 그것을 쓰고, 없으면 앱 폴더 `bin/`에
  휴대용으로 받는다. 학습 도구는 앱 폴더 `vendor/`, 모델은 이미지 생성 서버가 읽는 모델 폴더에 둔다.
- 같은 동작을 명령줄 스크립트(`tools/install_comfy_nodes.py`, `tools/install_trainer.py`)로도 할 수 있다.

## 이유

- 학습 도구 환경(CUDA PyTorch)만 수 GB라 패키지가 커지고, 학습을 쓰지 않는 사람도 받게 된다. 릴리스 파일 크기 제한도 있다.
- 이미지 생성 서버도 사용자가 설치한 것에 연결하는 방식이라, 그 주변 구성 요소도 같은 방식이 일관된다.
- GPL·AGPL 구성 요소와 비상업 라이선스 모델을 재배포하지 않아도 된다. 앱에는 MIT 파일만 들어간다.
- 명령을 직접 치지 않아도 되게 해서, 설치가 사용자에게 부담이 되지 않게 한다.

## 결과

- 패키지(pywebview)에는 앱과 화면만 넣는다. 처음 이미지 기능을 쓸 때 설치 화면으로 안내한다.
- 모델 목록은 `defaults/image/downloads.json`에 둔다(묶음, 파일, 받는 곳, 크기, sha256, 라이선스). 계정이 필요한 곳의 모델은
  받는 곳 링크와 넣을 폴더만 안내한다.
- 학습 도구 패치는 git 없이 앱이 적용한다. 다만 학습 도구의 `uv sync`가 일부 의존성을 git으로 받으므로 Git은 필요하다.
