# 매뉴얼 유지 관리

이 파일은 편집자를 위한 점검표이며 사용자 목차에는 넣지 않습니다. 공개 매뉴얼과 앱 안 오프라인 매뉴얼은 같은 Markdown을 사용합니다.

## 페이지 작성 기준

- 기능 목적과 진입 위치를 먼저 씁니다. 실제 한국어 UI의 버튼·탭 이름을 소스와 화면에서 확인합니다.
- 따라 하기는 준비 → 조작 → 완료 확인 → 막혔을 때 → 다음 작업 순서로 씁니다. 옵션 설명은 절차 사이를 끊지 않게 배치합니다.
- 튜토리얼은 샘플로 끝낼 수 있는 한 경로, 상세 가이드는 선택지·예외·되돌리기를 다룹니다.
- 링크는 페이지 단위 상대 Markdown 링크를 씁니다. 제목 앵커 링크는 오프라인 출력과 호환되지 않습니다.
- 페이지를 추가하면 `pages.json`에 정확히 한 번 등록합니다. 기존 URL을 바꾸면 기존 페이지에 목적별 연결을 남깁니다.
- 사용자 절차는 설명서와 함께 배포할 앱 버전의 화면과 동작에 맞춥니다. 지원 기능, 대역 검사, 실제 서비스에서 확인한 동작은 각각 명시합니다.

## 실제 화면 캡처

- 가상 작품과 공개가 허용된 예시 프리셋을 사용합니다. 개인 작품, API 키, 사용자 경로와 계정 정보가 보이지 않는지 확인합니다.
- 배포 대상 앱을 직접 조작해 화면을 캡처합니다. 생성·비교·갤러리처럼 이미지가 핵심인 화면에는 가상 작품에서 실제로 생성한 결과를 우선 사용합니다.
- 조작할 영역과 완료 상태가 읽히는 크기로 배치하고, 대체 텍스트와 짧은 설명을 붙입니다. `[![설명](이미지 경로)](이미지 경로)`로 원본을 열 수 있게 합니다.
- 단색 시험 결과 등 대역 데이터를 사용한 화면은 캡처 가까이에 그 사실을 적습니다. 외부 서비스 검증은 실제로 요청한 제공자와 확인한 동작을 기록하고, 대역으로 확인한 범위도 따로 표시합니다.
- 기존 생성 결과를 캡처용 비교 데이터에 넣었다면 원래 생성 경로를 설명합니다. 해당 화면에서 새로 생성하거나 외부 서비스를 검증한 것으로 소개하지 않습니다.
- 라이트·다크 모두 화면과 문서의 가독성을 확인합니다. 본문에는 학습에 필요한 화면만 싣고 중복 게재를 피합니다.
- UI가 바뀐 부분부터 다시 캡처하고, 그대로 쓰는 기존 캡처도 현재 설명과 모순되지 않는지 확인합니다.

## push·버전업 전 확인

1. 앱 버전·변경 이력·첫 화면·검증 범위를 같은 릴리스의 기능과 대조합니다. 앱과 함께 출시하는 기능은 사용자 안내에서 같은 버전의 기능으로 소개합니다.
2. 주요 흐름을 설명서만 따라 조작합니다: 첫 실행과 작품 열기, AI 제안과 채택, 단일·일괄 생성, 탐색·프리셋 재사용, 갤러리·내보내기, 백업·업데이트.
3. 웹 설명서와 오프라인 설명서에서 목차·검색·이전/다음·이미지·좁은 창·라이트/다크를 확인합니다.
4. 저장소 루트에서 `uv run python tools/build_manual.py dist/manual-check`를 실행합니다.
5. `docs/manual`에서 `npm ci` 후 `npm run build`를 실행합니다. 저장소 루트에서 `uv run python tools/audit_public.py`도 실행합니다.
6. 실제 서비스 확인을 하지 않은 부분을 검증 결과에서 분리합니다. `CONTRIBUTING.md`의 배포 절차에 따라 기능과 문서를 같은 출시 범위로 공개합니다.

문서 수정 완료는 사이트 배포 완료를 뜻하지 않습니다. push·병합·사이트 배포·버전업은 승인된 릴리스 작업 범위에서 수행합니다.
