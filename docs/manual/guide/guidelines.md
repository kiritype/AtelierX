# 지침

지침은 LLM 작업과 에이전트가 따르는 규칙을 적은 Markdown 파일입니다. 압축할 때 남길 것, 이미지 프롬프트로 옮기는 방식, JSX 문구를 쓰는 순서 같은 것을 정합니다. 앱에 기본 지침이 들어 있고, 필요하면 전체 또는 플랫폼·작품별로 고쳐 씁니다.

## 지침이 쓰이는 곳

작업마다 정해진 이름의 지침 파일을 읽습니다.

| 작업 | 읽는 지침 |
|---|---|
| 에이전트 | 앱 고정 지시 + 고른 모드의 지침(`agent/<모드 ID>.md`) + `platform.md` |
| 압축 | `compression.md` + `platform.md` (실행할 때 적은 추가 지침도 함께) |
| 뼈대 작성 | `authoring/<규모>.md`(`single`·`ensemble`·`simulation`) + `platform.md` |
| JSX 문구 만들기 | `jsx.md` + `platform.md` |
| 이미지 프롬프트 변환 | `image-prompt.md` |
| 모순 검사, 편집기의 일관성 검사 | `consistency.md` |
| 편집기의 내용 검토·형식 정리 | `platform.md` |

대화 테스트와 관계 찾기는 지침을 읽지 않습니다.

에이전트에는 표에 적은 세 가지만 들어갑니다. `jsx.md`나 `compression.md` 같은 다른 지침은 에이전트에 들어가지 않으므로, 에이전트가 따라야 할 규칙은 모드 지침 본문에 적습니다.

## 지침을 찾는 순서

같은 이름의 지침이 여러 곳에 있으면 아래 순서로 찾아 **처음 찾은 파일 하나만** 씁니다. 여러 파일을 합치지 않으므로, 일부만 바꾸고 싶어도 파일 전체를 복사해 고칩니다.

1. **작품**: `data/works/<작품 폴더>/.atelierx/guidelines/`
2. **작품에 연결한 플랫폼 프리셋**: `data/platforms/<프리셋 ID>/guidelines/`. 작품 태그에 프리셋이 여럿이면 뒤쪽 태그의 프리셋부터 찾습니다(규칙 값을 적용하는 순서와 같습니다).
3. **전역**: `data/guidelines/` — 설정 → **지침**에서 고친 지침이 여기에 저장됩니다.
4. **앱 기본값**: 앱에 들어 있는 지침. 전역에 고친 파일이 없으면 이것을 씁니다.

`data`는 앱 폴더 안의 데이터 폴더입니다. 파일을 넣거나 고치면 다음 요청부터 바로 쓰입니다(앱을 다시 시작하지 않아도 됩니다).

## 설정 → 지침에서 고치기

작품 화면 상단의 설정에서 **지침**을 엽니다. 이 화면은 **전역 지침**을 고칩니다.

![설정 → 지침](../screenshots/settings-guidelines.webp)

- 지침은 묶음별로 접혀 있습니다: **에이전트 모드**, **작업 지침**, **이미지 프롬프트**, **참고 문서**, **앱 고정 지시**. 위쪽 검색과 **바뀐 것만 보기**로 좁힐 수 있습니다.
- 지침마다 출처가 표시됩니다: **기본**(앱 기본값 그대로), **수정됨**(고쳐 저장함), **사용자 추가**(직접 만든 지침).
- 본문을 고친 뒤 **저장**해야 반영됩니다. **변경 취소**는 저장하지 않은 수정을 버립니다. 저장하지 않은 채 다른 지침으로 넘어가면 먼저 묻습니다.
- **기본값과 비교**로 앱 기본값과 무엇이 다른지 보고, **기본값으로 되돌리기**로 기본 텍스트를 불러옵니다. 되돌린 뒤에도 **저장**해야 반영됩니다.
- 앱 기본 지침은 지울 수 없고 기본값으로 되돌리기만 합니다. 직접 만든 지침은 지울 수 있습니다.
- **앱 고정 지시**는 모든 에이전트 모드 앞에 붙는 규칙(제안 형식과 안전 규칙)이라 읽기만 할 수 있습니다.

### 에이전트 모드

에이전트 모드는 지침 하나가 모드 하나입니다. 모드 지침 위쪽에서 에이전트 패널에 보이는 카드를 정합니다.

- **카드 이름**, **설명 한 줄**: 에이전트 패널의 모드 카드에 보입니다.
- **기본 범위**: 새 대화를 시작할 때의 범위(현재 파일 또는 작품 전체).
- **순서**: 카드가 놓이는 순서. 작은 수가 앞입니다.
- 아래 본문은 에이전트에게 주는 대화 방식입니다. 무엇을 묻고, 언제 파일을 제안하고, 어떤 기준을 지킬지 적습니다.

**새 모드 추가**로 모드를 만듭니다. **모드 ID**는 영문 소문자·숫자·하이픈으로 정하며, 파일 이름(`agent/<ID>.md`)이 되므로 나중에 바꿀 수 없습니다. 빈 모드에서 시작하거나 기존 모드를 복사해 시작할 수 있습니다.

## 플랫폼 프리셋·작품 지침 만들기

플랫폼 프리셋과 작품의 지침은 화면에서 고칠 수 없고, 폴더에 파일을 넣어 만듭니다.

1. 위 "지침을 찾는 순서"의 폴더(`guidelines`)를 만듭니다. 플랫폼 프리셋이면 `data/platforms/<프리셋 ID>/guidelines/`, 작품이면 `data/works/<작품 폴더>/.atelierx/guidelines/`입니다.
2. 바꾸려는 지침과 **같은 이름**으로 파일을 넣습니다. 설정 → 지침에서 해당 지침 본문을 복사해 시작하면 편합니다. 에이전트 모드는 `agent` 폴더 안에 둡니다(예: `guidelines/agent/jsx.md`).
3. 대화 테스트나 해당 작업을 다시 실행해 바뀐 규칙이 반영되는지 확인합니다.

플랫폼마다 다른 규칙(쓸 수 있는 훅·함수, 응답 속 표기 등)은 플랫폼 프리셋 지침에, 작품 하나에만 맞는 규칙은 작품 지침에 두면 다른 작품에 영향을 주지 않습니다. 작품 지침 폴더는 작품의 앱 데이터라 파일 트리와 내보내기에는 나오지 않습니다.

## 지침 쓰는 요령

- 읽은 모델이 무엇을 해야 하는지 바로 알 수 있게 씁니다. "적절히", "자연스럽게"처럼 판단을 맡기는 말 대신 기준이나 예시를 적습니다.
- 지켰는지 가릴 수 있게 씁니다. 개수, 형식, 지켜야 할 예와 피할 예를 함께 둡니다.
- 금지만 적지 말고 대신 할 것을 함께 적습니다.
- 지침도 요청에 들어가는 글입니다. 실제로 어긴 적이 있거나 어기기 쉬운 규칙만 넣고, 고친 뒤에는 같은 입력으로 결과를 비교합니다.
