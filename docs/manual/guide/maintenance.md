# 유지 관리와 문제 해결

## 꾸러미로 옮기기·백업하기

**작품 꾸러미**: 작품 목록에서 작품 카드의 메뉴(⋯) → **꾸러미 내보내기**를 고르거나, 작품 창의 **작품 → 꾸러미 내보내기**를 누릅니다. 이미지(채택한 것만·모든 이미지·없음), 기록(스냅숏) 포함, LoRA 파일 포함을 고르고 파일 수와 용량을 확인한 뒤 **꾸러미 받기**를 누르면 ZIP 파일 하나를 받습니다. 작품 목록의 **전체 백업**은 모든 작품을 한 꾸러미로 받습니다. 원고, 작품 설정, 에이전트 대화, 검토 대기 초안은 늘 들어가고, API 키 같은 인증 정보는 들어가지 않습니다.

다른 PC나 새 앱 폴더에서는 작품 목록의 **가져오기**로 꾸러미 파일을 고릅니다. 담긴 작품과 만든 버전이 보이면 가져올 작품을 고르고 **가져오기**를 누릅니다. 같은 작품 ID가 이미 있으면 새 ID로, 같은 이름이 있으면 이름 뒤에 번호를 붙여 들여오며, 이미지와 채택 기록도 함께 따라옵니다. 이미 있는 작품이나 이미지는 덮어쓰지 않습니다.

**설정 꾸러미**: 설정 → **꾸러미·백업**에서 담을 설정(일반 설정, 플랫폼 프리셋, 전역 지침, LLM 연결, 페르소나, 이미지 라이브러리·생성 프리셋 등)을 고르고 **꾸러미 받기**를 누릅니다. ComfyUI 위치나 모델 폴더처럼 이 PC에만 맞는 설정은 담지 않습니다. **인증 정보**를 고르면 API 키가 이 앱의 마스터 비밀번호로 암호화된 채 들어가므로, 가져올 때 그 비밀번호를 입력해야 합니다. 가져오기는 같은 화면의 **꾸러미 가져오기**에서 하며, 바뀌는 설정은 미리 `state/packages/backups/`에 백업됩니다.

## 백업

앱을 완전히 종료한 뒤 실행 폴더의 `config`, `state`, `data`, `output`을 다른 디스크나 안전한 위치에 복사합니다. 작품은 `data` 아래에, 외부 인증 정보는 암호화된 `config` 아래에 저장됩니다. 중요한 이미지 모델이나 LoRA가 앱 폴더 밖에 있다면 해당 폴더도 별도로 백업하세요. 백업 복구는 앱을 닫은 상태에서 진행하고, 복원 전 현재 폴더도 다른 이름으로 보관합니다.

## 업데이트와 이동

**앱에서 바로 업데이트**: 도움말 → **업데이트 확인**에서 새 버전이 있으면 **업데이트**를 누릅니다. 앱이 새 버전을 받아 공개된 SHA256과 대조하고, 설정·작품 데이터(`config`, `data`, `state`)를 `state/update/backup-before-…zip`으로 백업한 뒤 준비를 마칩니다. **다시 시작해 설치**를 누르면 앱이 닫히고 프로그램 파일만 바뀐 뒤 새 버전이 열립니다. `config`, `state`, `data`, `output`은 그대로 두므로 옮길 필요가 없습니다. 교체에 실패하면 이전 버전으로 되돌리고 그 사실을 알려 줍니다. 진행 중인 이미지 생성·학습·설치·LLM 작업이 있으면 먼저 끝내야 합니다. 이 기능은 패키지로 실행한 앱에서만 동작합니다.

다른 PC로 옮기거나 수동으로 업데이트할 때는 새 패키지를 별도의 폴더에 풀고 이전 실행 폴더의 사용자 데이터 폴더를 복사해 옮기는 방법이 안전합니다. 앱 실행 파일과 `_internal`은 한 세트로 보존합니다. 기존 `config`, `state`, `data`, `output`을 새 패키지와 섞을 때는 앱을 종료하고 백업부터 만드세요. `Program Files` 같은 쓰기 제한 위치는 사용하지 않습니다.

## 자주 생기는 문제

- **앱이 열리지 않음**: Windows x64, WebView2 Runtime, .NET Framework 4.8을 확인합니다. `state/logs/desktop.log`도 살펴봅니다.
- **저장이 안 됨**: 실행 폴더가 쓰기 가능한지 확인합니다. 파일이 외부에서 변경되었다면 최신 내용을 다시 읽고 편집합니다.
- **LLM 요청 실패**: 설정의 주소, 모델, 인증 정보와 네트워크를 확인한 뒤 **모델 목록**과 **응답 테스트**을 각각 시도합니다. 오류에는 응답 코드에 맞는 안내가 붙습니다. 402는 결제나 요금제가 필요하다는 뜻이니(사용량 한도, 유료 전용 모델) 서비스의 사용량·결제 화면을 확인하거나 설정 → LLM에서 그 작업에 다른 모델을 고릅니다.
- **이미지 기능을 찾지 못함**: ComfyUI 연결과 경로, 설치 화면의 노드·모델 상태를 확인합니다. 설치 로그를 살펴봅니다.
- **작업이 오래 대기함**: 작업 대기열에서 GPU를 쓰는 이미지 생성이나 LoRA 학습이 진행 중인지 확인합니다. 이 PC의 GPU를 쓰는 LLM 응답이 진행 중이면 새 이미지는 그 응답이 끝난 뒤 시작합니다.
- **비밀번호를 잊음**: 잠금 화면의 재설정 흐름으로 인증 정보를 초기화한 뒤 제공자 키 등을 다시 등록합니다. 작품 파일은 그대로 유지됩니다.

재설치나 데이터 복사를 하기 전에 오류 메시지와 로그를 복사해 두면 문제 확인에 도움이 됩니다.

## 오류 제보와 문의

오류 제보, 기능 제안, 질문은 GitHub [Discussions](https://github.com/kiritype/AtelierX/discussions)에서 받습니다. 앱의 **도움말** 메뉴 → **오류 제보**·**기능 제안**·**질문·문의**를 누르면 해당 글쓰기 화면이 열립니다.

- 오류 제보에는 앱 버전(**도움말 → AtelierX 정보**), 재현 절차, `state/logs/desktop.log`에서 문제가 난 시각 근처를 함께 적어 주세요.
- API 키, 비밀번호, 개인 작품 내용은 지우고 올려 주세요.
- 확인된 내용은 작업 목록(Issues)으로 옮겨 진행하고, 원래 글에 진행 상황을 알려 드립니다.
- 보안 취약점은 공개 게시판에 쓰지 말고 [비공개 취약점 제보](https://github.com/kiritype/AtelierX/security/advisories/new)로 알려 주세요.
