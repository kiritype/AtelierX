# 검증 범위와 출시 상태

AtelierX는 1.0 이전 릴리스(0.x) 단계입니다. 1.0 전에는 기능과 데이터 형식이 바뀔 수 있고, 형식이 바뀌면 변환 도구를 함께
냅니다. 이 안내는 실제로 확인한 범위와 아직 확인하지 않은 범위를 구분해 기능 상태를 판단하도록 돕습니다. 버전마다 바뀐 점은
[바뀐 점](../changelog.md)에 있습니다.

## 0.6.0 시험판 확인 범위

- 업데이트 실패·재시도는 시계/HTTP 대역으로 검증했습니다. 실제 GitHub 서비스에 오류나 요청 제한을 유발하지 않았습니다.
- 그림체 탐색은 전체 artist 검색·풀 관리·후보 생성·Elo/되돌리기·실패/재개·세션 복원·프리셋 저장을 자동 회귀 및 가상 데이터 UI로 확인했습니다.
- ComfyUI 0.42.1 / RTX 4090에서 고정 장면·seed 104729, 1024×1024, 32 steps, CFG 5, er_sde/simple 조건으로 Anima base 1장과 같은 계열 aestheticV11 + flat LoRA 0.6 1장을 실제 생성했습니다. 결과 저장, 임시 평가/되돌리기, 프리셋 저장 및 재시작 후 세션 보존을 확인했습니다.
- 두 후보는 모델·LoRA를 함께 바꾼 기능 검증으로 개별 효과나 품질 순위의 근거가 아닙니다. 같은 프롬프트·시드라도 팔 자세·의상 세부 형태는 달라질 수 있습니다.
- NAI 실서비스 검증은 보류합니다. 다중 캐릭터 생성과 MOSS 지원은 이번 버전 범위 밖입니다.
- Windows 시험판 패키지 빌드 및 실행 검사는 [GitHub Releases](https://github.com/kiritype/AtelierX/releases)의 해당 시험판과 CI 기록을 확인하세요. 시험판의 사용자 확인과 정식 릴리스는 별도입니다.

## 확인된 내용

모두 개발 PC 한 대에서 확인한 것입니다.

- **패키지·업데이트**: Windows x64 포터블 패키지를 새 앱 데이터로 실행하고, 네이티브 창이 열리고 닫히는 것을 확인했습니다.
  앱 안 업데이트로 0.0.7에서 0.0.8로 올려 파일 교체·재시작·작품 유지를 확인했습니다.
- **LLM**: Ollama Cloud 연결에서 모델 목록, 응답, 스트리밍을 확인했습니다. 로컬 OpenAI 호환 서버로 에이전트 패널, 압축,
  대화 테스트와 페르소나를 확인했습니다.
- **이미지(ComfyUI)**: 이미지 생성·검수, 업스케일, 태깅, 검열 적용을 확인했습니다. 이 설명서의 캡처 일부가 그때 찍은 것입니다.
- **NovelAI**: 사용자 계정의 API 키로 Anlas 표시와 이미지 생성을 확인했습니다.
- **LoRA**: 학습 도구 설치부터 학습, 등록, 자동 적용 생성까지 확인했습니다.
- **생성 한 번에 업스케일·디테일러**(0.3.0): 모델 보정(shift), 업스케일 후 다시 그리기, 얼굴 디테일러를 켠 생성을 실제 ComfyUI로 끝까지 확인했습니다.
- **이미지 프롬프트 변환**(0.3.0): 로컬 LLM(LM Studio, Gemma 4 31B)으로 섹션 없는 인물의 본문 전체 변환과 범위 지정 변환(외모, 외모에 범위 추가, 새 의상)을 확인했습니다. 근거 문장이 본문 그대로 옮겨지고 과거·다른 인물·가정 문장은 빠졌습니다. 다른 모델에서는 결과가 다를 수 있습니다.
- **모델 화면**(0.3.0): Civitai 찾기와, 찾은 모델을 받기 탭에서 읽는 것까지 실제 Civitai로 확인했습니다.
- 작성·편집은 외부 이미지 도구 없이 사용할 수 있고, 앱 데이터는 포터블 폴더에 저장됩니다.

## 0.5.0 확인 범위

- 공식 0.4.3 실행 파일에서 만든 합성 데이터를 별도 복사본에 올려 UUID 전환 전후 프롬프트, 범위별 재정의, 채택·제외 상태, 학습 데이터, 이미지·마스크와 재시작 후 ID 보존을 비교합니다.
- 파일 교체 도중 강제 중단, 손상된 백업·저널과 잘못된 매핑은 자동 테스트로 검증합니다. 실제 사용자의 앱 폴더를 수동 변환한 결과는 아닙니다.
- 생성 정보 보기는 NAI·ComfyUI 형식의 합성 메타데이터를 넣은 이미지로 파일·드롭·붙여넣기, 표시·복사, 없음·부분 해석·손상 상태를 브라우저에서 확인합니다. 실제 서비스의 모든 파일·커스텀 노드를 검증한 것은 아닙니다.
- Windows RC의 새 설치·재시작, 0.4.3 데이터 업그레이드 및 대역 제공자 이미지 작업 결과는 [GitHub Releases](https://github.com/kiritype/AtelierX/releases)에 남깁니다. 별도 실행 파일로 기존 데이터를 여는 검증은 앱 내 자동 업데이트 교체 전체 흐름과 구분합니다.

## 0.4.3 확인 범위

- 갤러리 모달의 기록 버튼 중복, 페이지 경계 탐색과 판정 후 선택 유지, 이미지 작업 목록의 정리·복원, 상태 영역의 접힘 유지, R2 업로드 단계 전환, 프리셋·라이브러리의 이름 표시를 자동 회귀 검사로 확인했습니다.
- 개발 실행 환경의 Edge 브라우저에서 합성 이미지 2,060개를 사용했습니다. 61장인 범위에서 페이지 경계를 왕복하고, 판정으로 필터에서 제외된 이미지가 유지되는 것을 확인했습니다. 정리·복원과 미저장 마스크 보호, 접수 시 자동 펼침·스크롤이 없는 것도 확인했습니다.
- R2 화면은 합성 API 응답으로 40개 미리보기 항목, 900×600 창, 경로 수정 후 재확인, 실제 응답 URL 저장을 검증했습니다. 실제 R2 버킷에 업로드하지 않았습니다.
- 이름이 비거나 같거나 긴 항목과 전역·작품 항목을 확인했습니다. 이름 저장 후 기존 ID가 유지됩니다. UUID 전환과 데이터 마이그레이션은 포함하지 않습니다.
- Windows RC 패키지의 실행·재시작, 0.4.2 합성 데이터 호환성, 정리 후 파일·마스크 보존과 화면 검증 결과는 [GitHub Releases](https://github.com/kiritype/AtelierX/releases)의 해당 버전 기록에 남깁니다. 별도 설치에서 같은 데이터를 읽는 검증은 앱 안 자동 업데이트의 전체 교체 경로와 구분합니다.
- 이번 검증에는 실제 GPU 생성이나 유료 이미지 서비스 호출을 사용하지 않았습니다.

## 0.4.2 확인 범위

- 화면 상태 동시 저장, 단일 이미지·후처리·비교 결과의 재생성, 미리보기 랜덤 시드·재시도, 일괄 작업 중복 접수와 완료 기록 정리를 자동 회귀 검사로 확인합니다. 외부 서비스는 대역을 사용합니다.
- 개발 실행 환경의 실제 브라우저에서 가상 작품 20개 × 캐릭터 20개 × 의상 5개와 이미지 2,060개를 사용해 갤러리 접기·선택·필터·페이지 유지, 키보드 조작과 좁은 창을 확인했습니다. 실제 GPU로 2,060장을 생성하거나 처리 성능을 측정한 결과는 아닙니다.
- 같은 환경에서 이미 열린 대기열 탭 이동, 앱 안 기록 JSON 표시(외부 창·인증 오류 없음), 시드 **-1**의 Enter·포커스 이탈 저장을 확인했습니다.
- Windows RC 패키지의 실행·재시작, 0.4.1 합성 데이터 호환성 및 패키지 API·화면 검증 결과는 [GitHub Releases](https://github.com/kiritype/AtelierX/releases)의 해당 버전 기록에 남깁니다. 별도 설치에서 같은 데이터를 읽는 검증과 앱 안 자동 업데이트의 전체 교체 경로는 구분합니다.
- 이번 수정에서 실제 ComfyUI GPU·NovelAI·PixAI 유료 계정으로 생성하지 않았습니다. 기존 잘못된 경로의 파일을 자동 이동·삭제하거나 UUID로 변환하는 작업은 포함하지 않습니다.

## 0.4.1 확인 범위

업데이트 알림·탐색기 상태 복원과 입력·격리·업데이트 백업 보완을 자동 회귀 검사로 확인했습니다.
Windows 로컬 패키지 실행·재시작 후 저장 유지, 0.4.0 합성 데이터의 별도 설치 호환성, 실제 브라우저의 탐색기 상태 복원과 JSX 렌더링·격리 동작을 확인했습니다. 외부 다운로드 서비스의 실제 연결 검증과 자동 업데이트 전체 경로 검증은 별개입니다.
0.4.0에서 업그레이드할 때의 기존 `.old` 백업 주의사항은 [유지 관리](maintenance.md)를 먼저 확인하세요.

## 0.4.0 확인 범위

- 단일 이미지 생성(#242)과 갤러리에서 이미지 도구로 이동(#223)은 개발 실행 환경에서 사용자 동작 확인을 마쳤습니다.
- 대량 도구 작업(#222)은 격리된 API 모의 요청으로 8,000개 항목 접수·최대 32개 분할 공급·전체 결과 저장을 확인했습니다.
  저장 상태 복구, 중복 요청 방지, 128개 항목 취소와 취소 상태 복구도 확인했습니다. 가상 2×2 이미지를 사용한 검증으로,
  실제 8,000장 생성이나 GPU 처리 성능을 측정한 결과는 아닙니다.
- 이번 배포 변경(#220)은 모의 테스트로 검증했으며 실제 R2 업로드는 별도로 확인하지 않았습니다.

## 확인된 화면 제약

- 900×600처럼 좁은 창에서 LoRA 데이터셋이 있는 화면은 **학습** 탭이 본문과 겹쳐 클릭되지 않을 수 있습니다. 공식 0.4.3 패키지에서도 같은 합성 데이터로 재현한 기존 레이아웃 제약입니다. 창을 넓혀 사용하세요. 0.5.0 이름 표시 검증과 별도로 기록하며 이번 릴리스에서 수정하지 않았습니다.

## 아직 확인하지 않은 범위

- **다른 PC**: 깨끗한 별도 Windows PC에서 설치·업데이트·복구 절차를 확인하지 않았습니다.
- **Vertex AI**: 연결 프리셋은 있지만 실제 서비스로 확인하지 않았습니다. 액세스 토큰은 만료되며 자동으로 갱신하지 않아 직접
  바꿔 넣어야 합니다.
- **PixAI**: 구현은 되어 있지만 실제 계정으로 확인하지 않았습니다(PixAI API는 멤버십 베타 가입이 필요합니다).
- **이미지 도구 일부**: 디테일러, 인페인트, 검열 부위 감지, 배경 나누기는 실제 ComfyUI·모델로 확인하지 않았습니다.
- 모든 ComfyUI 노드·모델 조합, 다른 GPU·드라이버 조합에서의 이미지 생성과 LoRA 학습.

개발 PC에서의 성공은 다른 PC의 실행, 계정 설정, GPU·드라이버 조합을 보장하지 않습니다. 이미지와 학습 기능은 외부 프로그램·
모델의 버전과 시스템 요구사항을 따릅니다. 문제를 발견하면 [유지 관리와 문제 해결](maintenance.md)의 안내에 따라 제보해 주세요.
