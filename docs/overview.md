# 개요

## 목적

RP 챗봇 하나를 만드는 데 필요한 것(메인 프롬프트, 로어북, 캐릭터 설정, 화면용 JSX 컴포넌트, 캐릭터 이미지)을
**작품 단위로 한곳에서** 만들고, 고치고, 시험하고, 되돌릴 수 있게 한다.

- 글 작성은 사람이 하고, LLM은 뼈대 만들기·압축·검토를 돕는다. LLM 결과는 사람이 확인한 뒤에만 반영한다.
- 플랫폼마다 다른 규칙(용량 제한, JSX에서 쓸 수 있는 함수 등)은 코드에 넣지 않고 **플랫폼 프리셋과 가이드라인**으로 둔다.
  사용자가 편집할 수 있다.
- 데이터는 사람이 읽을 수 있는 파일(Markdown, JSON)로 저장한다. 다른 도구나 git으로도 다룰 수 있어야 한다.
  예외는 API 키 같은 인증 정보뿐이며, 마스터 비밀번호로 암호화한다.
- 화면의 파일 트리가 곧 디스크의 폴더 구조이고, 내보내기도 그 구조 그대로 한다. 폴더 구성은 사용자가 자유롭게 정한다.

## 하지 않을 것 (지금 기준)

- 특정 플랫폼 전용 규칙을 기본값으로 넣는 것. 기본 제공 플랫폼 프리셋은 범용 하나뿐이다.
- 플랫폼에 자동으로 올리는 것. 내보내기는 복사·파일 출력까지만 한다.
- 데이터를 데이터베이스에 넣는 것. 캐시·검색 색인은 다시 만들 수 있는 파생 데이터로만 둔다.
- 사용자의 git 저장소에 자동 커밋하는 것. 이력은 자체 스냅샷으로 관리한다.
- LLM 결과를 확인 없이 원본에 쓰는 것.
- 작품 내용을 암호화하는 것. 디스크 보호는 OS 기능이나 암호화 폴더 도구에 맡긴다.
- 앱 폴더 밖(사용자 프로필 폴더 등)에 설정·데이터를 쓰는 것.

## 용어

| 용어 | 뜻 |
|---|---|
| 작품 (work) | 챗봇 하나. 작품과 챗봇은 1:1이다. |
| 항목 | 작품 폴더 안의 `.md`·`.jsx` 파일. 종류(메인 프롬프트, 시작 상황, 로어북, 캐릭터, JSX, 메모)는 위치가 아니라 메타데이터 `kind`로 정하며, 만든 뒤 상단 폼에서 고른다. |
| 메인 프롬프트 | 매 대화에 항상 들어가는 본문(`kind: main`). 원본·압축본처럼 여러 판을 둘 수 있지만 사용 중인 것은 하나다. |
| 시작 상황 | 챗봇이 대화를 시작할 때 보내는 글(`kind: start`). 여러 개를 둘 수 있다. |
| 로어북 항목 | 키워드 등 조건이 맞을 때 들어가는 문서(`kind: lorebook`, 기본 종류). 캐릭터도 로어북 항목의 한 종류다. |
| 캐릭터 | 작품 안의 인물. `kind: character`인 로어북 항목이며, 이미지 데이터(외모·의상 프롬프트, LoRA)를 ID로 연결해 가진다. |
| 예약 참조 | `{{user}}`(챗봇을 쓰는 사용자)와 `{{char}}`(1:1 작품에서 대화 상대 캐릭터). 본문·관계도에서 쓰고, 테스트에서만 실제 이름으로 바꾼다. |
| ID | 작품·항목의 바뀌지 않는 식별자. 권유 형식은 작품 `W###`, 메인 프롬프트 `M###`, 시작 상황 `S###`, 로어북 `L###`, 캐릭터 `C###`, JSX `J###`. 관계도에만 있는 로어북 없는 인물은 `N##`. 표시 이름은 파일·폴더 이름이다. |
| 섹션 | 캐릭터 본문의 `##` 제목 단위(식별, 외모, 의상 등). 앱은 키로 다루고 제목 글자는 작품 언어를 따른다. |
| 태그 | 작품에 붙이는 이름표. 플랫폼 프리셋 ID와 같은 태그는 그 프리셋을 연결하고, 나머지는 분류용이다. |
| 플랫폼 프리셋 | 플랫폼 규칙 묶음: 용량 제한, 세는 방식, 로어북 활성화 규칙, JSX 허용 함수, 가이드라인. 설정에서 만들고, 작품에 태그로 연결해 상속받는다. |
| 그림체 프리셋 | 이미지 생성 설정과 artist 태그의 묶음(서비스, 모델, 샘플러, 크기, 작가 태그 등). 플랫폼 프리셋과는 다르다. |
| 가이드라인 | 사람이 읽고 LLM에도 그대로 주는 지침 문서(Markdown). 전역 → 플랫폼 프리셋 → 작품 순으로 덮어쓴다. |
| 임시 항목 | 사람이 확인하기 전의 LLM 결과(압축 후보 등). 채택해야 원본에 반영된다. |
| 스냅샷 | 작품(항목과 앱 데이터)의 한 시점 기록. 되돌리기·비교의 단위. |
| 배포 표시 | 실제 플랫폼에 올린 스냅샷에 붙이는 표시. |
| 휴지통 | 앱에서 지운 것이 가는 곳. 되살리거나 완전 삭제할 수 있다. |
| 메모 | 작품 폴더에 두지만 내보내지 않는 글(`kind: note`). 설정 노트, 아이디어 등. |
| 사용 여부 | 항목의 `enabled`. 끄면 내보내기·테스트·용량 합계에서 빠진다. 여러 판을 함께 보관할 때 쓴다. |
| 금고 | API 키 등 인증 정보를 마스터 비밀번호로 암호화해 두는 파일. 같은 비밀번호로 앱 실행 인증도 한다. |
| 앱 폴더 | 프로그램·설정·데이터·출력을 모두 담는 폴더. 통째로 옮겨 쓸 수 있다. |
| 데이터 루트 | 앱 폴더의 `data/`. 작품, 플랫폼 프리셋, 가이드라인, 이미지 라이브러리를 둔다. |
| 출력 루트 | 앱 폴더의 `output/`. 생성 이미지·학습 로그 같은 큰 파일을 둔다. |

## 배포 형태

- 개발 중에는 로컬 웹 서버 + 브라우저로 쓴다.
- 목표는 스탠드얼론 프로그램(사용자가 고른 쓰기 가능한 폴더에 풀거나 설치, 창, 네이티브 파일 선택, 트레이). 그래서 처음부터
  다음을 지킨다.
  - 화면은 빌드한 정적 파일을 서버가 제공한다(웹·데스크톱 창 어디서나 같은 방식).
  - 설정·데이터·출력을 모두 앱 폴더 안에 둔다(포터블). 업데이트는 프로그램 폴더만 바꾼다.
  - 파일·폴더 선택, 알림 같은 기능은 "데스크톱 기능이 있으면 쓰고, 없으면 대체 화면"으로 추상화한다.
- 상세는 [architecture.md](architecture.md).
