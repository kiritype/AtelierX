# ADR-0018: 묶음 검증 기준·대상 변경과 운영 예외

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: ADR-0007~0010, ADR-0016

## 결정

| 항목 | 확정 기준 |
| --- | --- |
| 후보 동점 | 고정 순서로 선정해 반복 실행마다 기준이 바뀌지 않도록 함 |
| 선정 근거 | 잘 보이는 특징 등 선정 이유 표시. 점수·가중치는 테스트로 조정 |
| 보조 수 | 필요한 특징을 비교하는 최소 수, Provider 한도 준수 |
| 보조 교체·삭제 | 해당 자료를 사용한 판정을 재검증 필요로 표시하고 사용자 확인 후 재검증 |
| 실행 중 대표 변경 | 기존 기준으로 마무리하되 과거 기준 결과로 보존. 새 기준에 따른 재생성에 자동 적용하지 않음 |
| 실행 중 대상 추가 | 현재 요청 대상 유지. 추가 이미지는 단일 통과 후 별도 일관성 검사 |
| 실행 중 대상 삭제·교체 | 결과는 이력으로 보존하고 현재 그룹 판정에서 제외. 교체 이미지는 새 대상으로 검사 |
| 오래된 화면 요청 | Core가 기준·대상 변경을 확인하고 변경됐으면 안내·재확인 |
| 기준 자료 모순 | 사용자 기준 확인 요청. 임의 문제 대상 확정·자동 재생성 없음 |
| 불확실한 판단 | 비교 불충분과 이유 반환. 일치/불일치 강제 없음 |
| 참조 접근 실패 | 비교 불충분과 구분한 실행 오류 |
| 추적 | 실제 기준·보조·대상·검사 설정 기록 |

## 영향 및 후속 구현

실행 당시 입력과 현재 그룹 판정의 유효성을 구분한다. 자료가 바뀌어도 과거 이력을 삭제하지 않으며 더 늦게 도착한 결과가 최신 기준 결과를 덮지 않도록 한다. 동점의 구체 정렬 키·버전 저장·원자적 조건 검사·현재 집계 구현은 후속 설계한다.

## 충돌 확인

ADR-0001~0017의 Core 책임·기준 변경 확인·부분 재검증·오류 및 취소 경계를 유지한다. 미정 운영 예외를 구체화하며 기존 Accepted 결정을 대체하지 않는다. 단일 검증의 명시 요소 누락 불합격을 묶음 불확실성 처리로 변경하지 않는다.

## 기록 방식 보완

사용자는 나머지 Validation 설계를 기존 요구사항·일반적인 기준으로 진행하고 꼭 필요한 판단만 질문하도록 위임했다. 확정 요구와 충돌하지 않는 세부 설계·테스트값은 주 에이전트가 정리하고 근거·변경 이력을 남긴다. 기존 제품 의도·책임·자동 실행 경계 변경이나 해소할 수 없는 요구 충돌은 사용자에게 확인한다. 이 위임은 미구현 Backend·외부 유료 호출·모델 다운로드의 실행 승인이 아니다.
