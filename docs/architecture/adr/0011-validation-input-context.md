# ADR-0011: 단일·묶음 검증 입력 정보와 준비 책임

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: [ADR-0003](0003-generation-execution-and-queue.md), [ADR-0004](0004-validation-outcomes-and-errors.md), [ADR-0007](0007-group-image-validation.md), [ADR-0010](0010-group-completion-and-partial-failure.md)

## 결정 범위

Validation 입력을 공통 정보·단일 검증 입력·묶음 검증 입력으로 구분하고 필요한 정보의 의미와 준비 책임을 확정한다. 필드명·JSON 구조·필수/선택·이미지 전송 방식은 별도 결정한다.

## 전달할 정보

| 구분 | 정보 | 기준 |
| --- | --- | --- |
| 공통 | 요청 추적 정보·검사 설정 | 어떤 요청이며 어떤 검사를 수행하는지 명시 |
| 공통 | 이미지 식별·접근 정보 | 실제 이미지와 기록 연결. 파일 전달 방식은 별도 |
| 단일 | 실제 생성 Positive / Negative Prompt | 편집 중인 최신 Prompt가 아니라 해당 시도의 고정 입력 |
| 단일 | 실제 생성·후처리 설정 | 모델·LoRA·Seed 등 재생성 변경값 판단에 필요한 정보 |
| 단일 | 기대 최종 출력 조건 | 해상도·포맷·Alpha 등. 후처리가 있으면 최종 출력 기준 |
| 묶음 | 그룹 식별 정보 | 작품·캐릭터·의상 그룹과 검증 요청 연결 |
| 묶음 | 이번 판정 대상 이미지 목록 | 전체 검증과 일부 재검증의 범위를 명시 |
| 묶음 | 대표·보조 이미지와 기준 식별 정보 | 판정 대상과 비교 자료 구분, 기준 변경 여부 확인 |
| 묶음 | 이미지별 생성 Prompt | 자세·구도·표정 등 의도된 차이 해석 |
| 묶음 | 그룹에서 유지할 외형·의상 정보 | 이미지 사이에서 같아야 하는 특징 명시 |

정보 범주를 확정한 것이며 모든 필드를 모든 요청에 필수로 요구하는 Schema는 아니다. Negative Prompt를 입력으로 전달한다는 결정만으로 개별 금지어·추상 표현의 판정 기준을 확정하지 않는다.

## 최종 이미지 검증

생성 → 선택한 후처리 → 최종 출력이 완료된 **최종 이미지**를 단일 검증에 전달한다. 해상도·포맷·Alpha 등의 기대 조건도 같은 최종 출력 단계에 맞춘다. 중간 이미지와 최종 출력 조건을 혼합하지 않는다.

후처리가 바꾼 가시성·투명도 등과 Prompt 판정의 세부 관계는 별도 기준에서 다룬다. 이번 결정으로 ADR-0004의 명시 요소 누락·불일치 불합격 원칙을 변경하거나 후처리별 예외를 추가하지 않는다.

## Core의 입력 준비

Core가 캐릭터 외형·의상·각 이미지의 생성 Prompt·검사에 필요한 Context를 정리해 전달한다. Validation은 Core DB에서 추가 정보를 찾아 조합하지 않는다. 기존 Core SQLite 소유·REST 업무 경계와 Generation의 AI Provider/DB 직접 접근 금지를 유지한다.

묶음 예시: 같은 캐릭터·의상 그룹의 3번·7번을 대표 1번·보조 2번과 비교한다. 자세·표정 차이는 각 이미지의 Prompt로 해석하고 공통 외형·의상의 차이를 검사한다. 1번·2번은 비교 자료이며 이번 판정 대상과 구분한다.

## Validation API 입력과 Provider 입력 구분

Validation API는 이미지·그룹 ID와 추적 정보 등을 결과 연결에 사용한다. 이 정보를 외부 AI에 그대로 전달하지 않는다. Validation 내부에서 해당 검사에 필요한 이미지·Prompt·공통 특징 등 최소 Context를 구성한다. 내부 식별값도 실제 필요가 없는 경우 외부 AI에 보내지 않는다.

## 미결정 사항

이미지 업로드/다운로드·원격 접근 방식, 필수·선택 필드, 정보 부족 처리, 검사 설정·Profile 세부, 전체 기계 검증 Schema·필드명·Endpoint, 식별 및 기준 버전 표현, Provider별 변환, 세부 검사와 후처리 관계는 후속 결정이다. ADR-0005의 단일 응답 초안은 Proposed로 유지한다.

[ADR-0012](0012-validation-image-transfer-and-required-input.md)에서 조회 API/업로드·필수 정보·입력 부족 처리를 확정했다. 검증은 가능하지만 재생성 설정 정보가 부족하면 판정을 제공하고 자동 재생성 제안은 하지 않는다. 충분한 정보에 대해 Provider가 잘못된 변경값을 반환한 실행 오류와 구분한다. 전체 Schema·필드명·전송/인증 세부는 계속 미정이다.

## 충돌 및 대체 확인

ADR-0001~0010과 대조했다. ADR-0003의 최종 출력 검토·고정 입력, ADR-0004의 실제 Prompt 기반 검증, ADR-0007~0010의 그룹 비교 대상·기준·부분 재검증을 구체화한다. 기존 Accepted 결정을 대체하지 않고 상태·supersede 관계를 유지한다. 입력 전송을 구현하거나 미정 Schema를 승인하지 않는다.
