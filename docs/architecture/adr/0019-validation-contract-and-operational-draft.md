# ADR-0019: Validation 초기 API·저장·운영 설계

- 상태: Proposed — 사용자 위임에 따른 ADR 검토용 문서 초안, 개별 승인 질문 없이 보완
- 작성일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: [ADR-0005](0005-validation-response-contract.md), ADR-0011~0018

## 목적과 출처

기능·운영 원칙 논의를 마친 뒤 남은 세부 계약을 한 곳에 모은다. 사용자는 기존 요구사항과 일반적인 기준을 바탕으로 설계하고 테스트로 조정하도록 위임했다. 아래는 그 위임에 따라 정한 초기 설계이며 테스트 완료·Backend 구현 완료를 뜻하지 않는다. ADR-0005는 이전 합의대로 초안으로 유지한다.

## API 표면

현재 검토 범위는 요청·응답의 의미와 책임이다. 아래 경로·필드명·숫자는 구체적인 논의를 위한 설계 초안이며 코드·Schema·자동 검사 결과로 확정되지 않는다.

| API 초안 | 용도 |
| --- | --- |
| POST /v1/uploads | 정지 PNG/WebP multipart 업로드, upload_id·SHA-256·크기·실제 형식 반환 |
| POST /v1/validation-jobs | kind=single/group 입력, Idempotency-Key 필수, 새 접수 202 |
| GET /v1/validation-jobs/{job_id} | 작업 상태·진행·결과 연결 조회, 조회 성공 200 |
| GET /v1/validation-jobs/{job_id}/result | 준비된 결과 200, 미완료 409·현재 상태 안내 |
| POST /v1/validation-jobs/{job_id}/cancel | 실행 취소 요청, 중단 확인 전 cancelling 유지 |
| GET /v1/validation-jobs | cursor 페이지 조회·상태/Provider 필터 |
| GET /v1/events | 변경 ID·revision 알림. 누락 복구 불가 시 현재 페이지 재조회 |

Generation의 이미지 조회 경로는 해당 서비스 계약에서 정한다. Validation 입력은 server_id+image_id+digest 또는 upload_id+digest 중 하나로 지정하며 임의 URL/파일 경로를 받지 않는다. 서비스 주소와 인증 정보는 서버 설정에서 해석한다. 외부 Provider에는 내부 주소·접근 토큰을 넘기지 않는다.

ID는 외부 계약에서 opaque string으로 취급해 프로젝트 공용 ID 정책을 선결하지 않는다. request_id는 호출 추적, job_id는 실행 기록, idempotency key는 중복 접수 방지로 분리한다.

## 입력·결과와 상태

입력은 schema_version·kind·subject·images·profile_snapshot·provider_snapshot을 기본 구조로 한다. single은 실제 positive/negative Prompt·필요한 generation_settings·expected_output, group은 group_id·group_revision·reference_revision·targets·primary_reference·auxiliary_references·image별 Prompt·공통 외형/의상을 포함한다. Secret은 snapshot에 복사하지 않고 서버 측 참조로 관리한다.

Job 상태 초안은 queued/running/cancelling/completed/failed/cancelled. completed는 처리 완료이며 이미지 합격을 뜻하지 않는다. 대기 자원/사유는 별도 표시한다. 단일 결과는 ADR-0005의 passed/rejected/error 구분을 유지하고 실행 실패는 failed와 연결한다. 묶음은 개별 match/mismatch/insufficient/error와 summary=all_match/mismatch_present/incomplete를 사용한다. 일부 오류는 개별 결과로 보존하고 그룹 Job 자체의 치명적 실패와 구분한다.

결과에는 대상 범위·판정 근거·미실행 검사·생성 현황·비교 집계·실제 기준과 Provider/Profile·유효성을 연결한다. 현재 유효성은 Core가 현재 revision과 대조해 판단하며 Validation이 Core DB를 조회하지 않는다. 기준 역할과 판정 대상 역할을 분리하고 비교가 수행되지 않은 기준 이미지의 자기 비교를 합격으로 집계하지 않는다.

공통 error는 code/message/stage/field와 request_id로 연결한다. 입력 오류의 400/413/415/422, 자체 인증 401/권한 403, 대상 없음 404, 키·revision 충돌 409를 구분한다. 이미 접수된 Provider 오류는 조회 HTTP를 5xx로 바꾸지 않고 Job 결과에 담는다. ADR-0005의 동기 오류 HTTP 표는 비동기 조회에 적용하지 않는다. access/integrity/expired-upload/revision-conflict 코드와 Profile 검사별 finding 코드는 Schema 작성 때 보완한다.

## 요청·응답과 검사 보고 — 문서 검토 보완

### 응답의 세 층

| 구분 | 제공할 의미 | 혼동하지 않을 것 |
| --- | --- | --- |
| 접수 응답 | 요청 수락 여부·Job 식별·조회 방법 | 접수 성공은 이미지 합격이 아님 |
| 작업 조회 | 대기/실행/취소/종료·진행·결과 준비 여부 | 작업 완료는 모든 이미지 일치가 아님 |
| 검증 결과 | 단일 판정 또는 묶음 이미지별 판정·검사 근거·실제 기준/설정 | 조회 성공 HTTP와 이미지 판정은 별개 |

접수 전에 확인 가능한 형식·필수 입력·권한·이미지 개수 오류는 요청 오류로 반환한다. 원격 파일 접근·Decode·Provider 수행처럼 접수 후에 발견할 수 있는 오류는 해당 Job의 실패·대상별 오류로 기록한다. 비동기 접수 전에 모든 외부 접근이나 AI 실행을 끝내도록 요구하지 않는다. 두 경우 모두 AI 실행 전 필요한 입력 검사를 유지한다.

### 검사마다 남길 정보

검사 ID/종류·설정상 활성 여부·실행 여부·판정·생략 이유·대상/비교 자료·관찰 근거를 구분해 기록한다. 기술적인 enum 문자열과 필수 필드 구성은 후속 계약으로 남긴다.

| 상황 | 검사 보고 | 종합 처리 원칙 |
| --- | --- | --- |
| 사용자가 검사를 Off | 비활성·미실행 | 검사 범위에서 제외. 통과했다고 표시하지 않음 |
| Negative Prompt 미사용 | 적용 대상 없음·미실행 | 금지 요소가 없다는 입력 조건을 기록 |
| 앞선 출력 검사에서 불합격 | 이후 AI 검사 생략·선행 불합격 명시 | 출력 불합격 유지. 의도된 조기 종료를 추가 실행 오류로 취급하지 않음 |
| 입력 접근/Decode 실패 | 입력 오류·이후 검사 미실행 | 단일 오류 또는 묶음 영향 대상 오류. 불합격과 구분 |
| 정상 수행·요구 충족 | 완료·일치/통과 및 확인한 범위 | 활성 검사 범위의 판정에만 사용 |
| 정상 수행·차이 확인 | 완료·불합격 근거 | 다른 항목의 통과가 불합격을 상쇄하지 않음 |
| 묶음 비교 자료 부족 | 비교 불충분·부족한 특징/이유 | 기존 묶음 판정 미완료 원칙 유지 |
| 수행해야 할 검사 실행 실패 | 실행 오류·대상·사유 | 합격으로 처리하지 않고 자동 재생성 근거로 사용하지 않음 |
| 취소로 중단 | 취소·미완료 범위 기록 | 완료 판정으로 바꾸지 않고 후속 자동 흐름 중지 |

모든 콘텐츠 검사가 Off이거나 적용 대상이 없으면 입력 파일을 읽을 수 있다는 사실만 남는다. 이를 이미지 검증 합격으로 보이지 않게 **검사 대상 없음**으로 안내하는 방향을 권고한다. 단일 완료 판정에 새 enum을 임의 추가하지 않고, 접수 단계의 검사 설정 확인과 요청 범위 안내로 처리하는 안을 유지한다. 이는 ADR-0005의 결과 형태를 일괄 변경하지 않는다.

### 오류와 부분 결과

단일 검증에서 필수 실행이 실패하면 ADR-0005 초안의 result=null 경계를 유지한다. 실패 전에 관찰한 내용은 진단 이력에 남길 수 있지만 정상 판정·재생성 제안으로 반환하지 않는다. 묶음은 오류가 난 이미지와 정상 처리된 다른 이미지를 구분해 보존한다. 그룹 Job 자체를 수행할 수 없는 오류와 일부 비교의 오류도 분리한다.

출력 불합격에 따라 AI를 계획적으로 생략한 경우와 수행 예정 AI 호출이 실패한 경우를 구분한다. 전자는 정상 불합격, 후자는 실행 오류다. 이 구분으로 ADR-0014의 조기 종료와 ADR-0005의 오류 분리가 충돌하지 않는다.

### 결과의 현재 유효성

Validation은 실제 사용한 기준·대상·Profile·Provider 기록을 반환한다. Core는 현재 그룹과 대조해 현재 판정에 포함할지, 과거 기준 이력으로만 보존할지 판단한다. 부분 요청의 모든 대상이 일치해도 현재 그룹 전체가 일치한다고 바로 표시하지 않는다. 기준 교체·대상 삭제·늦은 결과와의 관계는 ADR-0018을 따른다.

## 중복 방지·변경값

접수 키는 인증 주체 범위로 구분한다. 같은 키·같은 의미의 본문은 기존 Job을 반환하고 다른 본문이면 409다. 접수 기록과 Queue 등록은 원자적으로 관리한다. 명시적 재검증은 새 키·Job을 사용한다. 알 수 없는 완료 상태의 자동 재전송은 하지 않고 기존 Job/접수 기록을 조회한다.

변경값은 허용된 생성 필드의 교체 목록과 필드별 이유다. 중복 필드·알 수 없는 필드·잘못된 타입·의도 변경은 거부하고 일부 적용하지 않는다. LoRA 등 순서가 있는 목록은 전체 목록 교체로 검증해 인덱스 이동의 모호함을 피한다. 모델 조합의 최신 지원 정보는 Generation이 제공하며 Core가 필요한 범위로 Validation에 전달한다. 최종 실행 검사는 Generation이 수행한다.

## 저장과 복구

Core SQLite는 그룹·기준 revision·검사 설정·영속 결과와 재생성 이력을 소유한다. Validation의 독립 실행 Queue는 자체 작업 디렉터리에 구조화된 작업/접수 키/상태/결과 파일을 보관하는 초기안을 사용한다. 임시 파일 작성 후 원자적 교체·단일 기록 주체로 접수 경쟁을 제어하며 별도 SQLite 접근은 도입하지 않는다. 다중 프로세스 확장·잠금 구현은 구현 검토 대상이다.

queued는 복원, running/cancelling은 실행 식별값으로 확인하고 추적 불가면 실패 처리한다. 늦은 응답은 이력으로 구분하고 취소된 작업의 후속 생성에 적용하지 않는다. Core 결과 등록은 job_id 기반 중복 방지와 재조회로 복구한다. 기록 수신 확인 전 결과 파일을 정리하지 않는다. 직접 사용 시에도 임시 업로드 삭제와 결과 이력 보존은 분리한다.

## 테스트용 초기 운영값

아래는 성능 측정 결과가 아니라 시작값이다. Core 설정에서 운영자가 조정할 수 있게 하고 Provider의 더 낮은 한도가 우선한다. 검사 입력은 한도 초과 시 줄이지 않고 오류로 처리한다.

| 항목 | 초기값 |
| --- | --- |
| Provider 동시성 | 1 (ADR-0016 확정 기본값) |
| Provider 호출 제한시간 | 180초/호출, 묶음 Job 전체 시간과 구분 |
| 네트워크 연결 제한시간 | 10초 |
| 업로드 1파일 | 32 MiB |
| Decode 후 크기 | 32 megapixels, 가로/세로 각각 최대 16,384 |
| 요청 이미지 수 | 대상+참조 중복 제거 후 128장, Provider 호출별 한도 별도 |
| JSON 요청 크기 | 2 MiB, 이미지 base64 포함하지 않음 |
| 임시 이미지 보관 | 마지막 참조 Job 종료 후 24시간; 미참조 업로드는 업로드 후 24시간 |
| 정리 점검 주기 | 1시간; 활성 참조가 있으면 정리 보류 |
| 디스크 여유 | 5 GiB 미만이면 새 업로드 거부, 기존 활성 파일 삭제 금지 |
| 접수 키 보관 | 최소 종료 후 7일, 활성 작업은 만료 금지 |

Queue 대기 시간은 표시하되 초기에는 임의 대기 만료로 대규모 요청을 실패시키지 않는다. 자원 대기·사용자 취소가 가능해야 한다. 긴 묶음의 시간과 호출 횟수는 이력으로 관찰해 필요시 별도 제한을 조정한다.

## 접근·Secret 초기안

서비스별 무작위 Bearer credential을 사용하고 권한은 이미지 읽기·검증 제출/조회 등 역할로 제한한다. Secret은 Core 설정의 참조와 분리된 OS 보호 저장소를 우선하고 저장·배포 방식은 공통 인증 구현에 맞춘다. 원격 통신은 TLS, 로컬은 loopback을 사용한다. URL·로그·결과·Profile export에 Secret을 포함하지 않는다. 토큰 갱신/회수는 요청 파일 범위와 별도로 적용한다.

## 확인이 꼭 필요한 경우와 후속 작업

현재 사용자에게 추가 제품 결정을 요청할 사항은 없다. 위 세부안은 구현 전 Schema·상태 전이·실패 복구 테스트로 검토한다. 특정 VLM/SDK·모델 다운로드·유료 호출은 별도 환경 준비 범위다. 기존 요구를 바꿔야 하거나 외부 전송/비용·기록 삭제·자동 실행 경계를 확대해야 할 경우에만 사용자 판단을 요청한다.

Provider 품질 평가 데이터, 기계 검증 Schema, Queue 파일 기록의 crash 검증, 직접 ComfyUI 실행과의 경쟁은 남은 구현 검증이며 완료로 취급하지 않는다. 테스트별 환경·설정·결과·수정 이유를 기록한다. 기존 Accepted ADR을 대체하지 않고 ADR-0005도 자동 Accepted로 바꾸지 않는다.

## 구체화·검증 기록 — 2026-09-13

**현재 적용 상태 보완:** 사용자는 해당 작업 이후 현재는 ADR 검토 단계임을 재확인했다. 아래 자료는 범위를 앞서 작성한 참고 산출물로 보존하며 확정 명세·구현 착수 근거로 사용하지 않는다. 현재 후속 작업은 문서 검토에 한정하고 해당 코드·자동 검사·기계 Schema를 확장하거나 실행하지 않는다. 별도 승인된 Custom Node 개발과 구분한다.

[계약 초안](../../contracts/validation/README.md)에 5종 JSON Schema·10개 예제·추가 의미 검사·상태 전이를 작성했다. [검증 기록](../../development/validation-contract-verification.md)의 18개 검사가 통과했다. 실제 저장/Provider/GPU 복구는 아직 미시험이다. 여러 파일의 원자적 갱신 문제는 Job 원본 기록을 권위로 두고 인덱스를 복원하는 초안으로 보완했다. Schema와 Python은 계약 검증 자료이며 Backend 언어/라이브러리 선택이 아니다.

## 현재 검토 결론

요청/상태/판정의 분리, 미실행 이유, 의도된 조기 종료와 실행 오류의 구분은 기존 확정 요구를 일관되게 표현하는 문서 보완이다. ADR-0005·0019는 Proposed를 유지하고 새로운 제품 결정을 사용자 승인 없이 Accepted로 바꾸지 않는다. 현재 사용자에게 별도 판단을 요청할 충돌은 없다.

다음 ADR 검토는 접수 중복·오래된 기준 요청·취소와 완료 경쟁·결과 이력 보존의 문서상 예외를 점검하는 것이다. 이미 합의한 정책을 다시 승인받지 않고 세부 예외와 기존 ADR의 정합성만 검토한다.

## 후속 확정 — ADR-0020

[ADR-0020](0020-job-request-and-result-races.md)에서 접수 키 중복/충돌·응답 유실 조회·수동 재검증 연결·설정 고정·기준 재확인·취소/완료 반영 순서·늦은 결과·Core 저장 확인·임시 이미지와 이력 보존 분리를 확정했다. 해당 원칙은 초안에서 구체화됐으며 본 문서 전체의 API/저장/수치를 Accepted로 바꾸지 않는다.
