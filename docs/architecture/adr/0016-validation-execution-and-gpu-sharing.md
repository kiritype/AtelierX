# ADR-0016: Validation 비동기 실행·Queue·GPU 공유

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: [ADR-0003](0003-generation-execution-and-queue.md), [ADR-0006](0006-validation-manual-retry.md), [ADR-0010](0010-group-completion-and-partial-failure.md), [ADR-0015](0015-validation-providers-and-fallback.md)

## 실행과 Queue

| 항목 | 확정 기준 |
| --- | --- |
| 실행 방식 | 단일·묶음 모두 비동기 Job 접수. Job ID 반환 후 상태·결과 조회 |
| 책임 | Core가 전체 생성·검증 흐름 관리, Validation이 자신의 Queue·실행 상태 관리 |
| 순서 | 실행 가능한 작업을 접수 순서대로 처리. 초기 사용자 순서 변경 기능 없음 |
| 동시 실행 | Provider별 제한 설정. Local VLM·외부 API 모두 초기 기본 1개 |
| Provider별 분리 | 느리거나 장애가 난 Provider가 다른 Provider 실행까지 막지 않도록 Queue 분리 |
| 묶음 실행 | 그룹 요청은 하나의 Job으로 추적. 내부 비교는 Provider 한도에 맞게 분할하되 기준·대상 연결 유지 |
| 상태 알림 | REST 상태/결과 조회와 SSE 변경 알림. 전체 결과 반복 전송 없음 |
| Timeout | 대기 시간과 Provider 실행 시간 구분. 실행 Timeout은 오류 종료, 자동 재시도 없음 |
| 대기 취소 | Queue에서 제거하고 취소 완료 |
| 실행 취소 | 취소 중 표시 후 가능한 실행 중단. 중단 불가 외부 호출의 결과는 후속 자동 흐름에 적용하지 않음 |
| 재시작 복구 | 대기 작업 복원. 실행 중 상태 확인 후 추적 불가능하면 실패 처리. 무조건 재전송하지 않음 |
| 중복 접수 | 동일 접수 키 재전송은 기존 Job 반환. 명시적 사용자 재검증은 새 요청으로 구분 |

Provider별 분리는 공유 GPU 제한을 우회하지 않는다. 묶음 분할도 같은 Job·Provider 동시성 및 GPU 정책을 따른다. 기준을 생략하거나 요청 이미지를 임의 제외하는 방식으로 Provider 한도를 맞추지 않는다. 분할해도 비교가 불가능한 요청은 기존 미지원/입력 한도 오류 정책을 유지한다.

## 동일 GPU 공유

| 항목 | 확정 기준 |
| --- | --- |
| 조정 주체 | Core가 같은 GPU를 사용하는 Generation·Local Validation의 실행 권한 조정 |
| 추론 중첩 | 같은 GPU에서 두 서비스의 모델 추론이 겹치지 않도록 함 |
| 우선순위 | 실행 중 작업 유지. 다음 작업은 준비된 요청 순서 기준, 무조건적인 검증 우선권 없음 |
| 메모리 | 실행 종료와 VRAM 해제 구분. 다른 서비스 실행 전 필요한 메모리 확보 확인 |
| 외부 Provider | 로컬 GPU 실행 권한 없이 실행. Provider 동시성 제한은 적용 |
| 독립 자원 | 다른 GPU·다른 PC의 독립 자원은 병렬 실행 가능. 같은 자원을 공유할 때만 상호 제한 |

Core가 조정하는 전체 흐름과 각 서비스의 독립 실행 가능성은 유지한다. 독립 호출의 실행 권한 참여 방식은 구체 서비스 계약에서 정의한다. Generation이 AI Provider나 Core SQLite에 직접 접근하는 구조는 도입하지 않는다.

## 직접 ComfyUI 실행의 한계

Core를 거치지 않는 ComfyUI 화면의 직접 실행까지 Core가 통제할 수는 없다. 실행 전 ComfyUI 작업·GPU 가용 상태를 확인하고 사용 중이면 Local Validation을 대기시킨다.

이 확인만으로 확인 직후 발생한 직접 실행과의 경쟁을 완전히 막는다고 보장하지 않는다. 이를 위한 연동·실행 권한의 원자성·메모리 부족 대응은 후속 구현에서 정한다. 사용자 작업을 임의로 중단하거나 모델이 로드된 채로 남아 있는데 메모리가 확보됐다고 간주하지 않는다.

## 테스트·미결정 사항

Provider 동시성 기본 1을 초기 기준으로 적용하고 ADR-0015의 테스트·변경 기록 원칙에 따라 조정한다. Queue 저장 기술·Job 상태 enum·접수 키 수명/동일 키 다른 본문·SSE 상세·Timeout 수치·대기 제한은 미정이다.

GPU 식별·실행 권한 획득/반납·장애 시 해제·독립 호출 통합, 모델 unload·메모리 확보 판단, 직접 실행과의 경쟁, 묶음 비교 분할 알고리즘, 외부 취소 완료·늦은 응답 기록은 후속 설계한다. 이번 ADR 확정은 런타임/모델 설치나 Backend 구현 개시가 아니다.

## 충돌 및 대체 확인

ADR-0001~0015와 대조했다. ADR-0003의 Generation FIFO·취소·복구와 Core 책임, ADR-0006의 자동 검증 재시도 금지, ADR-0010의 그룹 종료·부분 실패, ADR-0015의 Provider별 설정 고정을 유지한다. 미정이던 Validation 실행·GPU 조정을 구체화하며 Accepted 결정을 대체하지 않는다.

ADR-0005는 Proposed로 유지한다. 비동기 접수·결과 조회에는 그 초안의 동기 실행 HTTP 예시를 그대로 적용하지 않으며 후속 응답 계약에 반영한다.
