# ADR-0020: 검증 접수·변경·취소·결과 보존 예외

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: [ADR-0016](0016-validation-execution-and-gpu-sharing.md), [ADR-0018](0018-group-validation-change-handling.md), [ADR-0019 초안](0019-validation-contract-and-operational-draft.md)

## 결정

| 상황 | 확정 처리 |
| --- | --- |
| 동일 키·동일 내용 중복 요청 | 기존 Job 반환 |
| 동일 키·다른 내용 | 충돌 오류, 기존 요청 변경 없음 |
| 접수 응답 유실 | 접수 키로 기존 Job 조회. 새 키 자동 재접수 없음 |
| 사용자 명시 재검증 | 새 키·새 Job 생성, 이전 검증과 연결 |
| 접수 이후 설정 변경 | 접수 당시 설정으로 실행. 변경 설정은 새 요청부터 |
| 오래된 기준으로 재검증/재생성 요청 | Core가 변경 여부를 확인하고 최신 내용으로 재확인 요청 |
| 완료·취소 경합 | 서버에 먼저 반영된 상태 기준 |
| 취소 먼저 반영 후 결과 도착 | 진단 이력 보존, 현재 판정·후속 자동 생성에 적용하지 않음 |
| 완료 후 취소 | 이미 완료됨을 반환. 결과 삭제·취소 상태로 되돌리기 없음 |
| 기준 변경 후 과거 결과 도착 | 당시 기준 이력으로 보존, 현재 판정 덮어쓰기 없음 |
| Core 결과 저장 응답 유실 | 동일 Job 결과 중복 등록 없이 저장 여부 확인 |
| 임시 이미지 정리 | 검증 결과·사용 기준·설정·오류 이력 유지 |

먼저 반영됐다는 기준은 클라이언트 시각이 아니라 서버의 원자적인 상태 반영 순서다. 이미 취소 요청을 반영해 cancelling인 작업은 뒤늦은 정상 응답으로 completed로 바꾸지 않는다. 늦은 결과 보존이 영구 원본 이미지 복제를 의미하지 않으며 민감한 Provider 원문을 무조건 저장하는 것도 아니다.

## 남은 구현 계약

접수 키 조회 API·키 수명·주체 범위·요청 내용 비교, 상태 revision과 원자적 갱신, Core 저장 확인 절차·진단 보관 범위는 문서 초안에서 구체화한다. 이번에는 코드·테스트를 추가하지 않는다.

## 충돌 및 대체 확인

ADR-0001~0019와 대조했다. 고정 시도 입력·취소 중 표시·중복 접수·과거 판정 보존·오류 후 자동 실행 금지를 구체화한다. Accepted 결정을 대체하지 않으며 ADR-0019의 관련 제안만 이번에 확정한다. 나머지 API·저장 기술·운영 수치 및 ADR-0005는 Proposed로 유지한다.
