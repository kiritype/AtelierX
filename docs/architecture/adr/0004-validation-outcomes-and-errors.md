# ADR-0004: Validation 판정과 실행 오류·재생성 경계

> 2026-09-23: [ADR-0025](0025-validation-check-scope.md)로 일부 변경되었다. 해당 부분은 그 ADR을 따른다.

- 상태: Accepted
- 작성일 / 확정일: 2026-09-12
- Supersedes: 없음. ADR-0003에서 미정으로 남긴 Validation 판정과 실행 오류 경계를 구체화한다.
- Superseded by: 없음
- 관련: [ADR-0003](0003-generation-execution-and-queue.md), [기능 대조표](../../requirements/module-feature-comparison.md)

## 결정할 질문

이미지와 생성 Prompt를 기준으로 검증할 때 불합격과 검증 실행 오류를 구분하고, 실행 오류로 자동 이미지 재생성이 반복되지 않도록 처리 경계를 정한다. Validation 전체 기능이나 상세 API를 일괄 확정하는 ADR은 아니다.

## 배경과 제약

Core는 자세·구도에 맞춰 Prompt를 정리하고 Generation은 그 입력으로 이미지를 생성한다. 동일 캐릭터도 구도에 따라 Prompt가 달라진다. 예를 들어 upper body에서는 하의·footwear를 Prompt에 포함하지 않는다. 검증은 해당 생성 시도에 실제 사용한 Prompt를 기준으로 해야 하며 편집 중인 최신 Prompt와 혼동하지 않는다.

ADR-0003에 따라 Core가 전체 흐름·이력·재생성 상한을 관리하고 Validation은 재생성 여부와 시도별 변경값을 반환한다. Provider 장애처럼 이미지 재생성으로 해결되지 않는 오류까지 재생성을 요구하면 상한에 도달할 때까지 불필요한 생성이 반복될 수 있다.

## 결정

### 입력과 이미지 판정

- Validation Backend는 이미지와 생성에 사용된 Prompt를 파라미터로 받아 Local VLM 또는 외부 AI API의 Vision 기능으로 검증한다. 구체 Provider·모델·입력 전송 Schema는 미정이다.
- 이미지에 있어야 한다고 Prompt에 명시된 요소가 보이지 않으면 불합격이다. 가림·구도로 보이지 않는 경우에도 이 기준을 적용한다.
- 명시된 요소와 이미지가 상이하면 불합격이다.
- Core가 구도에 맞춰 Prompt에서 제외한 요소를 누락으로 판정하지 않는다. upper body Prompt에 없는 하의·footwear는 해당 일치 검사의 대상이 아니다.
- Prompt 없는 이미지에 대한 Prompt 일치 검증은 제공 범위에 포함하지 않는다. 별도 Deterministic 검사 범위는 이번에 확정하지 않는다.

### 검증 결과와 실행 오류 분리

| 구분 | 의미 | 응답 및 후속 흐름 |
| --- | --- | --- |
| 합격 | 검증을 수행했고 요구를 충족 | 검증 결과 반환 |
| 불합격 | 검증을 수행했고 명시 요소 누락·불일치를 확인 | 재생성 여부·시도별 변경값 반환. Core가 자동 재생성 설정·상한을 적용 |
| 실행 오류 | Provider 오류·응답 파싱 실패 등으로 검증을 수행하지 못함 | Validation이 에러코드를 반환. 이미지 불합격이나 자동 이미지 재생성 요구로 취급하지 않음 |

위 구분은 의미상의 계약이다. 실제 필드명, enum, HTTP 상태, 응답 구조는 미정이다. 오류 응답에서 재생성 여부를 어떤 형태로 표현할지는 후속 Schema에서 정하되, 소비자가 오류를 자동 이미지 재생성으로 연결해서는 안 된다.

### 오류 이후 사용자 동작과 서비스 책임

- 검증 실행 오류는 자동 이미지 재생성을 유발하지 않는다. Critical 오류가 반복되어도 오류 응답 때문에 이미지 재생성 루프로 진입하지 않는다.
- CLI·Frontend는 에러코드에 따른 오류 안내와 해당 이미지의 수동 재생성 요청을 지원한다. 사용자가 수동 재생성을 선택할 수 있으며 오류 발생 자체가 수동 요청으로 간주되지는 않는다.
- 전체 작업의 상태·이력과 새 생성 시도 조정은 Core가 담당한다. CLI·Frontend에 자동 복구 업무 규칙을 복제하지 않는다.
- 수동 재생성은 새 생성 시도이며 ADR-0003의 이력 연결 원칙을 유지한다. ADR-0003의 2026-09-13 추가 결정에 따라 수동 재생성은 횟수 제한 없이 허용하고 자동 재생성 횟수에 포함하지 않는다.
- 동일 이미지의 검증 재시도는 이미지 재생성과 별개다. 후속 [ADR-0006](0006-validation-manual-retry.md)(2026-09-13)에서 `outcome=error` 완료 후 자동 검증 재시도는 도입하지 않고 사용자 재검증·수동 재생성을 지원하며 Core가 요청·이력을 관리하도록 확정했다. 재검증은 기존 이미지·생성 Prompt를 사용하고 이미지 재생성 횟수에 포함하지 않는다.

## 검토한 대안과 영향

- 실행 오류도 재생성 요구로 반환: 채택하지 않는다. 기존 재생성 상한만으로 불필요한 생성을 방지할 수 없다.
- 불합격과 실행 오류를 구분하고 오류에서는 에러코드와 사용자 수동 재생성 경로 제공: 채택한다. Core·Client가 오류를 정상적인 검증 결과와 구별해야 한다.
- Prompt 명시 요소가 보이지 않으면 판정 불가로 처리: 채택하지 않는다. Core가 구도에 맞게 Prompt를 구성한다는 전제에서 불합격으로 판정한다. 모델의 다른 불확실성 표현까지 일괄 결정하지 않는다.

## 이번에 결정하지 않는 사항

에러코드 목록·분류·HTTP 매핑·전체 응답 Schema, 작업 상태명·Batch의 다른 이미지 처리, Generation 실행 오류별 복구, Negative Prompt 해석·Prompt 필드 구조, 구체 검사 항목·판정 정확도·Profile·Provider 설정은 미정이다. 수동 재생성 설정 편집 UX는 후속 논의하며 상한 정책은 ADR-0003의 추가 결정을 따른다. 동일 이미지 검증 재시도 정책은 후속 ADR-0006을 따른다.

## 충돌 및 대체 확인

- ADR-0001의 개발 운영과 ADR-0002의 Node 기능·저장 경계와 충돌하지 않는다.
- ADR-0003은 이미지 불합격과 실행 오류별 복구 정책을 동일시하지 않고 후속 결정을 열어 두었다. 이번 결정은 그 경계를 구체화하며 기존 결정을 폐기하지 않는다. ADR-0003은 Accepted로 유지하고 후속 링크를 추가한다.
- Core 작업 조정·고정 시도 입력·이력·재생성 상한과 Thin Client 원칙을 유지한다. Generation 에러코드별 복구 정책을 이번 Validation 실행 오류 결정으로 대체하지 않는다.
