# ADR-0006: Validation 오류 완료 후 수동 재검증

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: [ADR-0003](0003-generation-execution-and-queue.md), [ADR-0004](0004-validation-outcomes-and-errors.md), [ADR-0005 초안](0005-validation-response-contract.md)

## 결정할 질문

Validation 완료 응답의 `outcome=error` 이후 동일 이미지의 검증 재시도를 어떻게 제공할지 정한다.

## 결정

- 적용 대상은 완료 응답의 `outcome=error`다. 이미지 불합격인 `rejected`와 구분한다.
- 자동 검증 재시도는 현재 도입하지 않는다. 오류 이후 자동 이미지 재생성 금지도 유지한다.
- 사용자는 **다시 검증** 또는 **수동 재생성**을 선택할 수 있다. 오류 발생이나 화면 재접속만으로 어느 동작도 실행하지 않는다.
- 다시 검증은 기존 이미지와 해당 이미지 생성에 사용한 Prompt를 그대로 사용한다. 편집 중인 최신 Prompt로 바꾸지 않는다.
- 다시 검증은 새 이미지를 생성하지 않으므로 이미지 재생성 횟수에 포함하지 않는다.
- Core가 요청과 이력을 관리한다. CLI·Frontend는 사용자 선택을 전달하고 결과를 표시한다.

## 대안과 영향

일시 오류를 자동 재시도하는 대신 사용자가 다시 검증하는 방식을 채택한다. 사용자의 추가 조작이 필요하지만 오류 응답으로 검증 요청이 반복되지 않는다. Provider 설정 등을 수정한 후 이미 생성된 이미지를 다시 검사할 수 있다.

## 이번에 결정하지 않는 사항

응답을 받지 못한 통신 오류·완료 여부 불명확 요청의 처리, 구체 Endpoint·Job 상태·중복 방지, Batch 영향, 재검증 시 Provider·Profile 설정 선택 계약은 미정이다. ADR-0005의 전체 응답 구조·에러코드·HTTP 매핑은 Proposed로 유지한다.

수동 재생성과 생성 상한의 관계는 ADR-0003의 2026-09-13 추가 결정으로 구체화했다. 수동 재생성은 횟수 제한이 없고 자동 상한은 Core 설정으로 지정하며 기본값은 5회다.

[ADR-0015](0015-validation-providers-and-fallback.md)에서 오류 후 Provider를 바꾸어 같은 이미지를 수동 재검증할 수 있도록 확정했다. 자동 Fallback은 사용하지 않는다.

## 충돌 및 대체 확인

ADR-0001·0002와 충돌하지 않는다. ADR-0003의 Core 조정·이력과 ADR-0004의 오류/불합격 분리·자동 이미지 재생성 금지를 유지하며, 미정이던 동일 이미지 검증 재시도 정책만 구체화한다. 기존 Accepted ADR을 대체하지 않는다. ADR-0005에서 본 결정에 해당하는 오류 완료 후 재검증 정책과 `outcome=error` 적용 범위만 확정 기준으로 연결하며 초안 전체를 승인하지 않는다.
