# ADR-0021: 작품·캐릭터·외형·의상 관계와 이미지 그룹

- 상태: Accepted
- 작성일 / 확정일: 2026-09-13
- Supersedes / Superseded by: 없음
- 관련: 요구사항 C-01~C-03, C-17, [ADR-0003](0003-generation-execution-and-queue.md), [ADR-0007](0007-group-image-validation.md), [ADR-0018](0018-group-validation-change-handling.md)

## 현재 확정 구조 — 사용자 추가 정정 2026-09-13

후속 [ADR-0022](0022-prompt-composition.md)에서 실제 조합 순서·전역 Negative 적용·문구 보존·충돌 안내·제출 문구 고정을 확정했다. 아래 조합 미정 표현은 해당 확정 범위를 제외한 상세 계약으로 한정한다. 이 ADR은 Accepted로 유지하며 대체 관계는 없다.

전역 및 의상 내부 구성 추가 확정:

사용자 후속 정정: 독립 액세서리 항목을 제거하고 관련 구성에 장식을 포함한다. 머리핀은 외형, 브로치는 상의, 하의에 부착하는 체인은 하의에 넣는다. 이는 액세서리 묘사 자체를 제외하는 결정이 아니다. 직전 4구분 합의를 현재 3구분으로 부분 대체하며 아래 최초 이력의 별도 액세서리 분류 표현보다 우선한다. ADR은 Accepted로 유지한다.

- category 계층과 별도로 전역 Positive(퀄리티) Prompt와 전역 Negative Prompt를 저장·편집한다.
- 의상 내부 Prompt 구분은 **외형 / 상의 / 하의(풋웨어 포함)**의 세 가지다. 풋웨어는 하의에 포함한다.
- 이 구분은 저장·편집 단위다. 실제 조합 순서, 구도별 포함·제외, 하의 내 풋웨어의 세부 제어 및 여러 영역에 걸치는 의상 표현은 후속 설계한다. 과거 신발 별도 구분 표현은 이 구성으로 구체화한다.


Prompt 편집·DB 저장의 category 계층은 **작품 > 캐릭터 > 의상(외형 포함)** 이다. 외형은 캐릭터 아래에서 별도로 선택·조합하는 단위가 아니라 의상 항목 안에 포함되는 Prompt 구성이다. 의상 항목에서 외형과 복장 묘사를 함께 관리한다. 작품은 생성 Prompt에 들어가지 않으며 category 이름을 생성 문구로 자동 삽입하지 않는다.

이 정정은 아래 최초 결정의 별도 외형 선택과 독립 도메인을 필수로 가정한 표현을 부분 대체한다. 복수 작품 연결·공유 참조를 이 계층에서 구현하는 방식은 이번에 확정하지 않는다. 직전 category 정리안의 참조·이동 등 세부 제안도 일괄 승인된 것이 아니다. Accepted 상태를 유지하고 같은 ADR 내 정정 이력으로 기록한다. 다른 ADR을 Superseded로 바꾸지 않는다.

이미지 그룹은 선택한 의상 항목의 외형·복장 내용을 고정한다. 기존 그룹 추가 시 고정 내용을 사용하고 수정된 내용으로 생성하면 새 그룹을 만드는 원칙, 과거 기록 보존·보관·기준 이미지 교체 원칙은 유지한다. 예를 들어 `작품 A > 유나 > 교복(기본 외형 포함)`과 `작품 A > 유나 > 교복 변형(단발 외형 포함)`으로 표현하며 외형을 별도 category 단계로 추가하지 않는다.

## 최초 결정 및 정정 이력 — 충돌 시 위 현재 확정 구조 우선

아래는 이전 승인 및 검토 이력이다. 별도 외형 선택·독립 관계에 관한 표현은 현재 확정 구조로 대체되었으며 현행 설계 근거로 사용하지 않는다.

## 배경과 결정할 질문

### 사용자 정정 — 2026-09-13

작품 / 캐릭터 / 의상은 Frontend의 Prompt 편집 화면과 DB 저장에서 사용하는 Prompt category다. 작품은 생성 Prompt에 들어가지 않는다. category와 그 이름을 생성 문구로 자동 삽입하거나 category 순서를 Prompt 조합 순서로 해석하지 않는다. 앞서 대화에서 제안한 `전역 → 작품 → 캐릭터·외형 → 의상…` 조합 순서는 철회됐으며 Accepted 결정이 아니다.

아래 독립 데이터·복수 작품 연결·공유 의상 규칙은 최초 승인 이력으로 보존한다. category라는 정정만으로 이 관계의 폐기나 특정 DB 구조가 확정된 것은 아니다. category 관계·항목 재사용으로 어떻게 표현할지 재검토 중이며, 독립 도메인 모델이 필수라는 구현 근거로 사용하지 않는다. 기존 생성 입력 보존·그룹 구성 고정·기준 이미지 교체·보관 원칙은 이번 정정으로 대체하지 않는다. 상태는 Accepted(분류 의미 정정, 관계 표현 재검토)이며 supersede 관계는 없다.

Core가 관리하는 작품·캐릭터·외형·의상의 관계, 재사용과 변경·보관 규칙을 정한다. 같은 캐릭터라도 의도한 외형이 다르면 묶음 일관성 비교에서 구분해야 한다. 아래는 사용자가 권고안을 승인한 결정이며 Backend 구현 개시를 의미하지 않는다.

## 결정

| 항목 | 확정 규칙 |
| --- | --- |
| 작품·캐릭터 | 캐릭터는 독립 데이터로 관리하고 여러 작품에 연결할 수 있다. 작품 미지정 캐릭터도 보관할 수 있다. |
| 캐릭터·외형 | 캐릭터 하나에 여러 외형 구성을 저장하고 생성 시 하나를 선택한다. 각 외형은 독립된 완성본이며 초기에는 상속하지 않는다. |
| 의상 재사용 | 의상은 독립 데이터로 관리하고 여러 캐릭터에 연결할 수 있다. 캐릭터 전용 변형은 복제 후 수정한다. |
| 의상 구성 | 상의·하의·신발·액세서리 등을 구분하고 같은 분류에 여러 요소를 허용한다. 원피스처럼 여러 신체 영역에 걸치는 요소도 표현한다. 초기 구성 요소는 의상 내부에서 관리한다. |
| 공유 데이터 수정 | 수정 내용은 이후 생성에 적용한다. 기존 이미지와 진행 중 작업은 당시 내용을 유지한다. 편집 화면에서 사용 중인 캐릭터·작품을 확인할 수 있게 한다. 기존 그룹에 추가하는 경우는 아래 고정 구성 규칙을 따른다. |
| 보관·삭제 | 기본 정리는 보관 처리로 하고 참조 중인 데이터의 영구 삭제는 제한한다. 작품 보관은 연결된 캐릭터·공용 의상·이미지를 연쇄 삭제하지 않는다. 작품과 캐릭터의 연결 해제는 캐릭터 삭제와 구분한다. |

## 이미지 그룹 구성

작품 / 캐릭터 / 의상 분류 아래에서 각 묶음 검증 그룹은 하나의 외형과 의상 구성을 고정한다. 같은 조합으로도 별도 그룹을 만들 수 있으므로 조합 자체를 그룹의 유일한 식별자로 취급하지 않는다.

- 작품 A / 유나 / 기본 외형 / 교복은 그룹 1, 작품 A / 유나 / 단발 외형 / 교복은 그룹 2로 구분한다.
- 같은 그룹의 자세·구도·표정은 이미지마다 달라질 수 있다. 해당 표현의 Prompt 일치 검사는 기존 단일 검증 규칙을 따른다.
- 기존 그룹에 이미지를 추가할 때는 그룹에 고정된 외형·의상 구성을 사용한다. 원본 데이터가 수정되어도 기존 그룹에 최신 내용을 자동 적용하지 않는다.
- 수정된 외형·의상으로 생성하려면 새 그룹을 만든다.
- 외형·의상 구성의 고정과 검증용 대표·보조 이미지의 교체는 구분한다. 같은 그룹의 기준 이미지 교체·재검증 확인은 ADR-0007·0018을 그대로 따른다.

## 검토한 대안과 영향

작품마다 캐릭터를 복제하는 방식보다 독립 캐릭터의 연결을 채택해 재사용 시 중복 관리를 줄인다. 의상도 공유하되 전용 변형은 복제하므로 공유 원본 수정의 영향을 구분할 수 있다. 외형 상속과 의상 구성 요소의 독립 공용 라이브러리는 초기 구조에 도입하지 않는다. 독립된 완성본은 중복 편집이 생길 수 있지만 적용 내용을 명확히 한다.

외형이 다른 이미지를 한 그룹으로 비교하면 의도한 변형을 불일치로 처리할 수 있다. 그룹별 구성을 고정해 이를 방지하며, 이후 데이터 수정과 과거 생성 근거를 분리한다. Core가 관계·참조·고정 내용을 관리하고 Frontend·CLI는 Core API를 통해 조작한다.

## 이번에 결정하지 않는 사항

구체 필드·ID·DB 구조·API, 외형 속성 분류, 의상 분류 목록과 중첩 충돌 처리, Prompt 포함·조합·우선순위, 버전 저장 방식, 보관 데이터의 상세 선택·복원 동작과 영구 삭제 절차는 후속 설계한다. 작품 미지정 캐릭터의 생성 그룹 표현도 상세 계약에서 다룬다. 이번 결정은 미정 절차나 UI 구현을 승인하지 않는다.

## 충돌 및 대체 확인

Core 소유 원칙 및 ADR-0003의 실행 입력 고정, ADR-0007의 외형·의상 일관성 비교, ADR-0010의 생성 대상 고정, ADR-0011의 Core Context 준비, ADR-0018·0020의 기준 변경·과거 결과 보존과 대조했다. 기존의 작품·캐릭터·의상 그룹 표현에 외형 선택과 구성 고정의 의미를 구체화하며 기존 Accepted 결정을 대체하지 않는다. 기준 이미지 교체는 계속 허용되고 자동 재검증·재생성을 새로 도입하지 않는다. 기존 ADR 상태와 supersede 관계는 유지한다.

## 2026-09-22 사용자 확정 정정 — 외형 소유권·액세서리

작품 > 캐릭터 > 의상 계층은 유지하며 캐릭터에 외형을, 의상에 상의·하의·액세서리를 저장한다. 이 결정은 이 문서의 과거 의상 내부 외형 배치에 한해 대체한다. Positive는 전역 퀄리티 + 캐릭터 외형(항상) + 조각에서 선택한 상의/하의/액세서리 + 조각 본문 순서다. 액세서리 포함 기본값은 true다. 전역·캐릭터 Negative 책임은 ADR-0023을 유지한다.

이전 데이터의 외형이 의상마다 다르면 자동으로 한 값을 고르지 않는다. 동일 값의 안전 이전과 명시적 충돌 해소를 구분하며 기존 revision·고정 그룹·Task/계획 스냅샷은 수정하지 않는다. 사용자 승인된 제품 변경이며 상세 API/호환성은 구현 명세에 기록한다.
