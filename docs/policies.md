# 현행 정책 — 사용자 확정 결정

AtelierX에서 사용자가 확정한 작업 방식·제품 결정의 현재 유효본이다. 날짜별 원문 지시는 로컬 전용 `docs/history/agents-log.md`에 보존하며(Git 제외), 뒤의 결정이 앞의 결정을 대체한 경우 여기에는 최신 결정만 남긴다. 아키텍처 결정은 [ADR](architecture/adr/README.md)과 [overview](architecture/overview.md), 기능 범위는 [scope](requirements/scope.md), 후속 과제는 [roadmap](requirements/roadmap.md)이 기준이다.

## 1. 작업 진행 방식

- **사용 형태:** 배포 전까지 사용자 1인의 개인 제작용이다. 다중 사용자 배포·무인 대량 운영 준비를 기능 구현의 선행 조건으로 두지 않는다. 외부 유료 API 테스트는 보류한다.
- **자율 진행 범위:** 확정된 설계의 구현·테스트는 단계별 승인 없이 진행한다. 제품 의도·확정 정책·외부 전송/비용·삭제·자동 실행 경계를 바꾸는 결정, 해소할 수 없는 요구 충돌만 사용자에게 확인한다. PR 생성·원격 병합은 그것을 지시한 작업 범위에서만 자율 진행한다.
- **분담:** 설계가 확정된 구현·테스트는 서브에이전트(Terra)에 위임하고, 주 에이전트는 통합·검토와 GPU 실행 조정을 맡는다. GPU를 쓰는 실행은 주 에이전트가 순차로 조정한다.
- **미확정 사항:** 임의로 결정하지 않는다. 대안·권고는 확정 결정과 구분해 제시한다. 첫 구현의 임시 선택으로 ADR·제품 정책을 확정하지 않는다. 사용자 승인 원칙과 에이전트가 정한 초안·테스트값의 출처를 구분해 기록한다.
- **ADR:** 사용자와 하나씩 논의하고, 사용자가 확정하기 전에는 Accepted로 기록하지 않는다. 확정 즉시 저장소 문서에 반영한다(절차는 AGENTS.md).
- **범위 밖 추가 금지:** 새 실행 환경·의존성·CI·제품 코드 영역은 명시적 지시 없이 추가하지 않는다.
- **완료 보고:** 부분 prototype·저장소 내부 테스트 통과만으로 기능 완료나 사용자 실행 준비 완료로 보고하지 않는다. 자동/모의/실제 실행/미검증을 구분해 기록한다.
- **1인 개발 Git 운영:** 리뷰 기준·브랜치 보호는 최초 릴리즈 이후 검토한다([ADR-0001](architecture/adr/0001-contribution-workflow.md), [CONTRIBUTING](../CONTRIBUTING.md)).

## 2. ComfyUI Custom Node

- 개발·테스트 후 설치된 ComfyUI(`C:\StabilityMatrix\Packages\ComfyUI`)에서 사용자가 직접 실행할 수 있도록 연결하고 예제 Workflow를 제공한다. 실제 Node 등록과 예제 실행을 확인하고, Node 이름·Workflow 위치·실행 방법을 보고한다.
- 기존 설치·모델·사용자 Workflow를 보존한다. 같은 소스 연결(Junction)은 재사용하고 다른 파일·Node를 덮어쓰지 않는다.
- 실행 중인 사용자 작업을 임의로 중단하지 않는다. 재시작이 필요하면 작업 상태를 확인하고 필요 시 사용자와 조율한다. 설치·시작·재시작과 실제 검증 여부를 구분해 기록한다.
- Generation은 REST로 Node를 제어한다. 준비된 Node부터 하나씩 REST 실행을 검증한다.

## 3. 제작 흐름·화면

- **메뉴 분리:** 작업실은 캐릭터 관리와 이미지 생성으로 나눈다. 검토와 갤러리를 분리하되 수동 승인을 강제하지 않는다. 이미지셋은 캐릭터·의상별 검증 통과 결과 조회다.
- **캐릭터·의상:** 외형은 캐릭터의 `appearance_prompt`, 의상은 상의·하의·액세서리·손으로 구성한다. 캐릭터에는 검사용 핵심 특징 목록을 둘 수 있다.
- **출력 파일명:** 생성 결과는 ComfyUI 출력 폴더의 `AtelierX\<작품>\<캐릭터>\<복장>\<조각번호>`로 저장하고, 이름이 겹치면 ` (2)`처럼 번호를 붙인다. Discord 결과는 `AtelierX\discord\<날짜>\`에 저장한다.
- **단일 검증 범위:** 전역 품질 프롬프트와 공통 적용 조각은 검사하지 않고, 캐릭터 외형(또는 핵심 특징)·포함된 의상·이미지별 조각만 검사한다. 이미지로 판단할 수 없거나 구도상 보이지 않는 요소는 판단 불가로 표시하고 불합격으로 세지 않는다([ADR-0025](architecture/adr/0025-validation-check-scope.md)).
- **전역 조각:** 사용자가 관리하는 단일 계층 카테고리를 쓴다. 이미지별 조각의 번호는 사용자가 입력·수정하며, 같은 번호가 있으면 경고 후 확인 시 저장한다(공통 적용 조각은 번호 없음). 조각의 액세서리·손 포함 체크 기본값은 true다([ADR-0026](architecture/adr/0026-fragment-numbers-output-names-hands.md)).
- **생성 화면:** 의상 체크 트리(작품>캐릭터>의상) × 전역 조각 체크 트리(카테고리>조각)와 설정의 3단 구성이며 총 장수·예정 목록을 보여 준다. 트리 계층을 명확히 표시하고 체크박스 크기를 보정한다.
- **Seed:** -1이면 이미지별 무작위, 0 이상이면 지정값이다. 실제 사용값은 Core가 고정·기록한다.
- **업스케일:** 모델 목록에서 선택하고 예상 최종 해상도를 표시한다.
- **제작 계획의 검사:** 생성만 / 단일 검사 / 단일+묶음 검사 중 선택한다. 미검사 결과를 합격으로 취급하지 않는다.
- **공통 적용 프롬프트:** 본문만 이미지 전체에 추가하며 장수를 늘리지 않고 의상 포함 여부를 바꾸지 않는다. 상의/하의/액세서리/손 포함은 이미지별 조각에서만 설정한다. 작품·캐릭터별 기본 공통 적용 프롬프트는 후속 과제다.
- **UI:** 모던한 공통 스타일, 모바일 탐색·입력·상태 유지를 제공한다. 실제 모바일 기기 검증 여부는 구분해 기록한다. 실사용 불편은 건별로 보완한다.
- **진행 상태:** 2026-09-22 사용자 실사용 확인으로 P0 제작 흐름 점검을 종료했다(장기 장애·GPU/VLM 품질 검증 완료는 아님).

## 4. 인증·원격 접속

- 개인용 Frontend는 Cloudflare Access 로그인 후 Core 토큰을 반복 입력하지 않도록 서버의 비공개 연결 설정을 사용한다. 설정 화면은 연결 상태와 저장 토큰 교체를 제공한다.
- Core는 서명된 Access 사용자 인증(JWT)을 검증하고 기존 서비스 Bearer 인증을 유지한다. 토큰 원문은 Frontend 설정 응답·정적 파일·브라우저 저장소·URL·로그에 노출하지 않는다.
- 앱 자체의 Google OAuth는 후속으로 미룬다(Access의 로그인 수단 설정과는 별개).
- 원격 조작은 사용자가 Tailscale+RDP로 로컬 PC에 접속해 수행한다. 서비스 on/off는 localhost 제어판에서만 호출하며 Frontend는 상태 조회만 제공한다.

## 5. Discord 봇

- Discord 봇은 일반 테스트 용도이며 추가 개발은 후순위다. 본체 Backend·Frontend 제작 흐름을 우선한다.
- 요청은 Frontend의 작품·캐릭터·의상 그룹과 독립적이다. 자연어를 로컬 LLM으로 프롬프트화하거나 자연어/Positive Prompt를 그대로 전달해 이미지를 응답한다. Cloudflare Workers를 사용하고 Discord 대기·응답 만료를 처리한다. 상태·실행 조정은 Core가 계속 담당한다.
- 권한: 봇 설치는 앱 소유자만 가능하다. 허용한 서버(비공개 설정의 목록)에서는 채널 제한 없이 모든 멤버가 사용한다. 다른 서버와 DM은 차단한다.
- 결과: `/draw` 결과는 해당 채널에 공개하고 이미지 스포일러를 기본 적용한다. `/status`는 요청자 전용이며 타인의 상태·결과 조회를 허용하지 않는다.
