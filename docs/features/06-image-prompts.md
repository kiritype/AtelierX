# 이미지 프롬프트

## 목적

캐릭터 본문의 외모·의상(글)을 이미지 생성용 프롬프트(태그)로 바꿔 캐릭터 디자인(`design.json`)에 저장한다. 본문에 정해진 섹션이
없어도 된다(#150). 처음에는 본문 전체를 한꺼번에 바꾸고(A), 틀린 부분은 본문에서 범위를 골라 정확히 고친다(E). 태그의 바탕이 된
본문 조각을 남겨, 그 조각이 바뀐 부분만 "본문 바뀜"으로 표시한다. 표정·구도·공통 프롬프트 같은 공용 재료(이미지 라이브러리)를 편집하고, 조합된 최종
프롬프트를 미리 볼 수 있다. 이미지 생성 자체는 이미지 모듈(7단계, 20번대 문서)에서 한다. 형식은
[data-model.md 이미지 데이터](../data-model.md#이미지-데이터).

## 사용 흐름

### 이미지 디자인 탭

1. 캐릭터 항목의 편집 탭에서 안쪽 탭 [이미지 디자인]을 연다([02-editor](02-editor.md)).
2. 처음이면 비어 있고 "외모·의상 변환"을 보여 준다. 이미 있으면 트리거, 외모, 의상 목록, 기본 의상을 보여 준다.
3. 각 부분(외모, 의상 하나하나) 옆에 상태를 표시한다: 최신 / 본문 바뀜 / 직접 편집 / 근거 없음(예전 형식은 연결 끊김도). 부분 아래
   "원문 n개"를 펼치면 바탕이 된 본문 조각과 그 출처(자동·지정)가 보인다.

### 변환 A: 본문 전체

1. [이미지 디자인] 탭의 "외모·의상 변환" 또는 "다시 변환".
2. 작업 `image_prompt`가 인물 본문 전체(로어북은 보통 4,500바이트 이하), 이미 있는 의상 이름 목록, 의상 부위 목록(`compose.json`의
   `slots`), 가이드라인 `image-prompt.md`를 LLM에 보낸다.
3. LLM은 외모와 의상마다 태그와 **근거 문장**(본문을 그대로 옮긴 문장)을 답한다. 고정 프롬프트와 기본 가이드라인에 "이 인물의 현재
   외모·의상만 쓴다. 다른 인물, 과거, 가정은 빼고 근거 문장은 본문을 그대로 옮긴다", "기존 의상과 같은 옷이면 그 이름을 그대로 쓴다"를 넣는다.
4. 앱은 근거 문장 중 본문에 실제로 있는 것만 원문(`by: auto`)으로 남긴다. 새 의상 이름은 본문과 같은 언어로 짓게 한다(#205). 의상은 이름으로 기존 의상과 짝짓고(같은 id), 새 이름만 새 의상이 된다.
   변환 결과에 없는 기존 의상은 그대로 둔다.
5. 결과는 임시 항목으로 들어가고 "검토"에 뜬다.

### 변환 E: 범위 지정

1. 인물 본문 편집기에서 글을 고르고 우클릭(또는 Alt+P) → **이미지 프롬프트로** ▸ **외모** / **의상** ▸ (기존 의상 목록, **새 의상…**) /
   **외모에 범위 추가**. 같은 메뉴에 잘라내기, 복사, 에이전트에 첨부(Ctrl+L)가 있다.
2. 저장하지 않은 본문이면 먼저 저장한다. 고른 글이 저장된 본문에 없으면 거절한다.
3. 고른 글만 LLM에 보내 그 한 부분의 태그로 바꾼다. 원문은 고른 글(`by: pick`)이 된다.
   - **외모에 범위 추가**: 외모의 원문 조각 중 본문에 아직 있는 것과 새로 고른 글을 함께 보내 다시 바꾼다. 고른 글이 기존 조각 안에
     있으면 그 조각을 `pick`으로 바꾸고(새 조각 없음), 기존 조각이 고른 글 안에 있으면 그 조각을 빼고 고른 글을 넣는다(#207). 외모 묘사가 여러 문단에
     흩어진 경우에 쓴다.
   - **새 의상…**: 이름을 물어 새 의상 id(`o01`…, 지운 id는 다시 쓰지 않음)로 만든다.
4. 결과는 임시 항목으로 들어가고 "검토"에는 그 부분만 보인다.

### 검토와 채택

1. 검토 화면은 부분별로 지금 값과 제안 값을 태그 칩으로 비교한다: 더해진 태그(초록), 빠진 태그(빨강), 그대로인 태그.
2. 부분마다 채택 / 건너뛰기를 고르고, 칩을 직접 더하거나 지울 수 있다.
3. 새 의상이면 의상 키(자동 제안 `o01`, `o02` …, 고칠 수 있음)와 이름(소제목 그대로)을 확인한다.
4. 부분마다 원문(근거 문장·고른 범위)을 펼쳐 보고, 의상에는 기존 의상과의 짝(갱신 / 새 의상)이 보인다.
5. A 변환에서 직접 편집한 부분과 범위 지정(E) 원문이 있는 부분은 "변환 결과 적용"이 기본으로 꺼져 기존 값을 유지한다. 켜면 바꾼다.
   E 변환은 고른 부분을 바꾼다.
6. "채택"을 누르면 `design.json`에 쓴다. 각 부분의 `source`에 원문 조각이 남는다. 쓰기 직전에 `before_llm` 스냅샷을 만든다.

### 직접 편집

- [이미지 디자인] 탭에서 태그를 칩으로 직접 더하고 지운다. 직접 고친 부분은 원문이 지워져 상태가 "직접 편집"이 되고, 본문 전체를
  다시 변환해도 검토에서 기본으로 유지된다.
- 의상의 부위는 "바로 적기"(태그) 또는 "공용 의상 부위 참조"(작품·전역 라이브러리의 `outfits.json`에서 고르기) 중 하나다.
- 트리거 단어: 기본 제안 `<작품 ID>_<캐릭터 ID>`(소문자). 고칠 수 있다.
- 기본 의상을 고른다.

### 태그 사전

- 앱에 Danbooru 태그 목록이 기본으로 들어 있다(`app/defaults/tags/danbooru.csv`, 처음 실행 때 `data/tags/`로 복사). 위치와 양식은
  배포본의 [태그 사전 안내](../../defaults/tags/README.md)에 적어 사용자에게 알린다.
- 다른 사전을 더 쓰려면 같은 양식의 CSV를 `data/tags/`에 넣거나, 설정 → 이미지 → 태그 사전에서 가져온다. `data/tags/`의 CSV는
  모두 읽는다. 사전을 모두 지워도 다른 기능은 동작하고, 아래 도움만 꺼진다.
- **자동 완성**: 태그 칩 입력란에서 글자를 치면 사전의 태그를 사용 수 순으로 제안한다. 별칭으로 쳐도 대표 태그를 제안한다.
  분류(일반, 캐릭터, 작품, 작가, 메타)를 색으로 구분한다.
- **표시**: 칩마다 사전에 있는지 확인해 알 수 없는 태그(정보), 별칭으로 쓴 태그("대표 태그로 바꾸기" 제안)를 표시한다.
  자연어 문장 태그는 검사하지 않는다.
- **변환 결과 검사**: LLM이 만든 태그도 같은 방식으로 표시해, 검토할 때 지어낸 태그를 걸러 내기 쉽게 한다.
- 사전과 비교할 때만 표기를 맞춘다(소문자, 공백 ↔ 밑줄). 저장하는 태그의 표기는 바꾸지 않는다.

### 본문 바뀜

- 원문 조각 하나라도 본문에서 바뀌거나 사라지면 그 부분만 "본문 바뀜"이 된다. 관계없는 문단을 고치거나 줄바꿈·공백만 바뀐 것은 최신이다.
- 다시 맞추려면 그 부분의 글을 골라 범위 지정(E)으로 다시 바꾸거나, 본문 전체를 다시 변환하거나, 직접 고친다.
- 예전 형식(섹션 기준 `source`)의 "연결 끊김"은 섹션·소제목을 찾지 못했다는 뜻이다. 다시 변환하면 새 형식이 된다.

### 조합 미리보기

- [이미지 디자인] 탭 아래 "조합 미리보기": 의상, 표정, 구도, 그림체 프리셋을 고르면 `compose.json`의 조합 순서대로 합친 최종
  프롬프트와 negative를 보여 준다. 각 조각에 출처(캐릭터 / 작품 / 전역)를 표시한다.
- "복사"로 최종 프롬프트를 클립보드에 담는다. 이미지 모듈이 생기기 전에도 다른 이미지 생성 도구에 붙여 넣어 쓸 수 있다.

### 이미지 라이브러리

1. 활동 막대의 이미지 → 사이드 패널: 캐릭터 목록(디자인 상태 요약), 작품 라이브러리, 전역 라이브러리.
2. 라이브러리 종류(표정, 구도, 공통, 공용 의상)를 고르면 편집 영역에 탭으로 항목 표가 열린다. 항목: id, 이름, 태그,
   negative와 종류별 필드(표정의 등급·어울리는 구도 등).
3. 작품 라이브러리에서는 전역 항목도 흐리게 함께 보여 주고, 같은 id로 덮어쓴 항목에는 "작품용으로 바꿈"을 표시한다. 전역 항목을
   "작품용으로 복사"해 고칠 수 있다.
4. 조합 규칙(`compose.json`: 조합 순서, 의상 부위, 표정 등급)은 전역 라이브러리에서만 고친다.
5. 내보내기·가져오기(#154): 종류마다 목록에서 체크한 항목(없으면 전체)을 이 앱 전용 JSON 파일 하나로 내보낸다. 파일에는 종류, 앱 버전,
   항목마다 범위(전역·작품)가 들어간다. 가져오기는 파일을 먼저 읽어 항목마다 새 항목·이미 있음(같은 id)을 보여 주고, 이미 있는 항목은
   바뀌는 필드(이전 → 새 값)를 보여 준다. 넣을 곳(전역·이 작품)을 고르고 항목마다 추가·덮어씀·건너뜀을 고른다(기본: 새 항목은 추가,
   있는 항목은 건너뜀).
   - 이 PC에 없는 사용 대상·의상 부위·등급·구도 참조는 알림으로 보여 주고 값은 그대로 저장한다.
   - 다른 종류의 파일은 "그 목록에서 가져오세요"로, 이 앱 형식이 아니거나 깨진 파일은 거절한다. 읽을 수 없는 항목(잘못된 id 등)은 빼고
     몇 개를 뺐는지 알린다.
   - 고른 것을 모두 확인한 뒤 한 번에 쓴다. 생성 프리셋은 [그림체 프리셋](20-generation.md) 꾸러미로 옮긴다.

### 항목 없는 이미지 데이터

캐릭터 항목을 지울 때 이미지 데이터를 남겼거나, 앱 밖에서 항목 ID를 바꾼 경우 이미지 패널에 "항목 없는 이미지 데이터"로 보인다.
- "캐릭터에 잇기": 캐릭터 항목을 고르면 그 항목의 ID로 이미지 데이터를 옮긴다(ID 바꾸기와 같은 절차).
- "지우기": 휴지통으로.

### 예외 흐름

- **고른 글이 저장된 본문에 없음(E)**: "먼저 인물을 저장하세요"로 거절한다. 편집기 메뉴는 먼저 저장한 뒤 보낸다.
- **근거 문장이 본문에 없음(A)**: 그 문장은 원문으로 남기지 않는다. 하나도 없으면 상태가 "근거 없음"이다.
- **응답 형식이 틀림**: 한 번 다시 요청한다. 그래도 틀리면 원문을 남기고 직접 옮기게 한다.
- **같은 의상 키가 이미 있음**: 채택할 때 새 키를 고르게 한다.

## 화면

### [이미지 디자인] 탭

```text
┌ 한서윤.md ─ [본문] [미리보기] [이미지 디자인 · 오래됨 1] ───────────────────────┐
│ 트리거 [w001_c001]     기본 의상 [o01 평상복 ▾]          [외모·의상 변환]       │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 외모                                                    ● 최신   [다시 변환]     │
│  [1girl] [black hair] [long hair] [straight hair] [brown eyes] [+]              │
│  negative  [+]                                                                   │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 의상 o01 · 평상복                                       ● 오래됨 [다시 변환]     │
│  상의 [white blouse]   하의 [black pencil skirt]   신발 → 작품: loafers         │
│  negative [necklace]                                                             │
│ 의상 o02 · 교복                                         ● 최신   [다시 변환]     │
│  …                                                                               │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 조합 미리보기  의상 [o01 ▾] 표정 [무표정 ▾] 구도 [상반신 정면 ▾] 프리셋 [기본 ▾] │
│  masterpiece, …, w001_c001, 1girl, black hair, …, expressionless, …, white…  [복사] │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 상태

- **비어 있음**: 디자인이 없으면 "본문의 외모·의상을 이미지 프롬프트로 바꿔 보세요"와 "외모·의상 변환". 라이브러리가 비면 "항목 추가".
- **불러오는 중**: 변환 작업이 진행 중이면 해당 부분에 진행 표시.
- **오류**: 디자인 파일을 읽을 수 없으면 오류와 원문 편집 열기.

## 규칙

- LLM에는 그 캐릭터의 본문(A) 또는 고른 글(E), 기존 의상 이름, 의상 부위 목록, 가이드라인만 보낸다. 다른 항목과 메인 프롬프트는
  보내지 않는다. 이 작업은 챗봇 플랫폼과 관계가 없으므로 `platform.md`를 넣지 않는다.
- 결과는 구조화 출력으로 받는다: A는 외모(태그, negative, 근거 문장), 의상별(이름, 부위별 태그, negative, 근거 문장), E는 그 한 부분.
  부위 이름은 `compose.json`의 `slots`에 있는 것만 쓴다.
- 채택 전에는 `design.json`을 바꾸지 않는다.
- 본문 바뀜 판단: 부분의 원문 조각이 지금 본문에 그대로 있는지(공백 정리 후 포함 여부) 본다. 디자인을 읽을 때마다 다시 계산한다.
- 검사에는 외모·의상 섹션이 없다는 알림이 없다(#150). 섹션은 작성 도우미가 권하는 구성일 뿐이다.
- 메모(#157): 줄 맨 앞·쉼표 뒤·공백 뒤의 `#`부터 그 줄 끝까지는 메모다. 저장은 그대로 하고, 조합·생성 요청·생성 기록에서는 뺀다
  (`image/comments.py`, 화면은 `lib/tags.js`의 같은 규칙). 태그 안의 `#`는 태그의 일부이고, `#`로 시작하는 태그는 `\#`로 쓴다.
  태그 사전에서 `#`로 시작하는 태그는 `#compass`, `#unicus_(idolmaster)`, `#b7282e` 정도다.
- 구도·배경(#162): 배경 태그는 구도 조각에 둔다. 표정의 어울리는 구도가 표정마다 배경을 정한다. 구도의 `hide_outfit`이 켜져 있으면
  의상 칸과 의상 negative를 넣지 않고, 조합 결과와 생성 기록에 `outfit_hidden`을 남긴다.
- 태그 정리(저장할 때): 앞뒤 공백 제거, 같은 태그 한 번만. 태그 안의 표기(밑줄·공백, 대소문자)는 바꾸지 않는다. 생성 모델마다
  관례가 달라서다(관례는 가이드라인에 적는다).
- 태그 검사(정보 수준): 외모 안에서 서로 부딪칠 수 있는 태그(머리색 둘 등), 외모와 의상에 같은 태그, 태그 사전에 없는 태그와
  별칭. 확실하지 않으므로 알리기만 한다.

### 기본 이미지 프롬프트 가이드라인 (`image-prompt.md`)

앱이 함께 주는 기본 내용의 줄기. 사용자가 고친다.

- 본문에 있는 특징만 태그로 옮긴다. 없는 것을 지어내지 않는다.
- 외모는 체형·피부·머리·눈 등 바뀌지 않는 특징, 의상은 부위별로 나눈다.
- 의상 하나에 부위가 없으면 비워 둔다.
- 생성 모델 계열별 관례(태그만 / 태그와 짧은 문장)를 여기 적어 두고 따른다.

### 기본 이미지 라이브러리

앱은 전역 라이브러리에 최소한의 기본 항목(표정 몇 가지, 구도 몇 가지, 조합 규칙)을 넣어 준다. 데이터 루트를 처음 만들 때 복사하며,
사용자가 고친다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works/{id}/image/characters/{cid}` · `PUT …` | 캐릭터 디자인 읽기·저장(상태 포함: 최신·오래됨·끊김) |
| `POST /api/works/{id}/image/characters/{cid}/convert` | 변환 → 작업. 본문 전체 `{llm?}`, 범위 `{range: {text, part: appearance·outfit, outfit?, name?, add?}, llm?}` |
| `POST /api/works/{id}/drafts/{did}/apply` | 부분별 채택 `{parts: {...}}` (임시 항목 공통 API) |
| `GET /api/works/{id}/image/compose?character=&outfit=&expression=&composition=&preset=` | 조합 미리보기 |
| `GET /api/image/library/{kind}` · `PUT …` | 전역 라이브러리 |
| `GET /api/works/{id}/image/library/{kind}` · `PUT …` | 작품 라이브러리(전역과 합친 보기 포함) |
| `GET /api/image/library-share/{kind}/export?work=&ids=` | 라이브러리 파일(JSON). `ids`가 없으면 전부 |
| `POST /api/image/library-share/{kind}/preview` | 가져오기 미리보기 `{file, scope, work?}` → `{items: [{id, name, exists, here_scope, changes, unknown, shadowed}], skipped}` |
| `POST /api/image/library-share/{kind}/import` | 가져오기 `{file, scope, work?, choices: {id: add·overwrite·skip}}` → `{written, items}` |
| `GET /api/works/{id}/image/orphans` · `POST …/orphans/{cid}/link` | 항목 없는 이미지 데이터, 캐릭터에 잇기 |
| `GET /api/tags/suggest?q=` · `POST /api/tags/check` | 태그 자동 완성, 태그 목록 검사(있음·별칭·없음) |

## 단계

- **5단계**: [이미지 디자인] 탭, 외모·의상 변환과 부분별 검토·채택, 직접 편집, 오래됨·연결 끊김 처리, 조합 미리보기와 복사, 이미지
  라이브러리 편집(전역·작품), 항목 없는 이미지 데이터, 기본 `image-prompt.md`와 기본 라이브러리, 태그 사전(가져오기, 자동 완성,
  알 수 없는 태그·별칭 표시).
- **이후**: 이미지 모듈(7단계)과 연결(생성 결과 미리보기를 탭 안에).
