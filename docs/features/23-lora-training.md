# LoRA 학습

## 목적

데이터셋으로 캐릭터 LoRA를 학습하고, 에폭 하나를 골라 등록한다. 등록한 LoRA 중 자동 적용인 것은 그 캐릭터를 생성할 때 함께 쓰인다.
학습은 따로 설치하는 학습 도구(anima_lora)가 하고, AtelierX는 설정·실행·기록·등록을 맡는다.
형식은 [data-model.md 이미지 모듈 데이터](../data-model.md#이미지-모듈-데이터).

## 사용 흐름

### 학습 도구 설치와 연결

1. 설정 → 설치 → LoRA 학습 도구 → "설치"([10](10-settings.md), [결정 0019](../decisions/0019-install-page.md)): anima_lora를
   시험한 판으로 `<앱 폴더>/vendor/`에 받고, `uv sync`로 학습 도구 자신의 Python 환경(Python 3.13, CUDA PyTorch, 수 GB)을 만들고,
   모델 경로 패치를 적용한다. 학습 모델은 설정 → 설치 → 모델 → "LoRA 학습용 Anima 기반 모델"로 받는다. 명령줄로는
   `uv run python tools/install_trainer.py --yes`. 앱에는 학습 도구를 넣어 배포하지 않는다.
2. 설정 → 이미지 → LoRA 학습: 학습 도구 폴더(비우면 `<앱 폴더>/vendor/anima_lora`), 그 Python, LoRA 출력 폴더(이미지 생성 서버의
   LoRA 폴더), 학습 모델 파일(공식 Anima 기반: DiT·텍스트 인코더·VAE, 선택으로 생성에 쓰는 Anima 모델). 경로마다 찾았는지 표시한다.

### 학습 시작

1. 이미지 → LoRA → 캐릭터 → "학습" 탭. 준비가 안 됐으면 무엇이 빠졌는지 보여 준다.
2. 데이터셋, 방식(T-LoRA dim 32 / LoRA dim 32·alpha 128), 학습 모델, 에폭(기본 40), 저장 간격(기본 10), 학습률(기본 1e-4).
3. "학습 시작" → 학습 기록 `lora/runs/R001.json`이 생긴다. 한 번에 하나만 학습한다.
4. GPU 대기: 생성 중인 이미지가 끝나면 GPU를 잡고, 이미지 생성 서버의 메모리를 비운다. 학습하는 동안 새 이미지는 생성하지 않고
   대기열에서 기다린다.
5. 데이터셋 내보내기 → 전처리 → 학습. 진행(스텝/전체, 에폭, loss)과 로그를 보여 주고, 멈출 수 있다.
6. 끝나면 저장된 에폭마다 파일이 LoRA 폴더에 `<작품 ID>_<캐릭터 ID>_<R###>-e<에폭>.safetensors`로 복사된다.

### 등록과 자동 적용

1. 학습 기록의 에폭 버튼 "e30 등록" → 그 캐릭터의 `lora/models.json`에 추가된다(이름, 이미지 생성 서버의 파일 이름, 세기, 출처).
   "등록하며 자동 적용"이 켜져 있으면 바로 자동 적용된다. 의상 하나짜리 데이터셋이면 그 의상이 대상으로 들어간다.
2. "쓰는 LoRA" 탭에서 이름·세기·자동 적용·대상(캐릭터 전체 / 이 의상만)·모델 계열·사용 여부를 고치거나 목록에서 뺀다
   (파일은 지우지 않음).
3. 이미지 생성 서버에 있는 다른 LoRA 파일도 이 캐릭터용으로 추가해 같은 방식으로 자동 적용할 수 있다.
4. 생성([20](20-generation.md)) 때: 같은 모델 계열(또는 공용)의 자동 적용 LoRA가 그 캐릭터(또는 그 의상) 이미지에 함께 쓰인다.
   대상·계열마다 자동 적용은 하나뿐이다(새로 켜면 다른 것이 꺼짐). 쓰는 LoRA가 있으면 트리거 단어도 프롬프트에 들어간다.

### 예외 흐름

- **학습 도구 실패**: 학습 기록을 "실패"로 두고 로그 파일 위치를 알린다. 로그는 화면에서 볼 수 있다.
- **멈춤**: 학습 도구와 그 하위 프로세스를 모두 끝내고 "취소됨"으로 둔다.
- **앱이 꺼짐**: 다시 켰을 때 진행 중이던 학습은 "중단됨"으로 표시한다(이어서 하지 않음).

## 데이터

| 파일 | 읽기·쓰기 | 형식 |
|---|---|---|
| `.atelierx/image/characters/<ID>/lora/runs/<R###>.json` | 읽기·쓰기 | [학습 기록](../data-model.md#학습-기록-lorarunsrjson) |
| `.atelierx/image/characters/<ID>/lora/models.json` | 읽기·쓰기 | [쓸 LoRA 목록](../data-model.md#쓸-lora-목록-loramodelsjson) |
| `.atelierx/image/characters/<ID>/datasets/<D###>.json` | 읽기 | [22](22-datasets.md) |
| 출력 루트 `<작품>/<캐릭터>/lora/<R###>/logs/` | 쓰기 | 학습 로그(`train.log`), 진행(`progress.jsonl`) |
| LoRA 출력 폴더 | 쓰기 | 에폭 파일 |
| `config/image/training.json` | 읽기·쓰기 | 학습 도구 폴더·Python, LoRA 출력 폴더, 학습 모델 파일 |
| 학습 도구 `configs/` | 쓰기 | 앱의 방식 파일, `presets.toml`의 앱 표시 구역(학습할 때마다 다시 씀) |

## 규칙

- 학습은 GPU를 혼자 쓴다. 학습 중에는 이미지 생성과 다른 GPU 작업이 기다린다.
- 학습 도구의 설정은 사람이 고치지 않아도 되게 앱이 학습할 때마다 쓴다: 방식 파일 복사, `presets.toml`의 표시된 구역만 바꿈(학습 도구의
  다른 설정은 그대로). 같은 이름의 프리셋이 이미 있으면 멈추고 알린다.
- 데이터셋 내보내기 전에 이미지 해시를 확인한다.
- 학습 기록과 쓰는 LoRA 목록은 스냅샷에 들어간다. 결과 파일은 LoRA 폴더에 있고 참조(이름·해시·크기)만 기록한다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/image/training/status` | 학습 도구·패치·Python·LoRA 폴더·모델 파일을 찾았는지, 고를 수 있는 방식·학습 모델 |
| `GET·PUT /api/image/settings/training` | 학습 설정 |
| `POST /api/works/{id}/image/lora/{cid}/runs` | 학습 시작 `{dataset_id, params: {method, base, epochs, save_every, learning_rate}}` |
| `POST …/runs/{rid}/cancel`, `GET …/runs/{rid}/log` | 멈추기, 로그 끝부분 |
| `POST /api/works/{id}/image/lora/{cid}/models` | 등록 `{run_id, epoch, auto_apply?}` 또는 파일 추가 `{file, name?}` |
| `PUT·DELETE …/models/{mid}` | 고치기, 목록에서 빼기 |
