# 배포 업로드

## 목적

갤러리의 채택 이미지를 배포 대상(Cloudflare R2)에 올리고, 챗봇 플랫폼에서 쓸 URL을 얻는다. 챗봇 작업 흐름의 마지막 단계다.
결정은 [0023](../decisions/0023-deployment-upload.md).

## 사용 흐름

### 준비

1. **설정 → 배포 대상**에서 대상을 추가한다: 이름, 계정 ID, 버킷, 접근 키 ID·비밀 키(금고에 저장), 공개 URL 기준 주소,
   기본 경로 형식.
2. **연결 확인**으로 키와 권한을 확인한다(버킷 목록 1건 조회).
3. 프롬프트 라이브러리에서 표정의 **배포 코드**, 캐릭터 이미지 설계에서 의상의 **배포 코드**를 정한다. 기본 표정은 `001`~`008`을
   갖고 있다.

### 올리기

1. 갤러리에서 범위(작품·캐릭터·의상)를 고르고 **배포 대상에 올리기**를 누른다.
2. 업로드 창: 배포 대상, 경로 형식(기본은 대상의 형식, 작품만의 형식으로 저장 가능), 등급 필터(기본 전체).
3. **미리보기**: 이미지마다 원본, 올릴 경로, 상태를 보여 준다.
   - 상태: 새 파일 / 덮어쓰기 / 변경 없음(건너뜀) / 코드 없음 / 경로 충돌.
   - 경로는 파일마다 직접 고칠 수 있다. 고치면 충돌을 다시 검사한다.
   - 채택 이미지가 없는 필요한 조합은 경고로만 알린다.
   - 코드 없음·경로 충돌인 이미지가 있으면 그것만 빼고 올릴지, 고칠지 고른다.
4. **올리기**: 백그라운드 작업으로 진행률을 보여 주고(작업 패널에도 표시), 취소할 수 있다.
5. **결과**: 파일별 성공·실패. 실패한 파일만 다시 올리기. URL 목록 복사·파일 저장.
   - 덮어쓴 파일이 있으면: "이미지가 바뀌지 않아 보이면 Cloudflare 대시보드에서 해당 URL의 캐시를 지우세요(Caching → Purge Cache →
     Custom Purge)."와 덮어쓴 URL 목록.

### 예외

- 키가 틀림·권한 없음: 연결 확인과 업로드에서 원인을 알리고 멈춘다.
- 접속 실패: 그 파일을 실패로 두고 다음 파일을 계속한다. 끝난 뒤 실패분만 다시 올린다.
- 원격에만 있는 파일은 지우지 않는다(결과 화면에서 "원격 파일은 Cloudflare 대시보드에서 지우세요" 안내).

## 화면

- 설정 → **배포 대상**: 대상 목록과 편집 폼, 연결 확인. 공개 URL이 `r2.dev`면 속도 제한·캐시 지우기 불가 안내.
- 프롬프트 라이브러리 → 표정: **배포 코드** 칸. 같은 코드를 쓰는 표정이 있으면 이름을 알린다.
- 캐릭터 이미지 설계 → 의상: **배포 코드** 칸. 같은 캐릭터 안에서 겹치면 알린다.
- 갤러리 → **배포 대상에 올리기** 버튼, 업로드 창(설정·미리보기·진행·결과).
- 업로드 창 위쪽 안내(막지 않음): 공개 버킷은 URL을 아는 누구나 접근, 경로가 규칙적이라 짐작 가능, 콘텐츠 정책은 사용자가 확인,
  API 토큰은 해당 버킷의 객체 읽기·쓰기 권한만 권장.

## 데이터

- [배포 코드](../data-model.md#배포-코드): 표정 `code`, 의상 `code`.
- [배포 대상](../data-model.md#배포-대상-데이터-루트imagedeployjson): `<데이터 루트>/image/deploy.json`, 작품의 `.atelierx/image/deploy.json`.
- 업로드 결과는 저장하지 않는다. 상태는 올릴 때마다 버킷 목록과 비교한다.

## 규칙

- 올리는 형식: WebP(품질 95) + 메타데이터 지우기. 크기 제한 없음. `Content-Type: image/webp`, `Cache-Control`은 붙이지 않는다.
- 변경 없음: 버킷의 같은 경로 객체의 ETag(MD5)가 변환한 파일의 MD5와 같으면 건너뛴다.
- 경로: 형식의 자리표시를 채운 뒤 `.webp`를 붙인다. 각 조각에 경로에 쓸 수 없는 문자가 있거나 비어 있으면 "코드 없음/잘못된 경로".
- 덮어쓰기는 같은 경로에 그대로 PUT(URL 유지).
- 키는 금고에서 읽고, 요청마다 SigV4 서명. 서명에 쓰는 시각은 이 PC 시계이므로 시계가 크게 틀리면 원인으로 알린다.

## API

| 요청 | 하는 일 |
|---|---|
| `GET/PUT /api/image/deploy/targets` | 배포 대상 목록·저장(키는 금고 참조로) |
| `POST /api/image/deploy/targets/{id}/check` | 연결 확인 |
| `GET/PUT /api/works/{id}/image/deploy` | 작품의 대상·경로 형식 |
| `POST /api/image/deploy/plan` | 범위·대상·형식·경로 수정 → 파일별 경로와 상태 |
| `POST /api/image/deploy/upload` | 계획대로 올리기(백그라운드 작업) |
| `GET /api/image/deploy/runs/{id}` | 진행·결과, URL 목록 |

## 단계

- 처음: R2 하나, 위 흐름 전체.
- 나중(필요하면): 다른 S3 호환 저장소, 작품 꾸러미 백업 업로드.
