# 작성 지원

## 목적

원고를 쓰는 사람을 돕는 도구 다섯 가지를 다룬다.

1. **뼈대 작성**: 챗봇 규모(`single`, `ensemble`, `simulation`)에 맞는 질문에 답하면 LLM이 파일 구성과 초안을 제안한다.
2. **관계도**: 인물 사이의 관계·호칭과 기준 사실(나이, 소속 등)을 그림과 표로 모아 보는 참고 도구. 관계의 원본은 각 캐릭터
   로어북과 메인 프롬프트 본문이며, 관계도는 내보내기·테스트에 들어가지 않는다([결정 0016](../decisions/0016-relation-map.md)).
3. **모순 검사**: 관계도와 본문, 본문끼리 어긋나는 곳을 찾는다.
4. **이름 일괄 변경**: 이름을 작품 전체에서 한 번에 바꾼다.
5. **용어집**: 작품 전체의 표기를 통일한다. 관계도와 별도 메뉴다.

LLM 결과는 모두 임시 항목으로 들어가고 사람이 검토한 뒤에만 반영한다. LLM 호출 방식은 [03-llm](03-llm.md).

## 사용 흐름

### 1. 뼈대 작성

**질문 답하기**

1. 시작하는 곳: 새 작품을 만든 직후의 빈 트리에서 "뼈대 작성", 또는 상단 바 메뉴 → 도구 → "뼈대 작성".
2. 작품 규모(`work.json`의 `scale`)에 맞는 가이드라인 `authoring/<규모>.md`의 **질문 목록**이 양식으로 열린다.
   예(ensemble): "세계와 배경은?", "고정 인물은 몇 명이고 각자 어떤 사람인가?", "사용자는 어떤 입장인가?", "응답 형식·분량은?"
3. 아는 것만 답한다. 비워 둔 질문은 LLM이 무난하게 채우거나 자리표시로 남긴다.
4. "뼈대 만들기" → 작업 `authoring` → 임시 항목.

**검토와 만들기**

1. 검토 탭에 **만들어질 파일 목록**이 트리로 보인다. 파일마다 종류, 경로, 본문 초안을 미리 볼 수 있다.
   - 예: `메인.md`(메인 프롬프트), `시작 상황.md`, `인물/한서윤.md`(캐릭터: 식별·외모·의상 섹션), `세계관/학교.md`, `메모/설정 메모.md`
   - 관계도 초안(인물, 관계, 기준 사실)도 함께 보인다.
2. 파일마다 체크해서 고르고, 경로·이름·본문을 고칠 수 있다.
3. "만들기" → 고른 파일을 만든다. ID는 종류별 다음 번호. 같은 경로에 파일이 있으면 그 파일은 건너뛰고 목록에 남긴다
   (덮어쓰지 않음). 관계도는 기존에 없는 줄만 더한다. 만들기 직전에 `before_llm` 스냅샷을 만든다.

**캐릭터 하나 추가**

- 파일 트리에서 폴더 우클릭 → "캐릭터 뼈대 추가": 캐릭터용 질문 몇 개(이름, 역할, 성격, 외모, 의상, 다른 인물과의 관계)에 답하면
  캐릭터 항목 하나와 관계도 줄을 제안한다. 흐름은 위와 같다.

### 2. 관계도

1. 활동 막대의 관계도(🔗) → 편집 영역에 관계도 탭이 열린다. 위쪽 전환으로 **그림**과 **표**를 오간다(처음은 그림).
2. **그림**: 인물이 노드, 관계가 방향 있는 화살표다. 화살표 위에 관계와 호칭을 적는다. 서로 다른 두 방향 관계는 서로 반대쪽으로
   휘어 겹치지 않는다.
   - `{{user}}`(사용자)는 늘 있고 다른 색으로 보인다. 로어북 없는 인물은 점선 테두리.
   - 노드를 끌어 옮기면 위치를 저장한다(`layout`). 옮긴 적 없는 인물은 원형으로 자동 배치한다.
   - 노드를 누르면 그 인물의 관계만 진하게 보이고, 옆에 기준 사실·관계 목록과 "로어북 열기"가 나온다.
3. **표**: 세 부분으로 나뉜다. 인물을 고르면 그 인물이 나오는 관계·사실만 걸러 볼 수 있다.
   - **인물**: `{{user}}`와 캐릭터 항목은 자동으로 들어온다(이름은 파일 이름, 고칠 수 없음). `single` 작품이면 `{{char}}` 표시가
     그 캐릭터 옆에 붙는다. 로어북이 없는 인물(`N01` …)은 직접 더한다.
   - **관계**: 한 줄에 한 방향(누가 → 누구에게): 관계, 호칭, 메모.
   - **기준 사실**: 인물별 항목과 값(나이 17, 학년 2, 소속 3반 …).
4. 고치면 잠시 뒤 자동으로 저장한다.
5. "본문에서 찾기": LLM이 캐릭터 본문들을 읽고 관계·호칭·사실 후보를 뽑는다(작업 `consistency` 모델). 검토 화면에서 줄마다
   더하기 / 건너뛰기를 고른다. 이미 있는 줄과 값이 다르면 "다름"으로 표시한다.

### 3. 모순 검사

1. 상단 바 메뉴 → 도구 → "모순 검사", 또는 관계도 탭의 "모순 검사". 범위를 고른다: 작품 전체 / 고른 항목들 / 지금 파일.
2. 먼저 **규칙 기반 검사**를 바로 돌린다(LLM 없음, 아래 표). 결과는 보조 패널 "검사"에 나온다.
3. "LLM 검사"를 누르면 작업 `consistency`가 돈다. 인물별로 나눠서(그 캐릭터 본문 + 그 인물이 나오는 관계·사실 + 본문에서
   이름이 나오는 다른 항목) 보낸다.
4. 결과(임시 항목)는 문제 목록이다: 종류(어긋남 / 빠짐 / 모호함), 관련 항목, 근거 인용, 설명, 고칠 제안.
5. 문제마다:
   - 누르면 해당 항목의 그 위치로 간다.
   - "제안 적용": 제안한 바꿈 글을 보여 주고 확인을 받아 본문에 반영한다(`before_llm` 스냅샷).
   - "해결됨", "무시"(이유 메모). 무시한 문제는 다음 검사에서 같은 근거로 다시 나와도 접어서 보여 준다.

규칙 기반 검사:

| 검사 | 수준 | 내용 |
|---|---|---|
| 없는 인물 | 오류 | 관계·사실이 가리키는 ID가 캐릭터 항목에도 관계도 인물에도 없음 |
| 이름 없음 | 경고 | 캐릭터 본문에 자기 이름(파일 이름)이 한 번도 나오지 않음 |
| 호칭 불일치 | 정보 | 관계도의 호칭이 그 두 인물이 함께 나오는 본문에서 쓰이지 않음 |
| 용어집 위반 | 경고 | 용어집에 적힌 피할 표기가 본문에 있음 |
| 사실 값 불일치 | 정보 | 기준 사실의 값과 다른 같은 종류 값이 그 인물 본문에 있음(숫자+단위처럼 알아보기 쉬운 경우만) |

### 4. 이름 일괄 변경

1. 상단 바 메뉴 → 편집 → "이름 일괄 변경", 또는 캐릭터 항목 우클릭 → "이름 바꾸기(작품 전체)".
2. 바꿀 글과 새 글을 입력한다(예: 서윤 → 서연). 대상: 본문, 키워드, 관계도 호칭, 파일 이름(그 이름이 파일 이름이면).
3. 미리보기에 찾은 곳을 모두 보여 준다. 뒤에 붙은 말(조사 등)은 그대로 두고 앞부분만 바꾼다(서윤이 → 서연이, 서윤아 → 서연아).
   받침 유무가 바뀌어 조사가 어색해지는 곳(예: 서윤 → 서아일 때 "서윤은" → "서아은", "서윤아" → "서아아")은 따로 표시한다.
   조사는 앱이 고치지 않는다(문맥에 따라 틀리기 쉬움). 표시된 곳은 사람이 보고 고친다.
4. 곳마다 체크를 풀어 뺄 수 있다. "바꾸기" → `before_bulk` 스냅샷 → 한꺼번에 바꾼다.

### 5. 용어집

1. 활동 막대의 용어집 → 편집 영역에 용어집 탭이 열린다. 줄마다: 쓸 표기, 피할 표기들(입력 후 Enter로 하나씩), 설명.
   고치면 잠시 뒤 자동으로 저장한다.
   예: 쓸 표기 "청원고", 피할 표기 "청원고등학교", "청원 고교".
2. 규칙 기반 검사가 피할 표기를 찾아 알린다. "쓸 표기로 바꾸기"는 이름 일괄 변경 흐름을 쓴다.
3. 용어집과 관계도의 이름은 압축의 누락 검사([05](05-compression.md))에도 쓰인다.

### 예외 흐름

- **규모가 정해지지 않음**: 뼈대 작성 전에 규모를 고르게 한다.
- **가이드라인에 질문 목록이 없음**: 질문 없이 자유 입력란 하나("어떤 챗봇을 만들고 싶은가요?")로 진행한다.
- **LLM 응답 형식이 틀림**: 한 번 다시 요청한다. 그래도 틀리면 원문을 남기고 직접 옮기게 한다.
- **모순 검사 범위가 모델 맥락보다 큼**: 인물별로 더 잘게 나눠 여러 번 보낸다. 그래도 크면 그 인물을 건너뛰고 알린다.

## 화면

### 뼈대 검토 탭

```text
┌ 검토: 뼈대 작성 (ensemble) ─────────────────────────────────── [만들기] ┐
│ ☑ 메인.md                    메인 프롬프트   │ # 청원고 이야기          │
│ ☑ 시작 상황.md               시작 상황       │ 사용자는 2학년 3반에 …   │
│ ☑ 인물/한서윤.md             캐릭터  C001    │ ## 식별                  │
│ ☑ 인물/김도현.md             캐릭터  C002    │ …                        │
│ ☐ 세계관/동아리.md           로어북          │                          │
│ ☑ 관계도 (관계 3, 사실 5)                    │                          │
└──────────────────────────────────────────────┴──────────────────────────┘
```

### 관계도 탭

```text
┌ 관계도 ─ [그림 | 표] ──────────────────────────────── [본문에서 찾기] [모순 검사] ┐
│                 ({{user}})                                ┌ 한서윤 C001 ────────┐ │
│            "전학생" ↑      ↖ "전학생"                       │ 나이 · 17          │ │
│   (한서윤 C001) ──친구 · "도현아"──▶ (김도현 C002)          │ → 김도현: 친구     │ │
│                ◀──친구 · "반장"───                          │ [로어북 열기]      │ │
│   ┊담임 선생님 N01┊                                         └────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 용어집 탭

```text
┌ 용어집 ───────────────────────────────────────────────────────────────┐
│ 쓸 표기    피할 표기                          설명                     │
│ 청원고     [청원고등학교 ×] [청원 고교 ×]      학교 이름은 줄여 쓴다    │
│ [용어 추가]                                                            │
└────────────────────────────────────────────────────────────────────────┘
```

### 상태

- **비어 있음**: 관계도에 관계가 없으면 "캐릭터를 만들면 인물이 자동으로 들어와요"와 "본문에서 찾기". 용어집이 비면 "용어가 없습니다". 모순 검사 결과가 없으면 "찾은 문제가 없어요".
- **불러오는 중**: LLM 작업 중에는 검토 탭 대신 진행 표시와 "취소".
- **오류**: 형식이 틀린 응답은 원문을 보여 준다.

## 규칙

### 뼈대 작성 가이드라인 (`authoring/<규모>.md`)

- 일반 Markdown이다. `## 질문` 제목 아래의 목록(`- `) 한 줄이 질문 하나다. 앱은 이 목록만 읽어 양식을 만든다.
- 나머지 내용(파일 구성 원칙, 섹션 구성, 분량, 문체 등)은 LLM 지침으로 함께 보낸다.
- 앱은 세 규모의 기본 가이드라인을 함께 준다. 권장 폴더 구성은 샘플 작품과 같게 맞춘다.

### LLM에 보내는 것

| 작업 | 보내는 것 |
|---|---|
| 뼈대 작성 | 답, 가이드라인(`platform.md`, `authoring/<규모>.md`), 작품 언어, 섹션 이름, 이미 있는 파일 목록(이름·종류만) |
| 본문에서 관계 찾기 | 캐릭터 본문들, 지금 관계도 |
| 모순 검사 | 인물별 묶음(위 흐름 3번), 관계도의 해당 줄, 용어집, 가이드라인 `consistency.md` |

- 결과는 구조화 출력으로 받는다. 뼈대: 파일 목록(경로, 종류, 본문, 키워드)과 관계도 초안. 모순 검사: 문제 목록(종류, 항목 ID,
  인용, 설명, 제안).
- 근거 인용은 본문에 실제로 있는 글이어야 한다. 앱이 확인하고, 찾을 수 없는 인용은 "근거 확인 안 됨"으로 표시한다.

### 반영

- 모든 반영(파일 만들기, 관계도 줄 더하기, 제안 적용, 일괄 변경)은 사람이 누를 때만 하고, 직전에 스냅샷을 만든다.
- 뼈대 작성과 관계 찾기는 이미 있는 파일·줄을 덮어쓰지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works/{id}/authoring/questions?scale=` | 질문 목록(가이드라인에서 읽음) |
| `POST /api/works/{id}/authoring` | 뼈대 만들기 `{answers, scope: "work" | "character", folder?}` → 작업 |
| `POST /api/works/{id}/drafts/{did}/create-files` | 고른 파일·관계 줄 만들기 |
| `GET /api/works/{id}/relations` · `PUT …` | 관계도(읽을 때 `view`에 화면용 인물 목록을 붙임) |
| `POST /api/works/{id}/relations/extract` | 본문에서 관계 찾기 → 작업 |
| `GET /api/works/{id}/glossary` · `PUT …` | 용어집 |
| `GET /api/works/{id}/consistency/rules` | 규칙 기반 검사 결과 |
| `POST /api/works/{id}/consistency` | LLM 검사 `{scope}` → 작업 |
| `POST /api/works/{id}/drafts/{did}/issues/{n}` | 문제 처리 `{action: "apply" | "resolve" | "ignore", note?}` |

## 단계

- **0단계(골격)**: 관계도 그림·표 편집과 노드 위치 저장, 용어집 편집, 규칙 기반 검사(없는 인물, 용어집 위반).
  뼈대 작성: 파일 트리 머리글의 뼈대 작성 버튼 또는 빈 트리의 "뼈대 작성" → 규모별 질문 양식(가이드라인 `## 질문`, 작품 → 연결된 프리셋 → 전역
  순으로 찾음) → 모의 초안(답에서 인물 이름을 추측해 파일 목록 구성) → 검토 탭에서 고르고 경로·본문 고치기 → 만들기(있는 파일은
  건너뜀, 관계도 줄은 없는 것만 더함, 직전 `before_llm` 스냅샷).
- **3단계(구현)**: 관계도 "본문에서 찾기"(새로움·같음·다름 표시, 기본으로는 새로움만 체크, 다름을 고르면 기존 줄을 바꿈),
  LLM 모순 검사(인물별 묶음, 근거 인용 확인 — 지정 항목에 없으면 작품 전체에서 찾음, 제안 적용·해결됨·무시, 무시한 문제는 다음 검사에서
  접힘). 실제 품질은 모델과 `consistency.md`에 크게 좌우된다.
- **이름 일괄 변경(구현)**: 본문·키워드·관계도 호칭과 이름·파일 이름(이름 전체가 같을 때) 미리보기, 곳마다 체크 해제,
  받침이 바뀌어 조사가 어색해질 곳 표시(`조사 확인`), `before_bulk` 스냅샷 뒤 한꺼번에 바꾸기.
- **6단계**: 뼈대 작성(작품·캐릭터), 관계도 본문에서 찾기, 규칙 기반·LLM 모순 검사와 문제 처리, 이름 일괄 변경, 용어집,
  기본 `authoring/<규모>.md`·`consistency.md`.
- **이후**: 뼈대 작성을 대화형(LLM이 되묻기)으로.
