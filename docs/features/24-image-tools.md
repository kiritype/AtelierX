# 이미지 도구

## 목적

만든 이미지나 밖에서 가져온 이미지를 한곳에 모아 살펴보고 고친다. 생성 정보 읽기, WebP 변환, 태깅, 업스케일·디테일러,
검열, 배경 제거, 인페인트, 프롬프트 형식 변환을 한 화면에서 한다. 원본은 바꾸지 않고 결과를 새 파일로 남긴다.

## 사용 흐름

### 목록

1. 이미지 → 이미지 도구. 왼쪽이 도구 목록, 가운데가 고른 이미지, 오른쪽이 도구 탭이다.
2. 이미지를 넣는 방법: "파일·ZIP 올리기"(PNG·WebP·JPEG, ZIP이면 안의 이미지 전부), 끌어 놓기, 갤러리에서 고른 뒤 "이미지 도구로
   보내기". 올린 파일은 앱 데이터에 복사되고, 갤러리 이미지는 복사하지 않고 경로로만 가리킨다.
3. 체크한 이미지가 일괄 작업 대상이고, 누른 이미지가 가운데에 보인다. "목록에서 빼기"는 올린 사본만 지우고 갤러리 이미지는 남긴다.
   "ZIP 받기"로 고른 이미지를 묶어 받는다.

### 생성 정보

- 가운데에 이미지와 크기·형식·용량, 그리고 이미지가 말하는 생성 정보를 보여 준다. 읽는 순서: 이 앱의 기록(PNG 청크·옆의 JSON), A1111/Forge
  `parameters`, ComfyUI 워크플로(PNG 또는 WebP EXIF). 워크플로는 읽기만 하고 실행하지 않는다.
- 프롬프트·설정·쓴 모델·투명 여부·텍스트 항목·EXIF. 프롬프트는 눌러 복사하고, "생성·비교에서 열기", "프롬프트 형식 변환"으로 넘긴다.
- 후처리 결과는 원본과 나란히 또는 겹쳐 밀며 비교한다.

### WebP 변환

- 품질(1~100, 기본 95)·무손실·긴 변 크기·파일 이름 꼬리말. 메타데이터 유지를 켜면 ComfyUI의 WebP 방식(EXIF)으로 프롬프트·워크플로를
  남기고, 끄면(기본) 지운 배포용 파일이 된다. CPU에서 처리하고 결과는 `<출력 루트>/_tools/<날짜>/`에 저장한다. 결과는 ZIP으로도 받는다.

### 태깅

- WD14 태거(이미지 생성 서버의 노드)로 태그를 읽는다. 모델·일반/캐릭터 기준값을 고른다. 생성 대기열을 함께 쓴다.
- 결과는 프롬프트와 비교해 "프롬프트와 일치", "그림에서만 보임", "그림에서 안 보임"으로 나눠 보여 준다(품질어·작가·문장은 비교에서 뺌).
- 제외 태그(워터마크 등)는 화면과 내보내기에서 뺀다. 내보내기: 이미지마다 TXT 캡션을 담은 ZIP, 또는 JSON 하나.

### 후처리

- **업스케일**: 업스케일 모델과 최종 배율. 투명은 사라지므로 배경 제거는 업스케일 뒤에 한다.
- **디테일러**: 얼굴 → 눈 → 입 → 손 순서로 감지해 다시 그린다. 이 앱의 기록이 있는 이미지만 되고, 그 이미지의 모델·LoRA·프롬프트를 쓴다.

### 검열

1. (선택) 부위 감지: 가릴 부위와 기준값을 골라 고른 이미지들의 마스크를 만든다.
2. 마스크 고치기: 브러시·지우개로 칠한다(크기, 되돌리기, 확대·이동, 배경 바꾸기). 빨간 곳이 가려진다.
3. 적용: 모자이크·흐림·단색(색·불투명도), 마스크 넓히기·가장자리 부드럽게. 이 이미지, 또는 마스크가 있는 고른 이미지 전부.

### 배경 제거

1. (선택) 배경 나누기: isnet-anime(애니 일러스트) 또는 사람 분할. 남길 곳이 마스크로 돌아온다.
2. 마스크 고치기: 파란 곳이 남는다. 결과 미리보기로 투명하게 된 모습을 본다.
3. 적용: 남길 곳 밖이 투명한 PNG를 새로 저장한다.

### 인페인트

1. 다시 그릴 곳을 초록으로 칠한다.
2. 프롬프트: 이미지 기록의 프롬프트에서 시작해 바꿀 부분만 고친다.
3. 다시 그리기: 범위(마스크 주변을 잘라 생성 크기로 키워 그리기 — 권장, 또는 전체), 주변 여유, 디노이즈, 스텝, 마스크 넓히기·부드럽게.
   칠한 곳 밖의 픽셀은 그대로 둔다. 이 앱의 기록이 있는 이미지만 된다.

### 프롬프트 형식 변환

- NovelAI(V4.5)·Anima·SDXL(Illustrious, ComfyUI) 사이에서 가중치 표기와 작가 표기만 바꾼다. 자연어, 태그 순서, 모르는 이름은
  그대로 둔다. SDXL 프롬프트는 작가 이름에 표시가 없으므로, 알려진 작가 이름 목록에 적은 이름만 작가로 바꾼다.
- 바뀐 곳과 확인할 곳(가중치 느낌이 다를 수 있음, 바꿀 수 없는 문법, 괄호가 맞지 않음 등)을 목록으로 보여 준다.
- 결과를 복사하거나 생성·비교로 보낸다(NovelAI 형식은 이 앱에서 생성하지 않으므로 보내지 않는다).

### 결과가 저장되는 곳

- 작품 이미지(작품/캐릭터/images/의상/표정)의 결과는 원본 옆에 `<번호>_<작업>.png`로, 원본의 생성 기록에 후처리 정보를 더해 저장한다.
  그래서 갤러리에서 통과시키면 그 조합의 채택 이미지가 된다.
- 그 밖의 결과는 `<출력 루트>/_tools/<날짜>/`에 저장한다. 결과는 도구 목록에도 추가되어 이어서 처리할 수 있다.

## 데이터

| 파일 | 읽기·쓰기 | 내용 |
|---|---|---|
| `data/image/tools/tools.json` | 읽기·쓰기 | 도구 목록(출처, 이름, 크기, 태그 결과, 마스크 상태, 원본 관계) |
| `data/image/tools/uploads/` | 읽기·쓰기 | 올린 이미지 사본 |
| `data/image/tools/masks/` | 읽기·쓰기 | 이미지별 마스크(검열·배경·인페인트), 인페인트 작업용 사본 |
| `config/image/tags.json` | 읽기·쓰기 | 제외 태그 |
| 출력 루트 `_tools/`, 작품 이미지 폴더 | 쓰기 | 결과 이미지와 기록 |

## 규칙

- 원본 파일은 바꾸지 않는다. 모든 결과는 새 파일이다.
- 태깅·감지·배경 나누기·업스케일·디테일러·인페인트는 이미지 생성 서버의 작업이라 생성 대기열과 GPU 규칙을 함께 따른다. 변환·검열 적용·
  배경 적용은 CPU에서 바로 한다.
- 인페인트 작업은 넣을 때의 마스크 사본을 쓴다. 기다리는 동안 마스크를 고쳐도 그 작업은 바뀌지 않는다.
- 필요한 노드와 모델은 설정 → 설치에서 받는다(명령줄로는 `tools/install_comfy_nodes.py`). 노드가 없으면 그 작업을 막고 이유를
  보여 준다.
- 올리기: 파일 하나 100MB, ZIP 안 500개·2GB, 6,400만 화소까지. 움직이는 이미지는 받지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/image/tools/items` | 도구 목록 |
| `POST /api/image/tools/upload` | 파일 하나(본문 그대로, 이름은 `X-File-Name`) |
| `POST /api/image/tools/gallery`, `/remove` | 갤러리 이미지 넣기, 목록에서 빼기 |
| `GET /api/image/tools/analyze?id` | 생성 정보 |
| `GET /api/image/tools/thumbnail`, `/image`, `/zip` | 썸네일, 원본, 고른 이미지 ZIP |
| `GET·PUT /api/image/tools/mask?id&kind` | 마스크(PNG) |
| `POST /api/image/tools/convert`, `GET /convert/task`, `/convert/zip` | WebP 변환 |
| `GET /api/image/tools/tagger`, `POST /tag`, `GET /tags/export` | 태거 정보, 태깅, 태그 내보내기 |
| `GET /api/image/tools/postprocess`, `POST /postprocess` | 후처리 정보, 후처리·감지·배경 나누기·인페인트 작업 |
| `POST /api/image/tools/censor`, `/alpha` | 검열·배경 적용 |
