# 편집기

## 목적

작품 안의 파일을 텍스트 편집기처럼 다룬다. 왼쪽 파일 트리에서 파일·폴더를 만들고 옮기고, 가운데에서 상단 메타데이터 폼과
본문을 편집한다. 편집하는 동안 용량과 규칙 검사 결과를 바로 보여 준다.

## 사용 흐름

### 새 파일

1. 파일 트리에서 폴더를 우클릭(또는 트리 위 "새 파일" 버튼) → "새 파일".
2. 트리 안에 이름 입력란이 생긴다. 이름을 입력하고 엔터. 확장자를 쓰지 않으면 `.md`가 붙는다. `.jsx`로 끝나면 JSX 항목이 된다.
3. 파일이 만들어지고 탭으로 열린다. `.md`는 종류 `lorebook`으로 시작한다. 본문은 비어 있다(섹션 뼈대를 넣지 않는다).
4. 상단 폼에서 종류를 고르고, ID(비워 두면 placeholder 값), 키워드 등을 입력한다.

### 편집과 저장

1. 본문을 고치면 탭에 저장 안 됨 표시(●)가 생긴다.
2. 입력을 멈추고 잠시(기본 1초) 지나면 자동 저장한다(기본 켬). `Ctrl+S`로 바로 저장할 수도 있다. 자동 저장은 설정에서 끌 수 있다.
3. 저장할 때마다 용량과 규칙 검사를 다시 계산한다. 저장 묶음 스냅샷(`save`)은 일정 간격으로 따로 만든다(09-snapshots).

### 파일 가져오기

1. 파일 트리에서 폴더나 빈 곳을 우클릭 → **가져오기…** 로 `.md`·`.jsx` 파일을 고르거나, 탐색기에서 트리의 폴더로 끌어 놓는다.
2. **파일 가져오기** 창: 파일마다 들어갈 경로, 메타데이터(있음·없음·깨짐), 종류, ID, 사용, 키워드 표를 보여 준다.
   - 머리 없는 Markdown 파일은 종류가 비어 있고, 정하기 전에는 **가져오기** 버튼이 막힌다. 여러 파일을 체크해 종류를 한 번에 정할 수 있다.
   - 겹치는 ID는 새 번호(`L001 → L002`), 겹치는 이름은 번호를 붙여 보여 준다. ID는 칸에서 고칠 수 있다.
   - 깨진 머리는 "빼기" / "본문째 메모로"를 고른다.
   - `_keywords.md`를 함께 고르면 키워드 표로 읽어 짝이 맞는 파일에 키워드를 채운다.
3. **가져오기**: 스냅샷을 만들고 파일을 쓴 뒤 첫 파일을 연다. 검사 결과는 검사 패널에 나온다.

규칙은 [data-model: 낱개 파일 가져오기](../data-model.md#낱개-파일-가져오기).

### 종류 바꾸기

- 상단 폼의 종류 드롭다운에서 고른다. 종류에 따라 폼 항목과 안쪽 탭 구성이 바뀐다.
- `.md` 종류끼리(로어북 · 캐릭터 · 메인 프롬프트 · 시작 상황 · 메모)는 바로 바뀐다. 이미 정한 ID는 그대로다.
- JSX로 바꾸거나 JSX에서 다른 종류로 바꾸면 확장자가 바뀐다. 본문이 비어 있지 않으면 확인을 받는다.

### 이름 바꾸기 · 옮기기 · 지우기

- **이름 바꾸기**: 트리에서 `F2` 또는 우클릭 → "이름 바꾸기". 열린 탭 제목도 바뀐다.
- **옮기기**: 트리에서 끌어서 다른 폴더에 놓는다. 같은 폴더 안에서 끌면 순서가 바뀐다(`work.json`의 `order`).
- 이름을 바꾸거나 옮겨도 ID가 그대로이므로 관계도·이미지 데이터 등과의 연결은 끊어지지 않는다.
- **지우기**: `Delete` 또는 우클릭 → "지우기". 휴지통으로 간다. 캐릭터는 이미지 데이터를, JSX는 예시 props를 함께 지울지
  묻는다. 폴더를 지우면 안의 파일 전체가 한 묶음으로 간다.

### 찾기

- `Ctrl+P`: 파일 이름·ID로 빠르게 열기.
- `Ctrl+Shift+F`: 작품 안 전체 검색(사용자 트리만, 본문과 키워드). 결과를 사이드 패널에 파일별로 묶어 보여 준다.

### 안쪽 탭 (종류별 화면)

파일 하나에 관한 화면은 그 파일의 편집 탭 안에 모은다. 편집 탭 위쪽에 **안쪽 탭**을 두고, 종류에 따라 구성이 바뀐다.

| 종류 | 안쪽 탭 |
|---|---|
| 로어북 · 메인 프롬프트 · 시작 상황 · 메모 | [본문] [미리보기] |
| 캐릭터 | [본문] [미리보기] [이미지 디자인] |
| JSX | [코드] [미리보기·props] |

- **[본문]·[코드]**: 상단 메타데이터 폼과 본문 편집기. 상단 폼은 이 탭에서만 보인다.
- **[미리보기]**: 본문을 Markdown으로 렌더링해 보여 준다(읽기 전용).
- **[이미지 디자인]**: 캐릭터의 이미지 프롬프트(외모·의상)와 상태. 이미지 프롬프트가 오래됐으면 탭 이름 옆에 "오래됨"을 단다.
  상세는 06-image-prompts.
- **[미리보기·props]**: JSX 렌더링 결과와 예시 props 전환·편집, 정적 검사 결과. 상세는 07-jsx.
- 종류를 바꾸면 안쪽 탭 구성도 바로 바뀐다. 없어진 탭을 보고 있었으면 [본문]으로 돌아간다.
- LLM 결과의 검토·채택(압축 후보, 이미지 프롬프트 변환 결과 등)은 보조 패널의 "검토" 탭에서 한다. 안쪽 탭은 현재 저장된 값을
  보여 주고 고치는 곳이다.

### 앱 밖에서 파일이 바뀌었을 때

- 트리를 갱신한다(새 파일, 지워진 파일, 이름 바뀐 파일).
- 열린 탭의 파일이 바뀌었고 그 탭에 저장하지 않은 변경이 **없으면**: 조용히 다시 불러오고 알림만 띄운다.
- 저장하지 않은 변경이 **있으면**: 탭 위에 띠를 띄우고 고르게 한다 — "디스크 내용으로 다시 불러오기", "내 내용 유지(저장 시
  덮어씀)", "비교". 고르기 전에는 자동 저장을 멈춘다.
- 열린 파일이 지워졌으면 탭에 "디스크에 없음"을 표시하고, 저장하면 다시 만든다.

### 예외 흐름

- **메타데이터 형식 오류**(YAML이 깨짐, `.jsx` 머리 주석이 깨짐): 상단 폼 대신 오류 안내와 메타데이터 원문 편집란을 보여 준다.
  고치기 전에는 폼을 쓸 수 없지만 본문 편집과 저장은 된다.
- **같은 ID가 이미 있음**: ID 입력란 아래에 "이미 쓰는 ID예요(인물/김도현.md). C003을 써 보세요"를 띄우고 저장은 하되
  규칙 검사 오류로 남긴다.
- **이름 충돌**: 같은 폴더에 같은 이름(대소문자 무시)이 있으면 이름 입력란에서 막는다.

## 화면

### 파일 트리 (사이드 패널)

```text
청원고                    [+파일] [+폴더] [⋯]
├ 📄 메인.md
├ 📄 메인 (압축).md       (흐리게: 사용 안 함)
├ 📁 인물
│  ├ 👤 한서윤.md   ●     (저장 안 됨)
│  └ 👤 김도현.md   ⚠     (검사 경고)
├ 📁 세계관
│  └ 📄 학교.md
├ 📁 UI
│  └ ⚛ 상태창.jsx
└ 📁 메모
   └ 🗒 떡밥 정리.md
```

- 아이콘은 종류별로 다르다(메인 프롬프트, 시작 상황, 로어북, 캐릭터, JSX, 메모). 항목이 아닌 파일은 회색으로 보여 준다.
- 사용 안 함(`enabled: false`) 항목은 흐리게. 검사 오류·경고가 있으면 이름 옆에 표시.
- 우클릭 메뉴: 새 파일, 새 폴더, 이름 바꾸기, 복제, 지우기, 탐색기에서 열기, 경로 복사.

### 편집 탭

```text
┌ 한서윤.md ● ─────────────────────────────────────────────────────────┐
│ [본문] [미리보기] [이미지 디자인 · 오래됨]                            │
│ 종류 [캐릭터 ▾]  ID [ C001 ]  우선순위 [100]  항상 넣기 [ ]  사용 [✓] │
│ 키워드 [서윤×][한서윤×][반장×] 입력…                                  │
│ ▸ 기타 (폼에 없는 메타데이터)                                         │
├──────────────────────────────────────────────────────────────────────┤
│ ## 식별                                                              │
│ 2학년 3반 반장. 17세 …                                                │
│ ## 외모                                                              │
│ …                                                                    │
└──────────────────────────────────────────────────────────────────────┘
```

상단 폼은 종류에 따라 바뀐다.

| 종류 | 폼 항목 |
|---|---|
| 로어북 | 종류, ID, 키워드, 우선순위, 항상 넣기, 사용 |
| 캐릭터 | 위와 같음 |
| 메인 프롬프트 | 종류, ID, 사용 |
| 시작 상황 | 종류, ID, 사용 |
| JSX | 종류, ID, 기본 예시 props, 사용 |
| 메모 | 종류, ID(선택) |

- 폼은 접을 수 있다(접으면 종류·ID만 한 줄로).
- 본문 편집기: `.md`는 Markdown 강조 표시(제목, 목록, 코드 블록), `.jsx`는 JSX 강조 표시와 괄호 짝 맞춤.
- 본문 우클릭(또는 Alt+P) 메뉴: 잘라내기, 복사, 에이전트에 첨부(Ctrl+L). 캐릭터 본문에는 **이미지 프롬프트로**(고른 글을 외모·의상으로 변환,
  [06](06-image-prompts.md#변환-e-범위-지정))가 더 있다.

### 용량 게이지

- 상태 표시줄: 현재 파일 용량 / 제한, 작품 전체 용량(사용 중 항목 합계) / 제한.
- 세는 방식은 연결된 플랫폼 프리셋의 `count`. 토큰 방식이면 토크나이저 준비 전까지 "계산 중"을 보인다.
- 제한의 90%를 넘으면 경고색, 넘으면 오류색.

### 검사 (보조 패널 "검사" 탭)

현재 파일의 검사 결과를 위에, 작품 전체 결과를 아래에 보여 준다. 항목을 누르면 해당 위치로 간다.

| 검사 | 수준 | 내용 |
|---|---|---|
| 용량 | 오류 | 파일·전체 용량이 플랫폼 제한을 넘음 |
| 메인 프롬프트 수 | 오류 | 사용 중인 메인 프롬프트가 0개 또는 2개 이상 |
| ID | 오류 | ID가 비었거나 형식이 틀림, 다른 항목과 겹침 |
| 메타데이터 | 오류 | YAML·JSX 머리 주석을 읽을 수 없음, 모르는 종류 |
| 키워드 개수 | 오류 | 플랫폼 프리셋의 `max_keywords` 초과 |
| 키워드 겹침 | 경고 | 같은 키워드를 쓰는 항목이 여럿 |
| 너무 짧은 키워드 | 경고 | 한 글자 키워드 등 대화에서 쉽게 걸리는 키워드 |
| 키워드 없음 | 경고 | 로어북·캐릭터인데 키워드가 없고 항상 넣기도 아님 |
| 이미지 프롬프트 오래됨 | 정보 | 캐릭터 본문이 바뀌어 이미지 프롬프트의 출처 해시와 다름 |
| 내보내기 이름 충돌 | 경고 | 내보낼 항목 중 최상위에 예약 이름 `_keywords.md`가 있음(이름을 바꾸기 전에는 내보내지 않음) |
| `{{char}}`를 정할 수 없음 | 경고 | `single`이 아닌 작품의 본문에 `{{char}}`가 있거나, `work.json`의 `char`가 없는 캐릭터를 가리킴 |
| 예약 참조 뒤 조사 | 정보 | `{{user}}는`, `{{char}}가`처럼 예약 참조 바로 뒤에 조사가 붙음 |
| 본문 속 컴포넌트 예시 | 경고 | 본문에 넣은 JSX 컴포넌트 요소를 읽을 수 없거나 그려지지 않음(07) |

- JSX 정적 검사(플랫폼 `jsx` 규칙)와 본문 속 컴포넌트 예시 검사의 기준은 07-jsx에서 정한다.

### 상태

- **비어 있음**: 트리가 비면 "새 파일"·"새 폴더"와 "샘플 작품에서 구성을 참고해 보세요" 안내. 열린 탭이 없으면 편집 영역에
  최근 연 파일 목록과 단축키 안내.
- **불러오는 중**: 큰 파일을 여는 동안 탭에 진행 표시.
- **오류**: 저장 실패 시 탭에 오류 표시와 "다시 저장", 저장되지 않은 내용은 화면에 그대로 둔다.

## 규칙

- 앱은 본문을 바꾸지 않는다. 저장은 사용자가 쓴 그대로 하고, 메타데이터 머리만 앱이 정리해서 쓴다(키 순서·모르는 필드 보존).
- 줄바꿈은 파일이 원래 쓰던 방식을 유지하고, 새 파일은 LF로 만든다. 인코딩은 UTF-8(BOM 없음).
- 쓰기는 임시 파일에 쓴 뒤 바꿔 넣는다. 자동 저장이 실패하면 다시 시도하지 않고 탭에 오류를 표시한다.
- 본문 편집기 엔진(CodeMirror 6 등)은 architecture.md에서 정한다.
- 이름 바꾸기·옮기기는 ID를 바꾸지 않는다. ID 바꾸기는 상단 폼에서만 하며 연결 갱신 절차를 따른다
  ([data-model.md ID](../data-model.md#id)).
- 여러 파일을 한꺼번에 옮기거나 폴더 이름을 바꾸기 전에는 `before_bulk` 스냅샷을 만든다.
- `.atelierx`라는 이름은 사용자 트리에서 쓸 수 없다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works/{id}/tree` | 사용자 트리(이름, 종류, 사용 여부, 검사 요약) |
| `GET /api/works/{id}/file?path=` | 파일 읽기: 메타데이터(구조화)와 본문, 디스크 해시 |
| `PUT /api/works/{id}/file?path=` | 저장: `{meta, body, base_hash}`. 디스크 해시가 `base_hash`와 다르면 충돌로 거절 |
| `POST /api/works/{id}/file` | 새 파일 `{path}` |
| `POST /api/works/{id}/folder` | 새 폴더 |
| `POST /api/works/{id}/move` | 이름 바꾸기·옮기기 `{from, to}` |
| `POST /api/works/{id}/kind` | 종류 바꾸기(확장자 변경 포함) |
| `DELETE /api/works/{id}/file?path=` | 지우기(휴지통으로, 함께 지울 부가 데이터 선택) |
| `GET /api/works/{id}/check` | 규칙 검사 결과(파일별·작품 전체) |
| `GET /api/works/{id}/search?q=` | 전체 검색 |
| `GET /api/works/{id}/measure?path=` | 용량 계산(플랫폼 `count` 방식) |

외부 변경은 [00-shell](00-shell.md)의 이벤트 스트림으로 알린다.

## 단계

- **1단계**: 파일 트리(새 파일·폴더, 이름 바꾸기, 옮기기, 순서, 지우기), 상단 폼(모든 종류), 안쪽 탭(본문·미리보기. 이미지 디자인·JSX 미리보기는 각 단계), 본문 편집기, 자동 저장,
  외부 변경 처리, 용량 게이지(바이트·글자 수), 규칙 검사(위 표), 빠른 열기·전체 검색.
- **구현됨(3단계 무렵)**: 용량을 플랫폼 프리셋 `count` 단위로 표시·검사(`utf8_bytes`, `chars`, `tokens:<이름>`). 토크나이저 파일을 아직
  넣지 않아 토큰은 추정치(한글 음절 ≈ 1토큰, 그 밖 4글자 ≈ 1토큰)로 "추정"을 붙여 보여 준다. 테스트 화면의 로어북 예산도 같은 단위로 센다.
  이름 일괄 변경(04)은 파일 트리 우클릭 "이름 바꾸기(작품 전체)"와 검색 패널의 ⇄.
- **이후**: 실제 토크나이저(03-llm), 검사 결과에서 바로 고치기(키워드 겹침 정리 등).
