# 테스트 화면

## 목적

작품을 실제 챗봇처럼 돌려 본다. 상단 바의 **테스트**를 누르면 작품 창이 테스트 화면으로 바뀌고, 설정에서 정한 LLM이 챗봇
역할을 한다. 챗봇은 네 가지로 이루어진다.

| 구성 | 테스트에서 쓰는 방식 |
|---|---|
| 시작 상황 | 사용 중인 시작 상황을 좌우로 넘겨 하나를 고른다. 고른 것이 봇의 첫 턴이 된다 |
| 메인 프롬프트 | 사용 중인 것 하나를 항상 불러온다 |
| 로어북(캐릭터 포함) | 활성화 키워드에 따라 턴마다 불러온다 |
| JSX | 응답에서 컴포넌트를 호출하면 그 자리에 표시한다 |

입력과 출력을 주고받으며 턴마다 무엇을 불러왔는지 오른쪽에 보여 주어, 원고를 고치고 바로 확인하는 흐름을 만든다. LLM 호출
방식은 [03-llm](03-llm.md).

- 로어북 활성화는 플랫폼마다 고유한 기능이다. 테스트 화면은 연결된 플랫폼 프리셋의 규칙으로 **근사**할 뿐이며, 통과/실패를
  매기지 않는다. 화면에도 이 점을 한 줄로 알린다.
- 대화 시나리오(저장해 두고 기대값으로 채점하는 기능)는 두지 않는다([결정 0017](../decisions/0017-test-screen.md)).

## 사용 흐름

### 테스트하기

1. 작품 창 상단 바의 **테스트**를 누른다. 작품 창 전체가 테스트 화면으로 바뀐다. 상단 바의 **← 작업으로**를 누르면 돌아간다.
   오가도 대화는 남아 있다.
2. 위쪽 막대에서 사용자 페르소나(이름과 한두 줄 설명. 이름은 `{{user}}` 자리에 들어감)를 정한다. 페르소나는 플랫폼 사용자가
   정하는 값이라 원고가 아니라 테스트 설정으로 둔다. 쓰는 LLM은 설정의 작업 `chat_test` 연결이며 막대에 표시한다.
3. 시작 상황 슬라이드에서 ‹ › 로 시작 상황을 고른다. 마지막 장은 "시작 상황 없이(사용자가 먼저)". 고른 시작 상황이 대화의
   첫 봇 메시지로 보인다. 첫 메시지를 보낸 뒤에는 바꿀 수 없다(새 대화에서 다시 고름).
4. 메시지를 보내면 앱이 맥락을 만들어 보내고, 응답이 흘러나오듯 표시된다.
5. 오른쪽 **불러온 내용** 패널에 고른 턴(기본은 마지막 응답, 응답을 누르면 그 턴)의 내용이 나온다.
6. 작업 화면에서 원고를 고치고 돌아와 다음 메시지를 보내면 고친 내용으로 맥락을 만든다(매 전송마다 원고를 새로 읽음).

### 턴 다루기

- **새 대화**: 대화를 비우고 새로 시작한다. 지난 대화는 테스트 기록으로 남는다.
- **입력 다시 보내기**: 새 대화에서, 지난 대화의 내 메시지들을 차례로 다시 보낸다. 원고를 고친 뒤 같은 입력으로 다시 확인할 때
  쓴다(비교·채점은 하지 않음).
- **다시 생성**: 마지막 응답을 다시 받는다. 이전 응답은 같은 자리에서 좌우 넘김으로 볼 수 있다.
- **고쳐서 다시**: 이전의 내 메시지를 고치면 그 자리부터 다시 진행한다.
- **원문 / 렌더링**: 응답마다 컴포넌트 호출을 원문으로 볼지 렌더링해 볼지 바꾼다.

### 불러온 내용

| 표시 | 내용 |
|---|---|
| 메인 프롬프트 | ● 사용 중인 메인 프롬프트 이름과 "상시". 없으면 경고 |
| 로어북 | 사용 중인 로어북·캐릭터 항목 전부. 이번 턴에 불러온 것은 ●와 이유(상시 / 맞은 키워드), 아닌 것은 ○ "이번 턴 없음", 예산·최대 개수로 빠진 것은 이유 |
| JSX | 사용 중인 JSX 항목 전부. 이 응답에서 호출된 것은 ◆ "응답에서 호출", 아닌 것은 ◇ |
| 크기 | 보낸 맥락 크기, 불러온 로어북 수 |
| 원문 | 실제로 보낸 맥락 전체(읽기 전용, 복사 가능) |

- 항목 이름을 누르면 작업 화면으로 돌아가 그 파일을 편집 탭으로 연다.

### 예외 흐름

- **맥락이 모델 맥락 길이를 넘음**: 보내지 않고 알린다. 오래된 턴을 빼고 보낼지(앞에서부터 잘라 냄) 고르게 한다.
- **사용 중인 메인 프롬프트가 없거나 둘 이상**: 불러온 내용에 경고를 보이고 고치러 가기를 보여 준다.
- **외부 연결**: 첫 전송 때 외부 전송 확인([03-llm](03-llm.md)).
- **응답 실패·거부**: 그 턴에 오류를 표시하고 "다시 생성"을 보여 준다. 거부면 서비스가 보낸 이유를 그대로 보여 준다.
- **컴포넌트 표기를 읽을 수 없음**: 그 부분은 원문 그대로 보여 준다.

## 화면

```text
┌ 샘플 single ▾  작품 설정  내보내기  [← 작업으로]                                          🔍 ⧗ ⚙ 🔒 ┐
│ 테스트  LLM: 로컬 · qwen3-32b   [{{user}} 이름] [페르소나 설명        ] [새 대화] [입력 다시 보내기 (3)] │
├──────────────────────────────────────────────────────────────┬──────────────────────────────────┤
│ ‹  시작 상황 1/3 · 시작 상황.md                            ›  │ 불러온 내용                      │
│                                                              │ ● 메인 프롬프트  메인.md    상시 │
│  봇   (시작 상황 본문)                                        │ 로어북                           │
│  나   하람 씨, 추천 메뉴가 뭐예요?                            │ ● 카페 노을   키워드 "노을"      │
│  봇   (응답 …)                                               │ ○ 윤하람      이번 턴 없음       │
│       ┌ ⚛ StatusPanel ─────────────┐                          │ JSX                              │
│       │ (컴포넌트 렌더링)           │                          │ ◆ StatusPanel  응답에서 호출     │
│       └─────────────────────────────┘  원문 보기              │ 보낸 맥락 2,275 B · 로어북 2개   │
│ [메시지 입력                                      ] [보내기]  │ ▸ 원문 보기                      │
└──────────────────────────────────────────────────────────────┴──────────────────────────────────┘
```

- 응답 본문 속 컴포넌트 요소(작품의 JSX 항목 이름과 같은 요소)는 그 자리에 렌더링한다. 읽는 규칙은 플랫폼 프리셋의 응답 속
  컴포넌트 표기를 따른다([07-jsx](07-jsx.md)). JSX 미리보기 전(0단계)에는 컴포넌트 이름과 속성 값을 상자로 보여 준다.

### 상태

- **비어 있음**: 시작 상황이 없고 대화가 비면 "메시지를 보내 시작해 보세요". 불러온 내용은 "메시지를 보내면 이번 턴에 불러온
  내용이 여기에 나옵니다".
- **불러오는 중**: 응답을 받는 동안 흘러나오는 글과 "멈추기".
- **오류**: 턴 안에 오류 문장과 다시 시도.

## 규칙

### 맥락 조립

1. **시스템 맥락** = 사용 중인 메인 프롬프트 본문 + 이번 턴에 들어갈 로어북 항목 본문들.
2. 로어북 항목 고르기는 [로어북 활성화](../data-model.md#로어북-활성화)의 선택 순서를 따른다: 항상 넣기 → 키워드가 맞은 항목을
   우선순위 순 → 예산·최대 개수를 넘는 항목은 뺀다. 키워드는 최근 `scan.messages`개 메시지(설정한 쪽)의 **원문**에서 찾는다.
   시작 상황도 봇 메시지로 친다. 응답 속 컴포넌트 표기(속성 값 포함)도 원문의 일부라, 상태창 안의 표시를 키워드로 써서 항목을
   이어서 활성화할 수 있다.
3. 들어간 로어북 항목은 메인 프롬프트 뒤에 우선순위 순(같으면 트리 순서)으로 붙인다. 항목 사이는 빈 줄로 구분한다.
4. **대화 기록** = 고른 시작 상황(봇의 첫 턴으로) + 지금까지의 턴. 사용자 페르소나 설명이 있으면 시스템 맥락 끝에 "사용자: …"로
   붙인다.
5. **예약 참조 바꾸기**: 보내기 직전에 시스템 맥락·시작 상황·대화 기록의 `{{user}}`를 페르소나 이름으로, `{{char}}`를 작품의
   `{{char}}` 캐릭터 이름으로 바꾼다([data-model.md 예약 참조](../data-model.md#예약-참조)). 원문 보기에는 바꾼 결과가 보인다.
6. 메타데이터는 보내지 않는다. 본문만 보낸다(내보내기와 같은 본문에서 예약 참조만 바꿈).
7. 관계도·용어집은 참고용이라 보내지 않는다.

- 플랫폼마다 로어북을 넣는 위치·형식이 다를 수 있다. 위 순서를 기본으로 하고, 필요해지면 플랫폼 프리셋에 넣는 위치 설정을
  추가한다. 항목별 활성화 옵션([로어북 활성화 옵션](../data-model.md#로어북-활성화-옵션-예약))은 아직 쓰지 않는다.

### 기록

- 테스트 기록은 대화 하나가 파일 하나, 한 줄에 한 턴: 시각, 내 메시지, 응답, 모델·설정, 맥락 요약(불러온 항목 ID와 해시, 빠진
  항목과 이유, 크기), 응답 속 컴포넌트 호출, 걸린 시간, 비용(가격이 있을 때). 스냅샷에 넣지 않는다.
- 작품마다 최근 100개를 남기고 오래된 것부터 지운다. 설정에서 바꿀 수 있다.
- 기록에는 인증 정보를 남기지 않는다([금고](../data-model.md#금고) 규칙).

### 외부 전송

- 외부 연결로 테스트하면 작품의 메인 프롬프트·시작 상황과 활성화된 로어북 본문이 그 서비스로 간다. 외부 전송 확인은
  [03-llm](03-llm.md)을 따른다. 기본 연결은 로컬이다.

## API

| 요청 | 내용 |
|---|---|
| `POST /api/works/{id}/chat/send` | 메시지 보내기 `{history, message, persona?}` → 응답 스트림(이벤트: 맥락 요약 `context`, 글 조각 `delta`, 끝 `end`) |
| `POST /api/works/{id}/chat/preview` | 보내기 전 맥락 조립만 `{history, message}` → 불러올 항목·크기(LLM 호출 없음) |
| `POST /api/works/{id}/chat/regenerate` | 마지막 응답 다시 받기(3단계) |
| `GET /api/works/{id}/runs` · `GET …/runs/{rid}` | 테스트 기록 |

- 맥락 요약에는 불러온 로어북(`picked`), 빠진 항목(`skipped`), 사용 중인 로어북 전체(`lorebook`), JSX 항목(`components`)이 들어간다.

## 단계

- **0단계(골격)**: 테스트 화면, 시작 상황 슬라이드, 페르소나, 맥락 조립과 불러온 내용 패널, 입력 다시 보내기, 원문/렌더링 전환.
  응답은 모의(첫 JSX 항목의 기본 예시 props로 컴포넌트 호출을 하나 붙임), 컴포넌트는 이름·속성 상자로 표시.
- **3단계**: 실제 LLM 연결(스트리밍, 멈추기), 다시 생성, 고쳐서 다시, 테스트 기록, 맥락 길이 확인.
- **4단계(07과 함께)**: 응답 속 컴포넌트 렌더링(격리된 미리보기 재사용).
- **이후**: 모델 두 개를 나란히 비교, 압축 전후 비교(05와 연결).
