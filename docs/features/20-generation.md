# 이미지 생성

## 목적

캐릭터 디자인(외모·의상)과 이미지 라이브러리(표정·구도·화풍·공통)를 조합해 이미지를 만든다. 생성은 사용자의 이미지 생성
서버(ComfyUI 등)가 하고, AtelierX는 조합·대기열·결과 정리를 맡는다. 만든 이미지는 출력 루트에 캐릭터·의상·표정별로 쌓이고,
검수([21](21-review.md))와 데이터셋([22](22-datasets.md))으로 이어진다. 조합 규칙은 [06-image-prompts](06-image-prompts.md).

## 사용 흐름

### 연결

1. 설정 → 이미지 → 이미지 생성 연결: 서버 주소(예: `http://127.0.0.1:8188`), 모델 폴더, LoRA 폴더.
2. "연결 시험" → 서버가 아는 모델·LoRA·샘플러 목록을 받아 온다.
3. 생성 프리셋(전역 라이브러리 `presets/`)을 만든다: 모델, 샘플러, 스텝, CFG, 크기, 기본 LoRA, 쓸 공통·화풍 항목, 워크플로 틀.

### 생성 요청

1. 캐릭터의 [이미지 디자인] 탭 또는 활동 막대 이미지 → "생성".
2. 생성 창에서 고른다.
   - 캐릭터(여럿 가능), 의상(여럿), 표정(여럿 또는 등급 전체), 구도(표정에 붙은 기본값 또는 직접), 생성 프리셋.
   - 조합마다 장수, 시드(무작위 / 고정 / 이어서).
3. 창 아래에 만들어질 장수 합계와 조합 미리보기 몇 개를 보여 준다. "대기열에 넣기".
4. 작업이 GPU 순서로 실행된다. 이미지가 나올 때마다 진행 표시와 썸네일이 갱신된다.

### 결과

- 이미지는 `<출력 루트>/<작품 ID>/<캐릭터 ID>/images/<의상>/<표정>/<번호>.png`로 저장되고, 같은 이름의 `.json`에 생성 기록이
  남는다.
- 이미지 파일에도 생성 정보(최종 프롬프트, 설정, 워크플로)를 넣어 다른 도구에서 열어도 다시 만들 수 있게 한다.
- 끝나면 알림 → 검수 화면([21](21-review.md))으로 가기.

### 다시 만들기

- 갤러리([21](21-review.md))에서 이미지를 "새 시드로 다시 생성"하면 생성 기록 그대로 시드만 바꿔 대기열에 넣는다.
- 설정을 바꿔 다시 해 보려면 갤러리의 "생성·비교에서 열기"로 아래 생성·비교 화면에 프롬프트와 설정을 넘긴다.

### 생성·비교

이미지 → 생성·비교. 작품과 상관없이 프롬프트 하나를 직접 써서 시험하는 화면이다.

1. positive·negative를 쓰고(태그 확인으로 모르는 태그·별칭을 본다) 생성 설정을 정한다. 생성 프리셋을 불러오거나 지금 설정을
   새 프리셋으로 저장할 수 있다.
2. **한 번 생성**: 시드 수만큼(최대 16) 만든다.
3. **값 비교**: CFG, 스텝, 샘플러, 스케줄러, CLIP skip, LoRA 세기, 화풍·작가 태그 중 하나를 골라 값을 2~12개 적는다. 행마다
   시드 하나, 열마다 값 하나인 격자로 만들어 그 값만 다르게 한다. 화풍·작가 태그는 후보를 공통 프롬프트 뒤에 붙이고, 아무것도
   붙이지 않은 기준 열을 함께 둘 수 있다. 한 번에 48장까지.
4. 결과는 격자로 보이고, 두 장을 골라 **기준·결과**로 나란히 또는 겹쳐 밀며(슬라이더) 비교한다. 갤러리에서 넘어왔다면 그 원본이
   기준이다. "결과의 설정 불러오기"로 마음에 드는 결과의 프롬프트·설정을 그대로 가져온다.
5. 결과는 `<출력 루트>/_lab/<날짜>/`에 생성 기록과 함께 저장되고(검수 대상 아님), 대기열을 정리해도 실행 목록은 저장된 기록에서
   다시 읽는다.
6. **조합으로 가져오기**: 고른 결과를 캐릭터·의상·표정 조합으로 복사한다(`<출력 루트>/<작품>/<캐릭터>/images/<의상>/<표정>/<번호>.png`,
   생성 기록에 조합과 `imported_from`을 적음). 갤러리 검수·채택·배포 내보내기를 그대로 타고, "바로 채택"을 고르면 가져오며 채택한다.
   생성·비교의 원본은 그대로 둔다.

### LoRA 적용

- 캐릭터의 쓸 LoRA 목록(`lora/models.json`)에서 "자동 적용"인 LoRA는 그 캐릭터를 생성할 때 기본 강도로 함께 쓴다. 생성 창에서 이번
  한 번 끄거나 강도를 바꿀 수 있다([23](23-lora-training.md)).

### 생성 뒤 단계 (#168)

- 생성 설정과 프리셋에 shift(Anima), LoRA 켜기/끄기, **업스케일 후 다시 그리기**(업스케일 모델·최종 배율·스텝·denoise·CFG),
  **디테일러**(부위별 denoise, 스텝)를 둔다. 순서는 LoRA → shift → 1차 생성 → 업스케일 → 디테일러이고 작업 하나다.
- 업스케일·디테일러 노드 조립은 이미지 도구와 같은 함수(`workflow.upscale_node`, `detailer_node`)를 쓴다. 디테일러는 부위마다
  노드를 하나씩 이어 부위별 denoise를 준다.
- 필요한 노드(앱 노드 팩, Impact)나 업스케일 모델이 없으면 대기열에 넣기 전에 막는다. 켜지 않으면 지금과 같은 그래프다.
- 대기열의 진행 문구에 단계 구성("생성 중 → 업스케일 → 디테일러")을 보여 준다. 이미지 생성 서버의 결과는 HTTP로 확인하므로
  단계별 시간은 따로 재지 않는다.

### 커스텀 노드 (#178)

- 생성 설정과 프리셋에 **모델 패치**(모델을 받아 모델을 돌려주는 커스텀 노드, 여러 개·순서대로)를 둔다. 노드는 이미지 생성 서버가
  가진 것에서 고르고, 설정 칸은 그 노드의 입력 정의로 만든다([결정 0026](../decisions/0026-custom-nodes.md)).
- 샘플러·스케줄러는 노드 팩이 더한 이름도 고를 수 있다. 없을 때 대신 쓸 이름(`fallback`)을 함께 둔다. `beta57`은 노드 팩 없이도 된다.
- 대기열에 넣기 전에 `check-nodes`로 없는 것을 확인하고, 있으면 **설치**(설치 목록에 있을 때) / **빼고 생성** / **취소**를 묻는다.
  설치 목록에 없는 노드 팩은 출처와 라이선스를 보여 준다.
- 이미 대기열에 있는 작업은 묻지 않고 빼고 생성하며, 뺀 것은 생성 기록의 `skipped`에 남는다.

### 예외 흐름

- **서버 연결 안 됨**: 작업을 대기 상태로 두고 "이미지 생성 서버에 연결할 수 없어요"를 띄운다. 연결되면 이어서 실행한다.
- **모델·LoRA 파일을 서버가 모름**: 생성 전에 알려 주고 그 조합은 건너뛴다.
- **생성 중 실패**: 실패한 이미지만 실패로 남기고 대기열을 멈춘다(잃는 것이 없게). 사용자가 원인을 보고 이어서 실행하거나 건너뛴다.
- **본문이 바뀌어 디자인이 오래됨**: 생성 창에 "이미지 프롬프트가 오래됨"을 표시한다. 막지는 않는다.

## 화면

### 생성 창

```text
┌ 이미지 생성 ──────────────────────────────────────────────────────────┐
│ 캐릭터 [한서윤 ×] [+]      프리셋 [기본 ▾]      LoRA: w001_c001 (자동, 0.8) │
│ 의상   [o01 평상복 ✓] [o02 교복 ✓]                                    │
│ 표정   [일반 전체 ✓]  무표정 · 미소 · 웃음 · 화남 · …                 │
│ 구도   [표정 기본값 ▾]                                                 │
│ 장수   조합마다 [2]   시드 [무작위 ▾]                                   │
├────────────────────────────────────────────────────────────────────────┤
│ 합계 32장 (의상 2 × 표정 8 × 2)                         [대기열에 넣기] │
└────────────────────────────────────────────────────────────────────────┘
```

### 상태

- **비어 있음**: 연결이 없으면 "이미지 생성 서버를 연결해 주세요". 디자인이 없는 캐릭터는 고를 수 없고 이유를 보여 준다.
- **불러오는 중**: 작업 대기열 패널과 상태 표시줄에 진행.
- **오류**: 실패한 조합과 서버가 보낸 오류.

## 규칙

- 생성 요청은 GPU 작업이다. 로컬 LLM 작업, 학습과 한 줄로 서서 하나씩 실행한다([architecture.md](../architecture.md)).
- 최종 프롬프트는 [06](06-image-prompts.md)의 조합 규칙으로 서버(AtelierX)에서 만든다. 화면의 조합 미리보기와 같은 결과다.
- 이미지 생성 서버로 보내는 것은 워크플로(조합된 프롬프트와 설정)뿐이다. 작품 본문은 보내지 않는다.
- 워크플로 틀은 모델 계열마다 하나다. 틀 안의 자리표시(프롬프트, negative, 시드, 크기, 모델, LoRA 목록)를 앱이 채운다.
- 생성 기록에는 같은 이미지를 다시 만들 수 있는 정보를 모두 남긴다: 최종 프롬프트·negative, 시드, 생성 프리셋 내용, LoRA와 강도,
  워크플로 틀 이름, 캐릭터 디자인의 해시.

## 단계

- **I4(구현)**: 생성·비교 화면(한 번 생성, 값 비교 격자, 기준·결과 나란히·슬라이더, 결과 설정 불러오기, 프리셋 저장, 갤러리에서 넘겨받기).
- **I2(구현)**: 이미지 → 프롬프트 라이브러리(표정·구도·화풍·공통·공용 의상, 전역/작품 범위, 태그 자동 완성), 생성 프리셋(계열·모델·
  샘플러·크기·LoRA·기본 공통/화풍), 이미지 → 생성(캐릭터×의상×표정, 구도·화풍·공통, 조합 미리보기, 한 조합이면 부분별 직접 수정),
  워크플로는 계열별로 코드에서 조립(anima: UNET+CLIP+VAE, SDXL: 체크포인트+clip skip, LoRA 연쇄), 영속 대기열(일시 정지·다시 시도·
  취소·끝난 것 정리, 실패하면 자동 일시 정지, 재시작 때 실행 중이던 것은 "중단됨"), 결과는 PNG(prompt·workflow·atelierx 청크)+같은
  이름의 .json. 트리거 단어는 그 캐릭터에 등록된 LoRA가 있을 때만 넣는다. 구도의 "보이는 부위"로 의상 부위를 고른다.
- **I1(구현)**: 설정 → 이미지: 연결(주소만으로 외부 ComfyUI 연결, 폴더·Python을 적으면 이 앱이 시작·중지), 설치 자동 찾기(실행 중인 것,
  Stability Matrix, 데스크톱 앱, 흔한 폴더), 모델·LoRA 계열 판별(폴더 → 직접 지정 → Stability Matrix 정보 → 파일 헤더)과 직접 지정,
  GPU 대기 규칙(남은 VRAM, 기다릴 프로그램)과 GPU 사용자 표시. 설정은 `config/image/`, 상태는 `state/image/`.

- **7단계**: 연결, 생성 프리셋, 워크플로 틀(한 모델 계열부터), 생성 창, 대기열 실행, 결과 저장과 생성 기록, 다시 만들기, LoRA 자동 적용.
- **이후**: 더 많은 모델 계열의 워크플로 틀.

## 정할 것

- 이미지 파일 형식(PNG / WebP)과 생성 정보를 파일에 넣는 방식.
- 처음 지원할 모델 계열과 워크플로 틀.
