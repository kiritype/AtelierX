# 작품 관리

## 목적

작품(= 챗봇 하나)을 고르고, 만들고, 복제하고, 지우고, 설정한다. 작품을 다른 곳에서 가져오거나 플랫폼에 올릴 파일로
내보내는 일도 여기서 한다. 작품 안의 파일 편집은 [02-editor](02-editor.md)에서 다룬다.

## 사용 흐름

### 작품 고르기

1. 잠금을 해제하면 작품 선택 화면이 열린다([00-shell](00-shell.md)).
2. 카드를 누르면 그 작품의 창이 열린다. 마지막으로 연 작품이 맨 앞에 있다.

### 새 작품

1. "새 작품"을 누르면 만들기 창이 열린다.
2. 작품 이름(= 폴더 이름), ID(placeholder `W00n`), 태그, 규모, 언어를 입력한다. 설정에 기본 플랫폼 프리셋이 있으면 그 태그가
   미리 들어가 있다.
3. "만들기"를 누르면 `data/works/<이름>/.atelierx/work.json`이 생기고 빈 작품 창이 열린다. 파일 트리는 비어 있고
   "새 파일"·"새 폴더"를 보여 준다.

### 샘플 작품

1. "샘플 작품"을 누르면 앱에 포함된 샘플 목록이 나온다.
2. 하나를 고르면 **복사본**을 새 작품으로 만든다(이름은 샘플 이름, ID는 다음 번호). 샘플 원본은 고치지 않는다.
3. 샘플은 권장 폴더 구성, 종류별 항목 예시(메인 프롬프트, 시작 상황, 로어북, 캐릭터, JSX, 메모), 캐릭터 섹션 예시를 보여 주는 용도다.
   규모별로 하나씩 세 개(single, ensemble, simulation)를 둔다. 공개 저장소에 들어가므로 새로 만든 가상 작품으로 쓴다.

### 복제

1. 카드의 메뉴 → "복제". 새 이름과 새 ID(placeholder 다음 번호)를 입력한다.
2. 복제 규칙은 [data-model.md ID](../data-model.md#id)의 "작품 복제"를 따른다(이력·임시 항목·휴지통·실행 기록은 복사하지 않음).

### 이름 바꾸기

카드의 메뉴 → "이름 바꾸기". 폴더 이름이 바뀐다. ID는 바뀌지 않으므로 출력 파일·LoRA와의 연결은 그대로다.

### 지우기

카드의 메뉴 → "지우기" → 확인. 작품 폴더 전체가 `data/.trash/`로 간다. 되살리기와 완전 삭제는 작품 선택 화면의 "휴지통"에서
한다([data-model.md 휴지통](../data-model.md#휴지통)).

### 작품 설정

1. 작품 창에서 상단 바 메뉴 → "작품 설정"(또는 상태 표시줄의 플랫폼 프리셋을 누름). 편집 영역에 탭으로 열린다.
2. ID, 태그, 규모, 언어, 섹션 이름, 플랫폼 프리셋 값 덮어쓰기(`overrides`)를 고친다.

### 가져오기 (AtelierX 작품 폴더)

다른 앱 폴더나 백업에 있는 AtelierX 작품을 옮겨 온다.

1. 작품 선택 화면 → "가져오기" → 가져올 작품 폴더(`.atelierx/`가 있는 폴더)를 고른다.
2. 이름과 ID를 확인한다. 이미 있는 ID면 새 ID를 권유한다.
3. "가져오기" → 작품 폴더를 그대로 복사한다. 가져온 직후 `import` 스냅샷을 만든다.

- `.atelierx/`가 없는 일반 폴더(다른 곳에서 쓰던 챗봇 원고)를 가져오는 기능은 지금 범위에 넣지 않는다. 플랫폼에서 작품을
  그대로 꺼낼 방법이 일반적으로 없기 때문이다. 필요해지면 이후 단계에서 다룬다(폴더 단위 종류 지정, 키워드 표 읽기 등).

### 내보내기

1. 작품 창에서 상단 바 메뉴 → "내보내기" → 내보낼 폴더를 고른다.
2. 미리보기 화면에서 내보낼 파일과 뺄 파일을 이유와 함께 보여 준다(메모, 사용 안 함, 항목 아님).
3. 규칙 검사에 오류가 있으면 함께 보여 준다(예: 사용 중인 메인 프롬프트가 둘, 용량 초과). 오류가 있어도 내보낼 수는 있다.
4. "내보내기"를 누르면 작업 대기열에 들어간다. 내보낼 폴더에 파일이 있으면 덮어쓰기 전에 확인을 받고, 이번에 내보내지
   않는 파일이 남아 있으면 목록으로 보여 준다(지우지는 않는다).
5. 내보낼 때 `export` 스냅샷을 만들지 고를 수 있다. 끝나면 "폴더 열기" 알림이 뜬다.

## 화면

### 작품 선택

```text
┌───────────────────────────────────────────────────────────┐
│ [작품 찾기          ]  태그 ▾  정렬: 최근 연 순 ▾          │
│                              [가져오기] [샘플 작품] [새 작품] │
│ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐          │
│ │ 청원고      │ │ 던전 기록   │ │ 작은 카페   │          │
│ │ W001 · 2시간 전│ W002 · 어제 │ │ W003 · 3일 전│          │
│ │ generic 학원물│ │ 판타지     │ │ 샘플        │          │
│ │ 항목 14 · 21KB│ │ 항목 32 · 58KB│ 항목 9 · 12KB│          │
│ └─────────────┘ └─────────────┘ └─────────────┘          │
└───────────────────────────────────────────────────────────┘
```

- 카드: 작품 이름, ID, 마지막으로 연 시각, 태그(플랫폼 프리셋 연결 태그는 강조색), 항목 수, 사용 중 항목 용량 합계.
- 카드 메뉴: 열기, 이름 바꾸기, 복제, 폴더 열기(탐색기), 지우기.
- 검색은 이름·ID·태그로 찾는다. 태그로 거를 수 있다. 정렬: 최근 연 순, 이름순, 만든 순.

### 새 작품 · 복제 · 가져오기 창

화면 가운데 작은 창. 입력란 아래에 오류를 바로 보여 준다(예: "같은 이름의 작품이 있어요", "이미 쓰는 ID예요. W004를
써 보세요").

### 작품 설정

| 묶음 | 내용 |
|---|---|
| 기본 | ID, 규모, 언어. 작품 이름은 폴더 이름이라 작품 선택 화면에서 바꾼다 |
| 태그 | 칩 입력(엔터로 추가). 플랫폼 프리셋과 같은 태그는 강조색과 연결 표시. 순서를 끌어서 바꾼다(상속 순서) |
| 플랫폼 규칙 | 상속받은 값을 표로 보여 준다. 각 값 옆에 출처(기본값 / 프리셋 이름 / 작품). 값을 고치면 `overrides`에 들어가고, "상속값으로 되돌리기"로 뺀다 |
| 섹션 이름 | 키별 제목. 언어 기본값을 회색으로 보여 주고, 바꾼 것만 `character_sections`에 저장 |

### 상태

- **비어 있음**: 작품이 없으면 카드 자리에 "첫 작품을 만들어 보세요"와 "샘플 작품 열기", "새 작품".
- **불러오는 중**: 카드 자리에 자리표시 카드.
- **오류**: 읽을 수 없는 작품 폴더(`.atelierx/work.json`이 깨짐 등)는 카드에 오류 표시와 "폴더 열기"만 둔다. 앱보다 새 버전
  작품은 "읽기 전용" 표시.

## 데이터

| 파일 | 읽기·쓰기 | 형식 |
|---|---|---|
| `data/works/<작품>/.atelierx/work.json` | 읽기·쓰기 | [data-model.md work.json](../data-model.md#작품-폴더) |
| `data/works/<작품>/` 사용자 트리 | 가져오기·내보내기·복제 | [항목](../data-model.md#항목) |
| `data/.trash/` | 지우기 | [휴지통](../data-model.md#휴지통) |
| `data/platforms/*/preset.json` | 읽기 | [플랫폼 프리셋](../data-model.md#플랫폼-프리셋) |
| `config/settings.json`의 `default_platform_preset` | 읽기 | [위치](../data-model.md#위치) |
| `state/ui.json`의 마지막으로 연 작품·시각 | 읽기·쓰기 | 화면 상태 |
| `app/samples/<샘플>/` | 읽기 | 앱에 포함된 샘플 작품. 업데이트 때 함께 바뀐다 |

## 규칙

- 작품 이름은 폴더 이름 규칙을 따른다(Windows 금지 문자 불가, 데이터 루트 안에서 대소문자 무시하고 유일).
- 작품 ID는 데이터 루트 안에서 유일하다. 가져오기·복제·되살리기에서 겹치면 새 ID를 고르게 한다.
- 작품 ID를 바꾸는 것은 연결 갱신 작업이다(출력 폴더 경로가 작품 ID를 쓰므로). 영향받는 곳을 보여 주고 확인을 받는다.
- 작품 폴더를 옮기거나 지우는 일은 앱 안에서만 한다. 작품이 열려 있는 동안 앱 밖에서 폴더가 사라지면 작품 선택 화면으로
  돌아가고 알린다.
- 가져오기는 기존 작품을 덮어쓰지 않는다. 항상 새 작품을 만든다.
- 내보내기는 `.atelierx/`와 인증 정보를 절대 포함하지 않는다. 내보낸 폴더의 다른 파일은 지우지 않는다.
- 폴더 선택은 데스크톱 창에서는 OS 폴더 선택 창, 개발 중 브라우저에서는 경로 입력으로 대신한다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works` | 작품 목록(카드 정보) |
| `POST /api/works` | 새 작품 `{name, id, tags, scale, language}` |
| `POST /api/works/{id}/duplicate` | 복제 `{name, id}` |
| `PATCH /api/works/{id}` | 이름 바꾸기, 작품 설정 저장 |
| `POST /api/works/{id}/change-id` | ID 바꾸기(영향 범위 미리보기 → 확인 후 실행) |
| `DELETE /api/works/{id}` | 지우기(휴지통으로) |
| `GET /api/samples` · `POST /api/samples/{name}/install` | 샘플 목록, 샘플 복사본 만들기 |
| `POST /api/works/import/inspect` · `POST /api/works/import` | 가져올 작품 폴더 살펴보기(이름, ID, 형식 버전), 가져오기 |
| `GET /api/works/{id}/export/preview` · `POST /api/works/{id}/export` | 내보내기 미리보기, 내보내기(작업 대기열) |
| `GET /api/works/{id}/settings/effective` | 상속을 반영한 플랫폼 규칙 값과 각 값의 출처 |

작품은 API에서 ID로 가리킨다(폴더 이름은 바뀔 수 있으므로).

## 단계

- **1단계**: 작품 선택, 새 작품, 샘플 작품, 복제, 이름 바꾸기, 지우기, 작품 설정, 가져오기(AtelierX 작품 폴더),
  내보내기.
- **이후**: 일반 폴더·다른 형식 가져오기(다른 곳에서 쓰던 원고, 다른 도구의 캐릭터 카드 등. 필요가 생길 때 정한다), 작품 단위
  백업 묶음(zip) 만들기.
