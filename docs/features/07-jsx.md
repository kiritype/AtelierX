# JSX

## 목적

챗봇 화면에 쓰는 JSX 컴포넌트를 작성하고, 예시 props로 미리 보고, 플랫폼 규칙에 맞는지 검사한다. 챗봇이 응답에 컴포넌트를
넣도록 메인 프롬프트·로어북에 들어갈 **프롬프트용 문구**(양식, 예시, 필드 설명)를 LLM으로 만들어 넣을 수 있다. 테스트에서는
응답 속 컴포넌트를 실제로 그려 본다. JSX 항목의 파일 형식은 [data-model.md 항목](../data-model.md#항목).

형식의 원본은 프롬프트·로어북 본문에 사용자가 넣은 문구 하나다. 앱은 컴포넌트별 형식 정보를 따로 저장하지 않는다.

## 사용 흐름

### 컴포넌트 만들기

1. 파일 트리에서 새 파일 `상태창.jsx`(또는 `.md`를 만든 뒤 종류를 JSX로 바꿈).
2. [코드] 탭에서 상단 폼(ID, 기본 예시 props, 사용)을 채우고 소스를 쓴다. 오른쪽에 `jsx.md` 가이드라인(플랫폼 JSX 사용 규칙)을
   참고 패널로 띄울 수 있다.
3. 저장하면 정적 검사가 돌고 결과가 보조 패널 "검사"에 나온다.

### 미리보기와 예시 props

1. [미리보기·props] 탭: 왼쪽에 렌더링 결과, 오른쪽에 예시 목록과 "미리보기 입력".
2. 예시를 추가·복제·이름 바꾸기·지우기 한다. 예시는 응답에 쓰는 그대로의 호출이다(`<Asset c='C001' o='001' />`). 새 예시는
   `<이름 />`으로 시작한다. 호출을 여러 개 쓰거나 응답 문장째 붙여 넣으면 찾은 호출마다 그린다.
   입력 아래에 읽은 props(속성별 값)와 읽지 못한 속성을 보여 준다. 읽는 방식은 실제 응답과 같은 플랫폼 표기 규칙이다.
3. 예시를 바꾸면 미리보기가 바로 바뀐다. 소스를 고치고 저장해도 바로 바뀐다.
4. 화면 폭 프리셋(좁게 / 보통 / 넓게)과 밝은·어두운 배경을 바꿔 본다.
5. 플랫폼이 제공하는 함수(플랫폼 프리셋 `jsx.globals`)는 미리보기에서 대역으로 동작한다. 대역이 받은 호출은 아래 "호출 기록"에
   쌓인다(예: `sendMessage("다음 날로")`).
6. 실행 중 오류는 미리보기 위에 오류 상자로 보여 주고, 해당 소스 줄로 갈 수 있다.
7. 응답 확인: 챗봇 응답 문장을 미리보기 입력에 붙여 넣으면 그 안의 호출을 플랫폼 표기 규칙대로 읽어 모두 그려 본다.

### 프롬프트용 문구 만들기

1. [미리보기·props] 탭에서 "프롬프트용 문구 만들기".
2. 작은 창에서 고른다.
   - 기준 예시 props(기본: 이 컴포넌트의 기본 예시)
   - 넣을 곳: 메인 프롬프트 / 기존 로어북 항목 / 새 로어북 항목
   - 추가 요청(선택). 예: "호감도는 대화가 끝날 때만 바꾸게 해 줘"
3. LLM 작업(`jsx_prompt`)이 컴포넌트 소스, 예시 props, 플랫폼 표기 규칙, 가이드라인(`platform.md`, `jsx.md`)을 보고 문구를
   만든다. 문구에는 출력 양식, 예시, 각 필드의 뜻, 언제 어떻게 갱신하는지가 들어간다.
4. 결과는 임시 항목으로 들어가고 보조 패널 "검토"에서 확인·편집한다. 문구 속 예시는 바로 아래 "문구 속 예시 검사"를 거친다.
5. "넣기" → 위치를 고른다: 커서 위치 / 본문 끝 / 특정 제목 아래. 새 로어북 항목이면 이름과 폴더를 정한다. 넣기 직전에
   `before_llm` 스냅샷을 만든다.

예시 결과:

```text
## 상태창
응답 맨 끝에 아래 형식으로 상태창을 한 번 출력한다.
<상태창 data='{"location": "장소", "time": "HH:MM", "affinity": {"캐릭터 ID": 호감도}}' />
- location: 지금 장면의 장소
- time: 장면 속 시각(24시간)
- affinity: 이번 대화에서 바뀐 캐릭터만 적는다
예: <상태창 data='{"location": "교실", "time": "08:40", "affinity": {"C001": 12}}' />
```

넣은 뒤로는 이 문구가 형식의 원본이다. 사용자가 자유롭게 고친다.

### 문구 속 예시 검사

- 메인 프롬프트·로어북 본문에 작품의 JSX 항목 이름과 같은 요소(`<상태창 … />`)가 있으면, 앱이 플랫폼 표기 규칙대로 읽어 본다.
  읽을 수 없거나(속성 JSON이 깨짐 등) 컴포넌트가 그 props로 그려지지 않으면 보조 패널 "검사"에 알린다.
- 양식 줄처럼 자리표시 값이 들어간 요소(예: `"HH:MM"`, `캐릭터 ID`)는 JSON으로 읽히지 않을 수 있다. 읽을 수 없는 요소는
  경고로만 알리고, "예:"처럼 실제 값이 들어간 요소를 그려 본다.
- 본문 속 예시를 "예시 props로 가져오기"로 이 컴포넌트의 예시 props에 추가할 수 있다.

### 테스트 화면에서

- 응답에서 작품의 JSX 항목 이름과 같은 요소를 찾아 그 자리에 렌더링한다. 응답마다 "원문 / 렌더링" 전환.
- 요소를 읽을 수 없으면 원문을 그대로 두고 경고를 붙인다. 읽은 props에 기본 예시 props의 필드가 빠져 있으면 정보 수준으로
  알린다(예: "time 없음").
- 응답에서 꺼낸 props를 "예시로 저장"하면 이 컴포넌트의 예시 props에 추가된다.
- 테스트 화면의 불러온 내용 패널에 이 응답에서 호출된 컴포넌트를 표시한다([08](08-chat-test.md)).

### 예외 흐름

- **문법 오류**: 미리보기 대신 오류 위치를 보여 준다. 마지막으로 성공한 렌더링은 흐리게 남겨 둔다.
- **무한 반복·멈춤**: 미리보기가 일정 시간 응답하지 않으면 멈추고 "미리보기 다시 시작".
- **호출을 찾지 못함**: "<이름 … /> 호출을 찾지 못했습니다"를 보여 준다. 읽지 못한 속성은 속성 이름과 이유를 함께 보여 준다.
- **플랫폼 표기 규칙이 없음**: 연결된 플랫폼 프리셋에 `jsx.response`가 없으면 앱 기본값(`element`, `json_lenient`, 치환 없음)으로 읽는다.

## 응답 속 컴포넌트 표기

챗봇 응답에 컴포넌트가 어떤 표기로 들어가는지는 컴포넌트가 아니라 **플랫폼**이 정한다. 그래서 플랫폼 프리셋의 `jsx.response`에
둔다([data-model.md 플랫폼 프리셋](../data-model.md#플랫폼-프리셋)).

응답 속 요소 이름은 **JSX 항목의 파일 이름**(확장자 제외)이다. `UI/StatusPanel.jsx`는 응답에서 `<StatusPanel … />`로 찾는다.
그래서 최상위 함수 이름도 파일 이름과 같게 쓴다(다르면 정적 검사 경고). 파일 이름을 바꾸면 본문 속 요소 이름도 바꿔야 하므로,
이름을 바꿀 때 "본문의 요소 이름도 함께 바꾸기"를 제안한다(이름 일괄 변경 흐름, [04](04-authoring.md)).

| 설정 | 내용 |
|---|---|
| `syntax` | 응답 속 표기. 처음 범위는 `element`(컴포넌트 요소를 응답에 직접 씀: `<이름 속성='…' />`) 하나. 다른 표기는 필요해질 때 추가한다 |
| `attribute_format` | 속성 값 읽기: `text`(따옴표 안을 쓴 그대로 문자열로), `json_lenient`(JSON으로 읽되 끝 쉼표·작은따옴표 허용, JSON 모양이 아닌 `C001`·`001` 같은 값은 쓴 그대로), `json`(엄격한 JSON). 설정 → 플랫폼 프리셋의 "응답 속 컴포넌트의 속성 값"에서 고른다 |
| `decode` | 읽기 전에 적용할 치환 표. 플랫폼이 특수 문자를 자체 표기로 바꿔 쓰는 경우에 쓴다 |

## 화면

### [미리보기·props] 탭

```text
┌ 상태창.jsx ─ [코드] [미리보기·props] ─────────────────────────────────────────┐
│ 폭 [좁게|보통|넓게]  배경 [밝게|어둡게]                    [프롬프트용 문구 만들기] │
├──────────────────────────────────────┬───────────────────────────────────────┤
│                                      │ 예시   [basic ▾] [+] [복제]           │
│        ( 렌더링 결과 )               │ 미리보기 입력                         │
│        (호출마다 하나씩)             │ <StatusPanel data='{"day": 1}' />     │
│                                      │ 읽은 props (JSON(느슨하게))           │
│                                      │ data: {"day":1}                       │
├──────────────────────────────────────┴───────────────────────────────────────┤
│ 호출 기록: sendMessage("다음 날로")                                           │
│ 쓰이는 곳: 메인.md (예시 1개 ✓)                                               │
└──────────────────────────────────────────────────────────────────────────────┘
```

- "쓰이는 곳": 이 컴포넌트 요소가 들어 있는 본문 목록과 문구 속 예시 검사 결과. 누르면 그 위치로 간다.

### 상태

- **비어 있음**: 예시 props가 없으면 "예시 props를 만들어 미리 보세요"와 "빈 예시 만들기". 쓰이는 곳이 없으면 "아직 프롬프트에
  넣지 않았어요 — 프롬프트용 문구 만들기".
- **불러오는 중**: 미리보기 준비 중 표시.
- **오류**: 문법·실행 오류 상자.

## 규칙

### 정적 검사

저장할 때마다 돈다. 결과는 보조 패널 "검사".

| 검사 | 수준 | 기준 |
|---|---|---|
| 문법 | 오류 | JSX로 읽을 수 없음 |
| 금지 문법 | 오류 | 플랫폼 프리셋 `jsx.forbid`(예: `import`, `export`) |
| 쓸 수 없는 훅 | 오류 | `jsx.hooks`에 없는 React 훅 사용 |
| 정의되지 않은 이름 | 경고 | 소스에서 정의하지도, 플랫폼 제공 함수(`jsx.globals`)에도 없는 전역 이름 |
| 컴포넌트 모양 | 경고 | 최상위에 함수 컴포넌트가 하나가 아님, 또는 그 함수 이름이 파일 이름(확장자 제외)과 다름 |
| 문구 속 예시 | 경고 | 본문 속 이 컴포넌트 요소를 읽을 수 없거나 그려지지 않음 |
| 쓰이지 않음 | 정보 | 사용 중인 본문 어디에도 이 컴포넌트 요소가 없음 |

### 미리보기 실행

- 미리보기는 격리된 영역(외부 네트워크 없음, 앱 데이터 접근 없음)에서 실행한다. 컴포넌트가 할 수 있는 일은 받은 props로 그리기와
  플랫폼 제공 함수 대역 호출뿐이다.
- 렌더링에 쓰는 React 등 실행 환경은 앱에 들어 있다(실행 중 내려받지 않음). 상세는 architecture.md.
- 플랫폼 제공 함수 대역의 동작은 프리셋 `jsx.globals`에 적힌 대로: `log`(호출만 기록), `return:<값>`(정한 값을 돌려줌),
  `random`(무작위 값).

### 프롬프트용 문구

- LLM에는 컴포넌트 소스, 기준 예시 props, 플랫폼 표기 규칙, 가이드라인, 추가 요청만 보낸다. 다른 항목의 본문은 보내지 않는다.
- 문구는 넣기 전까지 원본을 바꾸지 않는다. 넣기는 사람이 누를 때만 한다.
- 앱 고정 지시에 "예시에는 실제 값을 넣고, 플랫폼 표기 규칙대로 읽히게 쓸 것"을 넣는다.

### 내보내기

- 내보낼 때는 머리 주석(메타데이터)을 뗀 소스만 나간다. 예시 props는 내보내지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works/{id}/jsx/{jid}/props` · `PUT …/props/{name}` · `DELETE …/props/{name}` | 예시. `PUT` 본문은 호출 원문 그대로(`.txt`로 저장, 같은 이름의 이전 `.json`은 지움), 비어 있으면 거절. `POST …/jsx/elements`는 글 속 호출을 작품의 표기 규칙으로 읽는다(초안 검토) |
| `POST /api/works/{id}/jsx/{jid}/try` | 응답 문장으로 시험 `{text}` → 찾은 요소, 읽은 props, 오류 |
| `GET /api/works/{id}/jsx/{jid}/usages` | 쓰이는 곳과 문구 속 예시 검사 결과 |
| `POST /api/works/{id}/jsx/{jid}/prompt-text` | 프롬프트용 문구 만들기 `{props, target, feedback?}` → 작업 |
| `POST /api/works/{id}/drafts/{did}/insert` | 문구 넣기 `{item, position}` 또는 `{new_item: {path}}` |
| `GET /api/works/{id}/jsx/{jid}/check` | 정적 검사 결과 |

미리보기 렌더링과 소스 변환(JSX → 실행 가능한 코드)은 화면 쪽에서 한다.

## 단계

- **0단계(골격)**: [소스]·[미리보기·props] 탭, 예시 props 고르기·추가·복제·지우기·기본 지정과 JSON 편집(잘못된 JSON은 오류 표시,
  올바르면 자동 저장), 편집 중인 소스로 바로 그리는 격리된 미리보기(폭·배경 전환), 플랫폼 제공 함수 대역과 호출 기록, 실행·문법
  오류와 줄 번호, 응답이 없으면 미리보기 다시 시작, 테스트 화면의 응답 렌더링. 정적 검사는 정규식 수준(금지 문법, 쓸 수 없는 훅,
  컴포넌트 모양, 쓰이지 않음). 응답으로 시험·프롬프트용 문구는 버튼만 둔다.
- **3단계(구현)**: 프롬프트용 문구 만들기(기준 예시·추가 요청 → 검토에서 고치기, 문구 속 요소 읽기 결과 표시, 넣을 곳: 기존 항목의
  끝·제목 아래 또는 새 로어북 항목), 응답으로 시험(붙여 넣은 응답의 요소를 그려 봄), 쓰이는 곳(본문별 요소 수와 읽을 수 없는 요소),
  규칙 검사 "문구 속 예시"(읽을 수 없는 요소를 그 본문에 경고).
- **4단계**: [코드]·[미리보기·props] 탭, 예시 props 관리, 격리된 미리보기, 플랫폼 제공 함수 대역과 호출 기록, 정적 검사,
  응답으로 시험, 프롬프트용 문구 만들기·넣기, 문구 속 예시 검사, 테스트 화면의 응답 렌더링.
- **이후**: 미리보기에서 글자를 직접 고치면 소스에 반영, `element` 밖의 응답 표기, `jsx.md`를 쓰는 LLM 코드 수정 제안.
- **테스트하며 정할 것**: 응답 속 props의 엄격한 검사(배열 길이, 값 범위, 필수 필드 등). 지금은 기본 예시 props와 필드 유무만
  비교한다. 실제 작품으로 테스트 화면에서 시험해 보며 어떤 조건이 필요한지 정하고, 그때 검사 조건을 두는 방법(예: 예시 props 옆의
  선택 파일)도 함께 정한다.
