# 스냅샷 · 휴지통

## 목적

작품의 지난 상태를 기록하고, 비교하고, 되돌린다. 실제 플랫폼에 올린 시점에 배포 표시를 붙여 "배포 이후 무엇이 바뀌었나"를
볼 수 있게 한다. 지운 것을 되살리거나 완전히 지우는 휴지통도 여기서 다룬다. 형식은 [data-model.md 스냅샷](../data-model.md#스냅샷)과
[휴지통](../data-model.md#휴지통).

## 사용 흐름

### 스냅샷이 만들어지는 때

| 때 | `reason` | 누가 |
|---|---|---|
| 저장한 변경이 있고 마지막 `save` 스냅샷에서 일정 시간(기본 10분)이 지남. 작품을 닫거나 앱을 끌 때도 | `save` | 자동 |
| LLM 결과를 원본에 쓰기 직전 | `before_llm` | 자동 |
| 여러 파일을 한꺼번에 바꾸기 직전(ID 바꾸기, 폴더 이동·이름 변경, 휴지통에서 되살리기, 형식 변환) | `before_bulk` | 자동 |
| 되돌리기 직전 | `before_restore` | 자동 |
| 가져오기 직후 | `import` | 자동 |
| 내보낼 때(내보내기 창에서 선택) | `export` | 선택 |
| 사용자가 "스냅샷 만들기"를 누름(이름 붙이기 가능) | `manual` | 직접 |

- 마지막 스냅샷과 내용이 같으면 새로 만들지 않는다.

### 이력 보기

1. 활동 막대의 이력을 누르면 사이드 패널에 스냅샷 목록이 날짜별로 보인다.
2. 항목: 시각, 이유 아이콘, 이름, 바뀐 파일 수, 배포 표시. 거르기: 전체 / 직접 만든 것 / 배포 표시만.
3. 스냅샷을 누르면 편집 영역에 비교 탭이 열린다(그 스냅샷 ↔ 바로 앞 스냅샷).

### 비교

1. 비교 탭 왼쪽에 바뀐 파일 목록(추가, 수정, 삭제, 이름 바뀜·이동). 이름 바뀜은 항목 ID로 알아낸다.
2. 파일을 누르면 오른쪽에 차이를 보여 준다. 메타데이터는 필드 단위("키워드: 반장 추가"), 본문은 줄 단위로 위아래로
   보여 준다(빠진 줄 `-`, 들어간 줄 `+`).
3. **차이 표시 켬/끔**: 비교 탭 위의 토글로 차이 표시를 끌 수 있다. 끄면 고른 스냅샷의 파일 내용을 차이 표시 없이 그대로
   보여 준다(읽기 전용). 긴 본문을 원래 모습으로 읽을 때 쓴다. 마지막 선택을 기억한다(`state/ui.json`).
4. 비교 대상은 바꿀 수 있다: 바로 앞 스냅샷 / 지금 상태 / 다른 스냅샷 / 마지막 배포 표시.

### 파일 하나의 이력

파일 트리에서 우클릭 → "이력 보기". 그 항목(ID 기준이라 이름을 바꿨어도 이어짐)이 바뀐 스냅샷만 모아 보여 준다.

### 되돌리기

- **파일 하나**: 비교 탭에서 파일을 고르고 "이 파일 되돌리기". 지운 파일이면 다시 만든다.
- **작품 전체**: 스냅샷 메뉴 → "이 시점으로 되돌리기". 확인 창에 바뀔 파일 수, 되살아날 파일 수, 치워질 파일 수를 보여 준다.
- 어느 경우든 되돌리기 직전에 `before_restore` 스냅샷을 만들므로, 되돌리기 자체도 되돌릴 수 있다.
- 작품 전체를 되돌릴 때 그 스냅샷 이후에 생긴 항목은 지우지 않고 휴지통으로 옮긴다(한 묶음).
- 되돌리기 대상은 사용자 트리의 항목(`.md`·`.jsx`)과 스냅샷에 들어가는 `.atelierx/` 파일(작품 설정, 관계도, 이미지 데이터 등)이다.
  이력, 휴지통, 임시 항목, 실행 기록, 항목이 아닌 파일, 출력 루트의 큰 파일은 건드리지 않는다.
- 열린 탭에 저장하지 않은 변경이 있으면 먼저 저장할지 묻는다.

### 배포 표시

1. 스냅샷 메뉴 → "배포 표시" → 메모 입력(예: "1.2 배포"). 내보내기 창에서 "스냅샷 만들고 배포 표시"를 함께 고를 수도 있다.
2. 상태 표시줄이나 이력 패널에서 "마지막 배포 이후 바뀐 것"을 바로 열 수 있다.
3. 배포 표시는 지울 수 있다. 지우면 그 스냅샷은 다시 자동 정리 대상이 될 수 있다.

### 정리

- 앱을 켤 때(하루 한 번) 자동 정리: 오래된 `save` 스냅샷만 지운다(기본: 최근 200개 + 그 이전은 하루 하나씩 30일까지).
  어느 스냅샷에서도 쓰지 않는 객체를 지운다.
- `manual`, `before_bulk`, 배포 표시된 스냅샷은 자동 정리하지 않는다.
- 설정 화면에서 작품별 이력 크기를 보여 주고 "지금 정리"를 할 수 있다. 직접 만든 스냅샷은 사용자가 하나씩 지울 수 있다
  (배포 표시된 것은 표시를 먼저 지워야 한다).

### 휴지통

- **작품 안 휴지통**: 활동 막대의 휴지통. 지운 묶음 목록(지운 시각, 종류, 원래 경로, 크기).
- **지운 작품**: 작품 선택 화면의 "휴지통".
- 묶음마다 "되살리기", "완전 삭제". 위에 "휴지통 비우기"(전체 크기를 보여 주고 확인).
- 되살리기: 원래 경로로 옮긴다. 경로나 ID가 겹치면 새 이름·새 ID를 고르게 한다. 되살리기 전에 `before_bulk` 스냅샷을 만든다.
- 완전 삭제는 확인 문구를 받은 뒤 한다. 캐릭터 이미지 데이터가 들어 있는 묶음이면 출력 루트의 해당 캐릭터 폴더도 출력 휴지통으로 옮길지 따로 묻는다. 출력 휴지통(생성 이미지 등)도 이 화면에서 함께 다룬다.

## 화면

### 이력 패널 (사이드 패널)

```text
이력                       [스냅샷 만들기] [전체 ▾]
오늘
  15:00  ✋ 압축 후보 채택 전        3 파일
  14:30  💾 저장                     5 파일
  13:10  🚀 1.2 배포  [배포]         —
어제
  22:40  ⇄ ID 바꾸기 전              4 파일
  …
마지막 배포 이후 바뀐 것 보기 →
```

### 비교 탭

```text
┌ 비교: 14:30 저장 ↔ 지금 ── 대상 [지금 ▾]  차이 표시 [켬] ┐
│ 바뀐 파일            │ 인물/한서윤.md                    │
│ ~ 인물/한서윤.md     │ 메타데이터: 키워드 + "반장"       │
│ + 세계관/동아리.md   │ 본문:                              │
│ - 메모/초안.md       │ - 검은 단발머리                    │
│ → UI/상태창.jsx      │ + 검은 긴 생머리                   │
│   (이전: 상태.jsx)   │          [이 파일 되돌리기]        │
└──────────────────────┴───────────────────────────────────┘
```

### 휴지통

목록 한 줄에 묶음 하나. 펼치면 들어 있는 파일 경로. 묶음 오른쪽에 "되살리기", "완전 삭제".

### 상태

- **비어 있음**: 이력이 없으면 "아직 스냅샷이 없어요. 저장하면 자동으로 만들어져요"와 "스냅샷 만들기". 휴지통이 비면 "비어 있어요".
- **불러오는 중**: 비교를 계산하는 동안 파일 목록 자리에 진행 표시.
- **오류**: 객체 파일이 없거나 깨진 스냅샷은 목록에 오류 표시. 그 스냅샷으로는 되돌릴 수 없고, 비교는 읽을 수 있는 파일만 보여 준다.

## 데이터

| 파일 | 읽기·쓰기 | 형식 |
|---|---|---|
| `.atelierx/history/` | 읽기·쓰기 | [스냅샷](../data-model.md#스냅샷) |
| `.atelierx/trash/`, `data/.trash/` | 읽기·쓰기 | [휴지통](../data-model.md#휴지통) |
| 사용자 트리, 스냅샷 대상 `.atelierx/` 파일 | 되돌리기 때 쓰기 | [작품 폴더](../data-model.md#작품-폴더) |
| `config/settings.json` | 읽기 | 저장 묶음 간격, 자동 정리 기준 |
| `cache/` | 읽기·쓰기 | 파일 해시 캐시(크기·수정 시각 → 해시). 지워도 다시 계산 |

## 규칙

- 스냅샷은 객체를 먼저 쓰고 마지막에 스냅샷 파일을 쓴다. 중간에 끊기면 스냅샷 파일이 없으므로 없던 일이 된다
  (남은 객체는 정리 때 지워진다).
- 해시는 파일 바이트 그대로 계산한다(줄바꿈·인코딩 변환 없음). 크기·수정 시각이 같은 파일은 캐시된 해시를 쓴다.
- 되돌리기는 디스크에 쓰기 전에 대상 파일 목록과 결과를 다시 확인하고, 쓰기는 파일마다 임시 파일 → 바꿔 넣기로 한다.
- 되돌리기·되살리기 뒤에는 ID 겹침 등 규칙 검사를 다시 돌린다.
- 이력과 휴지통은 내보내기·스냅샷에 넣지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/works/{id}/snapshots` | 목록(거르기: 이유, 배포 표시) |
| `POST /api/works/{id}/snapshots` | 직접 만들기 `{label}` |
| `GET /api/works/{id}/snapshots/{sid}/diff?against=` | 비교(`against`: 스냅샷 id, `current`, `release`) |
| `GET /api/works/{id}/history?item=` | 항목 하나(ID)의 이력 |
| `POST /api/works/{id}/restore` | 되돌리기 `{snapshot, paths?}`(paths 없으면 작품 전체) |
| `PATCH /api/works/{id}/snapshots/{sid}` | 이름·배포 표시 바꾸기 |
| `DELETE /api/works/{id}/snapshots/{sid}` | 직접 만든 스냅샷 지우기 |
| `POST /api/works/{id}/history/prune` | 지금 정리 |
| `GET /api/works/{id}/trash` · `GET /api/trash` | 작품 안 휴지통, 지운 작품 |
| `POST …/trash/{tid}/restore` · `DELETE …/trash/{tid}` · `DELETE …/trash` | 되살리기, 완전 삭제, 비우기 |

## 단계

- **1단계**: 자동·직접 스냅샷, 이력 패널, 비교(파일 목록, 메타데이터 필드 차이, 본문 줄 차이), 파일·작품 전체 되돌리기,
  배포 표시와 "마지막 배포 이후", 자동 정리, 휴지통 전체.
- **구현 메모**: 저장 묶음(`save`)은 항목을 저장할 때 마지막 `save`에서 설정 간격(기본 10분)이 지났으면 만들고, 작품을 닫거나
  잠글 때도 만든다(바뀐 게 없으면 만들지 않음). 자동 정리는 앱을 켤 때 하루 한 번: 최근 `keep_recent`개 + 그 이전은
  하루 하나씩 `daily_days`일까지 남기고, 지운 스냅샷을 가리키던 `parent`는 남은 조상으로 잇고, 아무도 안 쓰는 내용 파일을 지운다.
- **이후**: 단어 단위 차이 강조, 두 스냅샷 사이 변경을 다른 작품에 옮기기.
