# 압축

## 목적

메인 프롬프트와 로어북 항목을 플랫폼 용량 제한 안으로 줄인다. LLM이 압축 후보를 만들고, 사람이 원본과 전문을 나란히 놓고
비교해 필요한 부분만 골라 채택한다. 빠진 정보가 없는지 검사해서, 줄이는 과정에서 설정이 사라지지 않게 한다. LLM 호출 방식은
[03-llm](03-llm.md).

## 블록

압축의 비교·채택 단위는 **블록**이다. 앱이 원문을 블록으로 나누고, LLM은 블록 번호별로 결과를 돌려준다.

- 블록은 빈 줄로 나뉜 덩어리 하나다: 문단, 목록 묶음, 코드 블록, 표, 제목 줄. 제목은 단계(`#`, `##`, `###` …)와 관계없이 한 줄이
  블록 하나다. 그래서 메인 프롬프트처럼 `#`을 쓰든, 제목이 아예 없든 같은 방식으로 동작한다.
- LLM에는 블록마다 번호를 붙여 보낸다.

  ```text
  [B1] # 세계관
  [B2] 이 세계는 …
  [B3] - 규칙 1 …
       - 규칙 2 …
  ```

- LLM은 같은 번호로 돌려준다. 이웃한 블록을 합칠 수 있고(`[B3-B4]`), 지울 수 있다(`[B5] (삭제)`). 순서는 바꾸지 않는다.
  이 응답 형식은 앱 고정 지시로 정하고 앱이 검사한다.
- 블록 나누기는 앱이 하므로 LLM이 문단을 합치거나 줄여도 원본의 어느 부분에 대응하는지 번호로 추적한다.

## 사용 흐름

### 압축 시작

1. 시작하는 곳은 세 군데다.
   - 편집 탭 [본문]에서 메뉴 → "압축". 본문 일부를 선택한 채로 시작하면 그 부분만 압축한다.
   - 보조 패널 "검사"의 용량 초과 항목 옆 "압축".
   - 작품 단위: 상단 바 메뉴 → 도구 → "용량을 넘는 항목 압축". 대상 항목 목록을 보여 주고 고르게 한다.
2. 압축 설정 창이 열린다.

| 설정 | 기본값 | 설명 |
|---|---|---|
| 목표 용량 | 플랫폼 제한의 95% | 바이트·글자·토큰은 플랫폼 프리셋의 세는 방식을 따른다. 직접 숫자나 "지금의 70%"처럼 비율로 바꿀 수 있다 |
| 후보 수 | 2 | 1~3 |
| 그대로 둘 부분 | 없음 | 제목을 고르면 그 제목부터 같거나 더 높은 단계의 다음 제목 전까지를 잠근다. 본문을 드래그로 골라 잠글 수도 있다. 잠긴 블록은 LLM에 "바꾸지 말 것"으로 보내고 결과에서도 원본을 쓴다 |
| 가이드라인 | `platform.md` + `compression.md` | 찾은 위치(작품 / 프리셋 / 전역)를 보여 준다. 참고 가이드라인을 추가로 고를 수 있다 |
| 연결·모델 | 작업별 기본(`compression`) | 이번 한 번만 바꿀 수 있다 |

3. "후보 만들기" → 예상 토큰·맥락 확인([03-llm](03-llm.md)) → 작업 대기열. 여러 항목이면 항목마다 작업 하나.
4. 끝나면 임시 항목이 생기고 보조 패널 "검토" 탭과 활동 막대의 임시 항목에 배지가 뜬다.

### 검토와 채택

1. "검토" 탭에서 압축 결과를 누르면 편집 영역에 **검토 탭**이 열린다.
2. 검토 탭은 **전문을 처음부터 끝까지 한 흐름으로** 보여 준다. 블록 하나가 한 줄이고, 원본 | 후보 1 | 후보 2 | 채택안을
   나란히 맞춘다. LLM이 합친 블록은 원본 쪽 블록들을 한 줄로 묶어 보여 준다.
3. 블록마다 무엇을 쓸지 고른다: 원본 / 후보 1 / 후보 2. 처음에는 모든 블록이 후보 1로 골라져 있다. 고른 결과를 합친
   **채택안**의 전체 용량과 목표 대비를 위에 보여 준다.
4. 여러 블록을 한꺼번에 고르는 단축 동작: "이 제목 아래 전부 후보 2로", "전체를 원본으로" 등.
5. 채택안은 직접 고칠 수 있다(아래 "채택안 편집").
6. 누락 검사 결과를 확인한다(아래).
7. "채택" → 방식을 고른다.
   - **원본에 덮어쓰기**: 원본 본문을 채택안으로 바꾼다.
   - **새 파일로 저장**: 원본 옆에 같은 종류의 새 항목(예: `메인 (압축).md`)을 만든다. 원본과 새 항목 중 어느 쪽을 사용할지 고른다.
8. 쓰기 직전에 `before_llm` 스냅샷을 만든다. 임시 항목은 `applied`가 된다.

### 다시 만들기

- 검토 탭의 "다시 만들기"에 요청을 덧붙일 수 있다(예: "말투 예시는 남겨 줘"). 같은 임시 항목에 새 후보가 추가되고, 이전 후보도
  비교에 남는다.
- 블록 몇 개만 골라 "이 부분만 다시"를 할 수도 있다. 고른 블록만 다시 보내고 결과는 새 후보 열로 붙는다.

### 누락 검사

후보가 만들어지면, 그리고 채택안이 바뀔 때마다 자동으로 **규칙 기반 검사**를 한다. 원본에는 있는데 채택안에 없는 것을 찾는다.

| 찾는 것 | 예 | 수준 |
|---|---|---|
| 캐릭터 섹션 제목 | 캐릭터의 `## 외모`, `## 의상` 등 섹션 키에 대응하는 제목. 빠지면 이미지 변환 연결이 끊긴다 | 오류 |
| 그 밖의 제목 | 메인 프롬프트의 `#` 제목, 의상 소제목 등 | 경고 |
| 이름 | 항목 파일 이름(캐릭터 이름 등), 관계도의 인물 이름·호칭, 예약 참조 `{{user}}`·`{{char}}` | 경고 |
| 키워드 | 모든 항목의 활성화 키워드 | 경고 |
| 숫자 | 나이, 날짜, 수치 | 경고 |
| 따옴표 안 표현 | 대사 예시, 고유 용어 | 정보 |

- 결과는 "빠진 것" 목록으로 보여 주고, 누르면 원본의 해당 블록을 강조한다. 각 줄에서 "괜찮음"으로 넘기거나 그 블록을 원본으로
  되돌릴 수 있다.
- 필요하면 **LLM 누락 검사**를 추가로 돌린다: 원본과 채택안을 주고 "빠지거나 뜻이 바뀐 설정"을 블록 번호와 함께 목록으로
  받는다(작업 `consistency`의 모델 사용). 시간과 비용이 드는 작업이라 자동으로 돌리지 않는다.

### 채택안 편집

- 검토 탭 오른쪽 열(채택안)은 블록마다 편집할 수 있다. 직접 고친 블록은 "직접 수정" 표시가 붙고, 그 뒤로 해당 블록의 선택을
  바꾸면 고친 내용을 버릴지 묻는다.

### 예외 흐름

- **후보가 목표 용량을 넘음**: 후보 이름 옆에 "목표 초과"를 표시한다. 채택은 막지 않는다.
- **후보가 원본보다 김**: "줄지 않음"으로 표시한다.
- **원본이 그사이 바뀜**: 검토 탭 위에 "만든 뒤 원본이 바뀌었어요"를 띄우고, 바뀌지 않은 블록만 비교를 유지할지, 다시 만들지
  고르게 한다.
- **응답의 블록 번호가 틀림**(없는 번호, 순서 뒤바뀜, 빠진 번호): 한 번 다시 요청한다. 그래도 틀리면 맞출 수 있는 블록만
  맞추고, 나머지는 "맞추지 못함"으로 후보 원문을 그대로 보여 준다(직접 옮길 수 있게).

## 화면

### 검토 탭

```text
┌ 검토: 메인.md 압축 ─ 원본 15,800 B → 채택안 14,900 B / 목표 15,200 B ✓ ─────────┐
│ [다시 만들기] [이 부분만 다시] [LLM 누락 검사]                     [채택 ▾]      │
├──────┬──────────────────┬──────────────────┬──────────────────┬─────────────────┤
│      │ 원본             │ 후보 1           │ 후보 2           │ 채택안 (편집)    │
├──────┼──────────────────┼──────────────────┼──────────────────┼─────────────────┤
│ B1   │ # 세계관         │ # 세계관         │ # 세계관         │ # 세계관         │
│ B2   │ 이 세계는 마법이…│(•)마법이 일상인… │( )마법 일상 세계…│ 마법이 일상인…   │
│ B3-4 │ - 규칙 1 …       │( )규칙: 1) … 2)… │(•)규칙 1·2 …     │ 규칙 1·2 …       │
│      │ - 규칙 2 …       │                  │                  │                  │
│ B5 🔒│ ## 말투 예시     │ (잠금: 원본 유지)│                  │ ## 말투 예시     │
│ B6   │ "어서 와…"       │( )(삭제)         │(•)"어서 와…"     │ "어서 와…"       │
├──────┴──────────────────┴──────────────────┴──────────────────┴─────────────────┤
│ 빠진 것: ⚠ 숫자 "17" (B2, 후보 1)   ⓘ "어서 와" (B6, 후보 1)                    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 바뀐 비율이 큰 블록을 강조하고, "바뀐 블록만 보기"로 거를 수 있다.
- 화면 폭이 좁으면 후보 열을 하나씩 전환해서 본다(원본 · 고른 후보 · 채택안 세 열).

### 상태

- **비어 있음**: 검토할 압축 결과가 없으면 "검토" 탭에 "대기 중인 결과가 없어요".
- **불러오는 중**: 작업이 진행 중이면 검토 탭 대신 진행 표시와 "취소".
- **오류**: 형식이 틀린 응답은 원문을 보여 주고 "직접 옮기기"(원문을 채택안 열에 붙여 넣기)를 제공한다.

## 데이터

| 파일 | 읽기·쓰기 | 형식 |
|---|---|---|
| 대상 항목(`.md`) | 읽기, 채택 때 쓰기 | [항목](../data-model.md#항목) |
| `.atelierx/drafts/<시각>-compression.json` | 쓰기·읽기 | [임시 항목](../data-model.md#임시-항목) |
| 가이드라인 `platform.md`, `compression.md` | 읽기 | [정해진 이름](../data-model.md#정해진-이름) |
| `.atelierx/relations.json`, 모든 항목의 키워드 | 읽기 | 누락 검사 재료 |
| 연결된 플랫폼 프리셋 | 읽기 | 세는 방식, 용량 제한 |

## 규칙

- 압축은 본문만 대상으로 한다. 메타데이터(ID, 키워드, 우선순위 등)는 바꾸지 않는다.
- LLM에는 블록 번호를 붙인 대상 본문(선택 범위가 있으면 그 블록들과, 위치를 알 수 있게 바로 위 제목 블록), 목표 용량, 잠긴
  블록 번호, 가이드라인만 보낸다. 다른 항목의 본문은 보내지 않는다.
- 블록 나누기 규칙은 앱 안에서 하나로 정하고, 임시 항목에 그때의 블록 목록(원본 블록별 시작·끝 위치와 해시)을 남긴다.
  나중에 원본이 바뀌어도 어느 블록이 그대로인지 알 수 있게 하기 위해서다.
- 채택 전에는 원본을 절대 바꾸지 않는다. 채택은 사람이 누를 때만 한다.
- 캐릭터 섹션 제목이 빠진 채택안은 채택할 때 한 번 더 확인을 받는다(이미지 변환 연결이 끊긴다는 안내와 함께).
- 용량은 플랫폼 프리셋의 세는 방식으로 잰다. 토큰 방식이면 [03-llm](03-llm.md)의 토크나이저를 쓴다.

### 기본 압축 가이드라인 (`compression.md`)

앱이 함께 주는 기본 내용의 줄기. 사용자가 고친다.

- 설정 사실(이름, 관계, 나이, 소속, 규칙)은 지운다기보다 압축한다.
- 같은 내용의 반복, 꾸밈말, 설명조 문장을 줄인다.
- 말투·대사 예시는 특징이 드러나는 최소한만 남긴다.
- 목록·짧은 구절로 바꿔도 뜻이 같으면 바꾼다.
- 제목은 지우지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `POST /api/works/{id}/compress` | 압축 시작 `{targets: [{item, selection?}], target_size, candidates, keep, extra_guidelines, model?}` → 작업 |
| `GET /api/works/{id}/drafts/{did}` | 임시 항목(블록 목록, 후보별 블록 결과, 누락 검사, 채택안) |
| `PUT /api/works/{id}/drafts/{did}/composition` | 검토 중인 채택안 저장(블록별 선택, 직접 수정) |
| `POST /api/works/{id}/drafts/{did}/regenerate` | 다시 만들기 `{feedback, blocks?}` |
| `POST /api/works/{id}/drafts/{did}/check` | 누락 검사 `{llm: bool}` |
| `POST /api/works/{id}/drafts/{did}/apply` | 채택 `{mode: "overwrite" | "new_file", new_name?, enable: "original" | "new"}` |
| `POST /api/works/{id}/drafts/{did}/discard` | 버림 |

임시 항목 API(`drafts/…`)는 다른 LLM 작업(06·04)도 같은 형태로 쓴다.

## 단계

- **2단계**: 압축 설정, 블록 나누기, 후보 만들기(항목 하나·선택 범위·여러 항목), 전문 블록 단위 검토와 부분 채택, 채택안 편집,
  규칙 기반 누락 검사, 덮어쓰기·새 파일로 저장, 다시 만들기(전체·일부 블록), 기본 `compression.md`.
- **이후**: 블록 안 문장 단위 차이 강조, 압축 전후 테스트 비교(08과 연결).
