# LLM 연결

## 목적

압축·이미지 프롬프트 변환·뼈대 작성·모순 검사·테스트가 같은 방식으로 LLM을 부르게 한다. **기본은 로컬 LLM**이고,
연결 방식은 OpenAI 호환 하나로 시작한다. 외부 서비스는 사용자가 직접 추가했을 때만 쓰며, 작품 내용을 외부로 보내는 일을
최소화한다. 토큰 수 계산, 외부 전송 확인, 사용량·비용 기록도 여기서 정한다. 형식은 [data-model.md LLM 연결](../data-model.md#llm-연결).

## 사용 흐름

### 기본 연결

- 처음부터 "로컬 LLM" 연결 하나가 있다(OpenAI 호환, `http://127.0.0.1:1234/v1` — LM Studio 기본 주소). 모든 작업의 기본 연결이다.
- 사용자는 로컬 서버를 켜고 "연결 시험"으로 모델 목록을 받아 온 뒤 쓸 모델을 고르면 된다. 다른 포트나 서버(llama.cpp,
  vLLM 등)를 쓰면 주소만 바꾼다.

### 연결 추가

1. 설정 → LLM 연결 → "연결 추가". 연결 방식은 OpenAI 호환이다.
2. 이름, 주소, 인증 정보(필요하면 금고 항목 고르기 또는 새로 등록)를 입력한다. 같은 네트워크의 다른 PC에 있는 내 서버면
   "내 서버"로 표시한다.
3. "연결 시험" → 모델 목록을 받아 온다. 쓸 모델을 고르고, 모델마다 맥락 길이를 확인·수정한다.
4. 외부 서비스면 모델별 가격을 입력할 수 있다(선택). 입력하지 않으면 비용 대신 토큰 수만 보여 준다.

### 작업별 모델 정하기

설정 → LLM 연결 → 작업별 기본 모델에서 작업마다 연결·모델·생성 설정(온도 등)을 고른다.

| 작업 | 쓰는 곳 |
|---|---|
| `compression` | 압축 후보 만들기(05) |
| `image_prompt` | 외모·의상 → 이미지 프롬프트(06) |
| `jsx_prompt` | JSX 컴포넌트의 프롬프트용 문구 만들기(07) |
| `authoring` | 뼈대 작성(04) |
| `consistency` | 모순 검사(04) |
| `chat_test` | 테스트의 챗봇 역할(08) |
| `agent` | 에이전트 패널의 대화(11) |

작업을 실행하는 화면에서 이번 한 번만 다른 모델을 고를 수도 있다.

### 작업 실행 (공통)

1. 기능 화면에서 작업을 시작한다(예: "압축 후보 만들기").
2. 앱이 요청을 조립하고 예상 입력 토큰 수와(가격이 있으면) 예상 비용을 보여 준다. 모델의 맥락 길이를 넘으면 시작하지 않고
   알린다.
3. 외부 연결이면 [외부 전송 확인](#외부-전송-확인)을 거친다.
4. 작업 대기열에 들어가 실행된다. 결과는 임시 항목(`drafts/`)으로 저장되고, 보조 패널 "검토" 탭에 알림이 뜬다.
5. 실패하면 대기열에 실패 이유와 "다시 시도"를 보여 준다.

### 외부 전송 확인

- 작품 내용을 외부 연결로 처음 보낼 때 확인 창을 띄운다: "청원고의 내용을 OpenRouter로 보냅니다. 이 서비스의 이용 정책과
  데이터 처리 방침이 적용됩니다."
- "이 작품에서 이 연결은 다시 묻지 않기"를 고르면 작품 설정에 기록한다. 작품 설정에서 언제든 취소할 수 있다.
- 로컬 연결(이 PC의 `127.0.0.1`·`localhost`)은 묻지 않는다. 같은 네트워크의 다른 PC에 있는 서버는 연결 설정에서
  "내 서버"로 표시하면 로컬처럼 다룬다.

### 사용량 보기

설정 → LLM 연결 → 사용량: 달별·연결별·작업별 요청 수, 토큰 수, 비용(가격이 있는 경우).

### 예외 흐름

- **인증 실패**: "OpenRouter 인증에 실패했어요. 금고의 키를 확인해 주세요" + 금고로 가기.
- **요청 한도 초과(429)**: 잠시 기다렸다가 자동으로 다시 시도한다(최대 3번, 간격을 늘리며). 그래도 실패하면 작업 실패.
- **응답 거부**(서비스의 내용 정책 등): 작업을 "거부됨"으로 끝내고 서비스가 보낸 이유를 그대로 보여 준다. 다른 연결로 다시
  시도할 수 있다.
- **형식이 틀린 응답**(구조화 결과를 읽을 수 없음): 한 번 다시 요청한다. 그래도 틀리면 원문 응답을 임시 항목에 남기고
  "읽을 수 없는 응답"으로 표시한다(직접 보고 옮길 수 있게).
- **로컬 서버가 꺼져 있음**: "로컬 LLM에 연결할 수 없어요. 서버가 켜져 있는지, 주소가 맞는지 확인해 주세요."
- **잠금 중**: 외부 작업은 대기열에서 잠금 해제를 기다린다([00-shell](00-shell.md)).

### 작업 시작 확인 (작은 창)

연결·모델(바꿀 수 있음), 예상 입력 토큰 / 맥락 길이, 예상 비용, 쓰는 가이드라인 목록(추가 지침 고르기), "시작".

### 상태

- **비어 있음**: 연결이 없으면 LLM이 필요한 기능의 버튼 옆에 "LLM 연결이 필요해요 — 설정에서 추가".
- **오류**: 연결 목록에서 연결 상태 점(●)이 빨간색, 마지막 오류 문장.

## 규칙

### 요청 조립

모든 작업은 같은 순서로 요청을 만든다.

1. **앱 고정 지시**: 작업의 목적과 출력 형식(구조화 결과의 형태). 앱에 들어 있고 사용자가 고치지 않는다. 작품 언어에 맞춘다.
2. **가이드라인**: `platform.md`(챗봇에 들어갈 글을 만드는 작업: 압축, 뼈대 작성, JSX 프롬프트용 문구), 작업에 정해진 이름의 가이드라인(예: 압축은 `compression.md`), 사용자가 추가로
   고른 참고 가이드라인. 각각 작품 → 플랫폼 프리셋 → 전역 순서로 찾는다. 이름 표는 [data-model.md 정해진 이름](../data-model.md#정해진-이름).
   미리 만들어 둔 프롬프트 규칙(압축 규칙, JSX 사용 규칙 등)은 이 가이드라인으로 둔다.
3. **작업 재료**: 대상 본문, 플랫폼 제한(목표 용량 등), 관련 항목(예: 모순 검사의 관계도).

- 앱 고정 지시와 가이드라인을 나누는 이유: 출력 형식이 바뀌면 결과를 읽을 수 없게 되므로 형식은 앱이 지키고, 내용에 관한
  지침은 사용자가 고칠 수 있게 한다.
- 결과는 가능하면 구조화 출력(JSON 스키마 지정)을 쓰고, 연결이 지원하지 않으면 지시문으로 형식을 요구한 뒤 앱이 검사한다.

### 토큰 수

- 두 가지 용도가 있다. ① 플랫폼 용량을 토큰으로 세는 경우(플랫폼 프리셋 `count: "tokens:<토크나이저>"`), ② LLM 요청이
  모델 맥락에 들어가는지 확인.
- 토크나이저는 이름으로 가리키고 `data/tokenizers/<이름>/`에 둔다. 앱에는 널리 쓰이는 몇 가지를 함께 넣고, 사용자가
  Hugging Face 형식 `tokenizer.json`을 추가할 수 있다. 앱이 실행 중에 토크나이저를 내려받지 않는다.
- 로컬 서버가 토큰 세기 기능을 제공하면 그것을 쓸 수 있다.
- 맞는 토크나이저가 없으면 글자 수 기반 추정치를 쓰고 화면에 "추정"으로 표시한다.

### 외부 전송

- 외부 연결로 보내는 것은 작업에 필요한 내용뿐이다. 인증 정보, 앱 설정, 다른 작품의 내용은 보내지 않는다.
- 외부 전송 동의는 작품 × 연결 단위로 기록한다(`llm_consent`).

### 실행

- 로컬 연결은 GPU를 쓰는 작업으로 보고 한 번에 하나씩 실행한다(이미지 생성과 같은 GPU 순서를 따름). 외부 연결은 설정의
  동시 실행 수만큼 함께 실행한다.
- 요청·응답 원문은 작업 결과(임시 항목, 테스트 기록)에만 남는다. 요청 헤더와 인증 정보는 어디에도 기록하지 않는다.
- 사용량은 요청마다 `data/usage/`에 한 줄 남긴다: 시각, 연결, 모델, 작업, 작품 ID, 입력·출력 토큰, 비용(가격이 있을 때).
  내용은 남기지 않는다.

## API

| 요청 | 내용 |
|---|---|
| `GET /api/providers` · `POST /api/providers` · `PUT /api/providers/{id}` · `DELETE /api/providers/{id}` | 연결 관리 |
| `POST /api/providers/{id}/test` | 연결 시험, 모델 목록 받기 |
| `GET /api/llm/tasks` · `PUT /api/llm/tasks` | 작업별 기본 모델 |
| `POST /api/llm/estimate` | 작업 요청의 예상 토큰·비용·맥락 초과 여부 |
| `POST /api/tokenize` | `{tokenizer, text}` → 토큰 수(용량 게이지용) |
| `GET /api/usage?month=` | 사용량 요약 |
| `PUT /api/works/{id}/llm-consent` | 외부 전송 동의 기록·취소 |

작업 실행 자체는 각 기능의 API(05·06·04·08)가 만들고, 작업 대기열([00-shell](00-shell.md))로 돌아간다.

## 단계

- **3단계(지금 구현)**: OpenAI 호환 연결과 연결 시험(모델 목록), 연결별 기본 모델, 작업별 연결·모델·온도, 테스트 화면 스트리밍(멈추기,
  생각 중 표시), 압축(후보마다 줄이는 강도를 달리 요청)·뼈대 작성·이미지 프롬프트 변환의 실제 호출, JSON 결과 검사와 한 번 다시
  요청, 사용량 기록. 앱 고정 지시는 아직 한국어 하나다.
- **외부 연결(구현)**: 설정에서 연결 추가·삭제, 인증 키는 금고 항목을 고름(`secret:<이름>`), "내 서버" 표시. 이 PC 밖의 연결로 작품을
  처음 보낼 때 서버가 `428 server.llm.consent_needed`로 멈추고, 화면이 확인을 받아 작품의 `llm_consent`에 기록한 뒤 다시 보낸다
  (작품 설정에서 취소). 사용량은 설정 → LLM 아래에 이번 달 연결·모델·작업별 요청 수와 토큰 수로 보여 준다. 비용·가격 입력은 이후.
- **생각(reasoning)하는 모델**: 생각 내용은 별도 필드나 `<think>` 블록으로 오며 화면에 내지 않고 글자 수만 "생각 중"으로 보여 준다.
  생각 단계가 긴 모델은 JSON으로 답하는 작업이 매우 느리다(확인 사례: 짧은 압축 하나에 생각 토큰 수천 개). 이런 작업에는 instruct
  모델을 권한다. OpenAI 호환 요청으로는 생각을 확실히 끌 방법이 없어(`reasoning_effort` 등은 서버·모델마다 다름) 서버의 모델 설정에 맡긴다.
- **2단계**: 기본 로컬 연결, OpenAI 호환 연결, 연결 시험, 작업별 모델, 요청 조립, 구조화 결과 검사, 외부 전송 확인,
  토큰 수(포함 토크나이저 + 추정), 사용량 기록.
- **이후**: 다른 연결 방식(필요해질 때), 사용자 추가 토크나이저 관리 화면, 사용량 그래프. 앱에 함께 넣을 토크나이저는 구현
  단계에서 정한다.
