# 남은 작업과 개인 사용 기준 우선순위

2026-09-21 기준. Discord 공개 이미지·기본 스포일러 사용자 확인 이후의 점검이다. 기존 [구현 현황](implementation-status-2026-09-21.md)은 Discord 구현 이전 표를 포함하므로 현재 상태는 이 문서와 [Discord 기록](discord-personal-bot.md)을 우선 참고한다.

사용자 목적은 배포 전 개인 제작이다. 최신 지시로 Discord는 일반 테스트 도구로 두며 봇 추가 기능과 고정 Tunnel은 후순위로 미룬다. 본체 Backend와 F/E 제작 흐름을 우선한다. 현재 지정 Discord 서버의 멤버 사용은 유지한다. 무인 대량 운영 준비를 모든 기능의 선행 조건으로 두지 않는다. 아래 우선순위는 **검토 제안이며 착수 승인이나 미정 제품 정책의 확정이 아니다.** P1은 가까운 사용성·복구 개선, P2는 다음 기능/품질 보완, P3는 필요할 때 확장이다. 현재 조사에서 새로 확인한 즉시 사용 중단 수준의 P0 결함은 없다.

## 현재 완료 기준선

- Core/Generation/Validation, 분류·전역 조각·제작 계획, 단일/묶음 검사, 기존 그룹 작업의 취소·재생성, 파일럿 Frontend 및 기본 CLI가 있다.
- Discord Direct → Core → Anima → 1536 업스케일 → 응답의 실제 실행을 확인했다. 현재 서버 접근 제한, 소유자 설치 제한, 공개 결과·기본 스포일러를 적용했다. 공개·스포일러 표시는 사용자가 확인했다.
- Natural은 Core가 로컬 LLM에 간단한 Positive 문장 재작성을 요청하는 부분 구현이다. 실제 백엔드 LLM→생성 시험은 있으나, 체크포인트에 맞는 어휘·태그·자연어 조합을 최적화하는 기능은 없다. 사용자는 이 부분을 나중에 보완해야 한다고 지적했다.
- 모의 Provider/실제 SQLite·TCP·프로세스 장애 시험과 소규모 실제 GPU 복구 기록은 있다. 이를 장기 운영·VLM 정확도 보장으로 확대하지 않는다.

## A. 기능 구현·기능 확장

| ID | 우선 | 남은 작업 | 현재 상태 / 완료 기준 |
| --- | --- | --- | --- |
| F1 | P3 제안 | Discord 독립 작업 취소·수동 재생성 | 기존 그룹 작업에는 있지만 standalone REST/봇에는 없다. Core 기능을 먼저 만들고 봇은 호출만 수행. 실행 중 취소와 소유권을 포함해야 한다. |
| F2 | P3 제안 | Discord 생성 옵션·재현성 | 현재 prompt/mode만 받고 seed·크기·Negative·모델은 서버 설정이다. 후속 사용자 지시로 신규 요청의 무작위 Seed와 실제 사용값 표시를 구현했고 사용자 동작 확인을 마쳤다. 고정값 직접 입력 등 추가 옵션은 여전히 후보. 운영 활성화 상태는 Discord 기록을 따른다. |
| F3 | P2 사용자 지적 | 체크포인트별 Natural 프롬프트 변환 | Core에서 모델별 어휘/태그/자연어 규칙, 사용자 의도 보존, 프롬프트 결과 확인을 지원. 태그와 자연어의 혼합 비율을 모든 체크포인트에 일괄 고정하지 않으며 실제 이미지 비교로 평가. Discord/F/E에 변환 로직을 복제하지 않는다. |
| F4 | P1 | 신체 구조 이상·Metadata 검사 | 현재 해당 활성 Profile을 거절한다. 필수 Prompt 일치 검사와 별도인 손·얼굴·사지 구조 이상 검사, Metadata 검사 계약/구현이 필요. |
| F5 | P1 | 독립 이미지 후처리의 Core 흐름 | Generation에 후처리 API는 있다. Core 접수·결과 등록·외부 이미지 입력을 제품 흐름으로 연결하는 것은 남음. |
| F6 | P1 | Frontend 편집·설정 편의 | 고급 후처리 JSON 폼, 충돌 diff/복구, 초안 보존, 작업 진행 표시 보완. Discord 결과를 F/E에서 열람하는 별도 뷰는 후보이며 기존 그룹에 자동 편입하지 않는다. |
| F7 | P2 | Prompt/설정 이력 조회·복원 | 실행 snapshot/revision은 존재. 사용자가 보는 diff·복원 UI와 전역 설정 이력은 부분/미구현. |
| F8 | P2 | SDK·CLI 범위 확대 | 제작 계획·전역 조각·분류·Preset·Profile/Provider·standalone 전용 편의 메서드/명령 보완. 범용 REST request는 이미 가능. |
| F9 | P3 | SDXL/Illustrious 및 생성 단계 동일성 강화 | SDXL Node/Backend 미구현. 참조 이미지 기반 동일성 강화 기법은 미확정. Anima 개인 사용의 선행 조건이 아님. |
| F10 | P3 | 전체 자연어 제작 Agent 및 후속 편집 기능 | 캐릭터/의상 작성·도구 호출 Agent는 단순 Natural과 별개. Inpaint/ControlNet/Crop/색감/Watermark는 후속 로드맵이며 기본 사용을 막는 누락이 아님. LoRA 학습과 중복 이미지 검사는 현재 범위 제외. |

## 권장 실행 순서 — Discord 후순위 반영

1. R3: Alpha 생성 설정과 Core 검사 요구의 연결 누락을 먼저 보완. 작은 범위로 기존 기능의 정확도를 높인다.
2. F4/Q2: 신체 구조 이상·Metadata 등 Validation 미구현 범위를 설계/구현하고 작은 대표 이미지 세트로 평가. Metadata 검사 대상·판정 기준 등 미확정 제품 정책은 구분한다. VLM 호출 성공만으로 기능 완료로 보지 않는다.
3. F5/Q3: 기존 이미지의 독립 후처리를 Core 접수·결과 관리와 연결. 외부 이미지 입력은 별도 입력/보관 정책을 정한 뒤 확장한다. 후처리 품질은 표본으로 확인한다.
4. F6/R2: F/E에서 생성 결과 확인→검사→후처리/재생성→오류 확인의 제작 흐름을 완성. 고급 설정 폼과 초안 보존을 먼저, 모델 다운로드 등 주변 기능은 뒤로 둔다.
5. O2: 최소 백업/복원을 별도 작은 작업으로 확보. 실제 데이터 형식을 변경하는 작업 전에는 백업을 먼저 준비하지만, 전체 Import/Export 제품을 모든 기능의 선행 조건으로 두지 않는다.
6. F7/F8/R4: 이력 비교·복원, SDK/CLI 범위, 실제 GPU/VLM 장애 검증을 보완한다. 오류가 실제 작업을 막으면 해당 복구 항목은 즉시 앞당긴다.
7. F3/Q1: 체크포인트별 Natural 개선은 기본 제작 흐름 이후. Core의 태그+자연어 작성 규칙을 모델별로 검증한다.
8. F1/F2/R1/O1 및 F9/F10/R5/O4: Discord 추가 기능·고정 Tunnel, 모델/Agent 확장, 무인 대량 운영은 필요할 때 진행.

우선순위 제안의 중심은 **기존 연결 누락 → Backend 미구현 기능 → F/E 실제 제작 흐름 → 편의·확장**이다. 원래 요구의 캐릭터 동일성 목표는 유지하지만 기법은 미확정이며 실제 기본 제작 결과를 보고 별도 순위를 결정한다. Discord를 후순위로 미룬 것은 사용자 확정 사항이고, 위 세부 작업 순서는 검토 제안이다. 이번 작업에서 제품 구현이나 GPU 시험은 새로 실행하지 않았다.
