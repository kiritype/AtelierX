# 남은 작업과 개인 사용 기준 우선순위

2026-09-21 기준. Discord 공개 이미지·기본 스포일러 사용자 확인 이후의 점검이다. 기존 [구현 현황](implementation-status-2026-09-21.md)은 Discord 구현 이전 표를 포함하므로 현재 상태는 이 문서와 [Discord 기록](discord-personal-bot.md)을 우선 참고한다.

사용자 목적은 배포 전 개인 제작이며 현재 지정 Discord 서버의 멤버에게 사용을 허용한다. 무인 대량 운영 준비를 모든 기능의 선행 조건으로 두지 않는다. 아래 우선순위는 **검토 제안이며 착수 승인이나 미정 제품 정책의 확정이 아니다.** P1은 가까운 사용성·복구 개선, P2는 다음 기능/품질 보완, P3는 필요할 때 확장이다. 현재 조사에서 새로 확인한 즉시 사용 중단 수준의 P0 결함은 없다.

## 현재 완료 기준선

- Core/Generation/Validation, 분류·전역 조각·제작 계획, 단일/묶음 검사, 기존 그룹 작업의 취소·재생성, 파일럿 Frontend 및 기본 CLI가 있다.
- Discord Direct → Core → Anima → 1536 업스케일 → 응답의 실제 실행을 확인했다. 현재 서버 접근 제한, 소유자 설치 제한, 공개 결과·기본 스포일러를 적용했다. 공개·스포일러 표시는 사용자가 확인했다.
- Natural은 Core가 로컬 LLM에 간단한 Positive 문장 재작성을 요청하는 부분 구현이다. 실제 백엔드 LLM→생성 시험은 있으나, 체크포인트에 맞는 어휘·태그·자연어 조합을 최적화하는 기능은 없다. 사용자는 이 부분을 나중에 보완해야 한다고 지적했다.
- 모의 Provider/실제 SQLite·TCP·프로세스 장애 시험과 소규모 실제 GPU 복구 기록은 있다. 이를 장기 운영·VLM 정확도 보장으로 확대하지 않는다.

## A. 기능 구현·기능 확장

| ID | 우선 | 남은 작업 | 현재 상태 / 완료 기준 |
| --- | --- | --- | --- |
| F1 | P1 제안 | Discord 독립 작업 취소·수동 재생성 | 기존 그룹 작업에는 있지만 standalone REST/봇에는 없다. Core 기능을 먼저 만들고 봇은 호출만 수행. 실행 중 취소와 소유권을 포함해야 한다. |
| F2 | P1 제안 | Discord 생성 옵션·재현성 | 현재 prompt/mode만 받고 seed·크기·Negative·모델은 서버 설정이다. 로컬 seed는 12345 고정. 우선 seed 고정/변경 선택과 사용값 조회를 후보로 검토. 무작위 기본값으로 바꾸는 정책은 미확정. |
| F3 | P2 사용자 지적 | 체크포인트별 Natural 프롬프트 변환 | Core에서 모델별 어휘/태그/자연어 규칙, 사용자 의도 보존, 프롬프트 결과 확인을 지원. 태그와 자연어의 혼합 비율을 모든 체크포인트에 일괄 고정하지 않으며 실제 이미지 비교로 평가. Discord/F/E에 변환 로직을 복제하지 않는다. |
| F4 | P2 | 신체 구조 이상·Metadata 검사 | 현재 해당 활성 Profile을 거절한다. 필수 Prompt 일치 검사와 별도인 손·얼굴·사지 구조 이상 검사, Metadata 검사 계약/구현이 필요. |
| F5 | P2 | 독립 이미지 후처리의 Core 흐름 | Generation에 후처리 API는 있다. Core 접수·결과 등록·외부 이미지 입력을 제품 흐름으로 연결하는 것은 남음. |
| F6 | P2 | Frontend 편집·설정 편의 | 고급 후처리 JSON 폼, 충돌 diff/복구, 초안 보존, 작업 진행 표시 보완. Discord 결과를 F/E에서 열람하는 별도 뷰는 후보이며 기존 그룹에 자동 편입하지 않는다. |
| F7 | P2 | Prompt/설정 이력 조회·복원 | 실행 snapshot/revision은 존재. 사용자가 보는 diff·복원 UI와 전역 설정 이력은 부분/미구현. |
| F8 | P2 | SDK·CLI 범위 확대 | 제작 계획·전역 조각·분류·Preset·Profile/Provider·standalone 전용 편의 메서드/명령 보완. 범용 REST request는 이미 가능. |
| F9 | P3 | SDXL/Illustrious 및 생성 단계 동일성 강화 | SDXL Node/Backend 미구현. 참조 이미지 기반 동일성 강화 기법은 미확정. Anima 개인 사용의 선행 조건이 아님. |
| F10 | P3 | 전체 자연어 제작 Agent 및 후속 편집 기능 | 캐릭터/의상 작성·도구 호출 Agent는 단순 Natural과 별개. Inpaint/ControlNet/Crop/색감/Watermark는 후속 로드맵이며 기본 사용을 막는 누락이 아님. LoRA 학습과 중복 이미지 검사는 현재 범위 제외. |

## B. 오류·복구 검증과 연결 누락 보완

| ID | 우선 | 남은 작업 | 현재 상태 / 완료 기준 |
| --- | --- | --- | --- |
| R1 | P1 | Discord 장애·동시 요청 실제 시험 | 로컬 오프라인, Tunnel 단절, 응답 유실, 15분 초과, 첨부 제한, 여러 멤버 요청을 소규모로 시험. 이미 구현한 멱등성·만료·소유권 처리가 실제 환경에서도 동작하는지 확인. 친구 계정 접근 시험은 별도. |
| R2 | P1 | 접수 불명·정체의 사용자 복구 | 실행 종료 불명이나 영구 단절을 조회/정리하는 절차·화면 보완. 자동 재접수/Provider 재시도/시간 기반 GPU 강제 반납으로 해결하지 않음. |

| R4 | P2 | 실제 ComfyUI·VLM·GPU 장애 확대 | 기존 작은 생성 복구 시험 외에 ComfyUI 자체 재시작, 실제 VLM 도중 중단, OOM·외부 ComfyUI 경합 시험. 대량 무인 시험은 P3으로 분리. |
| R5 | P3 | Provider별 실행 제어·장기 부하 | 현재 단일 Validation worker 중심. Provider별 독립 제어가 필요할 때 구현하고 공유 GPU 직렬화를 유지. 수천 장 연속 실행·장기 무인 운영은 개인 사용의 선행 조건이 아님. |

## 권장 실행 순서

1. O1: 일상적으로 다시 연결할 수 있는 고정 Tunnel과 시작 절차.
2. F1/F2: Discord 취소·수동 재생성·seed 제어를 Core 중심으로 구현(구체 옵션 정책 확인 필요).
3. R1/R2: 실제 서버 멤버 요청과 짧은 장애·만료·정체 복구 시험.
4. O2: 최소 백업/복원으로 제작 자산 보존.
5. F3/Q1: 체크포인트에 맞춘 Natural 보완과 Direct 비교. 사용자의 '나중에 보완' 지시를 반영해 기본 운영 이후 배치.
6. F4~F8/R3/Q2~Q3: F/E 사용 빈도와 자동 검사 의존도에 따라 선택.

위 순서는 이번 검토의 권고이며 사용자의 우선순위 결정 후 갱신한다. Natural을 먼저 개발하거나 공개 배포 준비를 자동 착수하지 않는다.
