# 전역 조각 제작 계획 구현·검증

2026-09-13 사용자 확정: 외형은 항상 포함한다. 전역 공유 조각의 상의/하의 포함 여부만 조절한다. 조각 하나가 이미지 하나이며 줄/쉼표 및 구도×표정×동작으로 자동 분할하지 않는다.

## 구현

Core는 revision이 있는 조각 생성·수정·보관·이력 API와 영속 제작 계획을 제공한다. 전체 항목을 한 트랜잭션으로 고정 저장하고 명시적 시작 이후에 실행한다. 8개 실행 창과 32개 묶음 검증 분할은 내부 처리 크기이며 전체 이미지 수 제한이 아니다. F/E 제작 화면에서 여러 페이지의 조각을 체크하고 고정 계획을 확인·시작·취소할 수 있다. 작업 현황에서 계획을 다시 연다. 과거 32개 batch 양식은 호환용 접힌 영역으로 남겼다.

[API 명세](../api/prompt-fragments-production-plans.md)에 요청·응답 및 제약을 별도 기록했다. 현재 전송 본문 2 MiB와 그룹 하나당 계획이라는 범위는 유지된다. 여러 캐릭터를 동시에 선택하여 각 그룹의 계획을 만드는 상위 UI는 후속 작업이다.

## 자동 검증

- Python 전체 184개 통과.
- Node 프론트엔드 테스트 실행: 15개 통과(모듈별 자체 검증 포함); 제작 전용 11개 통과.
- 3,000개 항목 저장/페이지 조회, 도중 오류의 트랜잭션 롤백, 8개 실행 창, 재시작 후 중복 방지 및 취소를 mock으로 확인했다.
- 대상 65개를 동일 기준으로 32/32/1 분할하고 failed/error를 passed로 집계하지 않음을 확인했다.
- 잘못된 초대형 페이지 offset은 SQLite 예외 대신 입력 오류로 거절하도록 수정했다.

## 실제 파일럿 실행

파일럿을 유휴 상태에서 재시작한 뒤 REST와 브라우저에서 확인했다. ComfyUI 자체는 재시작하지 않았다.

- 계획 `cf054ea6-e2b3-4de2-8751-c3a25c2e671b`: 전역 조각 상반신 미소/놀람 2개.
- 외형·상의 포함, 하의 제외를 고정 프롬프트에서 확인. 생성 전 draft에는 Task가 없고 같은 키 재접수는 동일 계획을 반환했다.
- Anima 1024×1024 생성 및 UltraSharp 후처리로 PNG 1536×1536 두 장 저장.
- 단일 검사 두 장 모두 passed. 묶음 검사 `968fe901-7237-40f8-9125-d08f5edd05b2`는 completed / failed.
- Provider는 첫 이미지 머리 길이를 기준과 다르다고 판정했고, 두 번째 이미지는 하의 관찰 불충분으로 판정했다. 이는 모델의 검증 결과이며 사람이 확정한 품질 판정은 아니다. 실행 오류가 없더라도 합격으로 덮어쓰지 않는다.
- bounded smoke를 위해 계획 스냅샷의 자동 재생성만 비활성화하고 원래 전역 설정은 접수 직후 복원했다. 3,000장의 실제 GPU 실행은 수행하지 않았다.

브라우저에서 작업 현황 → 제작 계획 열기, 항목별 상태 및 묶음 결과 표시를 확인했다. 원시 실행 증거는 `artifacts/fragment-plan-*.json`, 전체 테스트 로그는 `artifacts/full-suite/`에 있다.

## 후속: 여러 그룹 선택 및 오류 정리

여러 기존 고정 그룹을 작품/캐릭터/의상 이름으로 선택하는 F/E를 추가했다. 전체 catalog는 200개씩 읽으며 동일 조각·설정을 그룹별 독립 계획으로 접수한다. 그룹마다 요청/키를 고정하고 부분 접수 결과를 표시한다. 각 계획의 상세에서 명시적으로 시작하며 단일 조각도 여러 그룹에 적용할 수 있다. 전체 그룹 목록은 현재 한 화면에 렌더링하므로 그룹 수가 많을 때 검색·화면 페이지 처리가 추가로 필요하다.

브라우저 통합 중 의상을 아직 선택하지 않았을 때 검사 설정이 빠지던 문제와 묶음 Profile에 단일 Profile을 표시하던 문제를 수정했다. 계획에서 새 제작으로 돌아갈 때 초안은 보존한다.

계획의 내부 오류가 기존 작업을 남긴 채 terminal로 끝나지 않도록 정리 단계를 추가했다. 취소 의도 저장 직후 중단과 Task 저장/항목 연결 사이 중단도 복구한다. 신규 장애 테스트 3개를 포함해 Python 전체 187개, F/E 실행 17개(제작 전용 13개)가 통과했다.

현재 파일럿의 기존 그룹 두 개로 UI 접수·동일 요청 재접수·상세 조회·실행 전 취소를 확인했다. 그룹별 새 계획은 `bc1e8429-b30c-463b-a33e-2a54c1ac5a73`, `19ed9ddd-adbf-40c4-bc67-147b70a75b6d`다. 둘 다 cancelled로 종료했고 GPU Task가 없음을 확인했다. 증거: `artifacts/multi-group-ui-smoke.json`. 서로 다른 그룹 ID의 요청 분리는 자동 테스트로 검증했다. 실제 장시간 무인 실행 및 여러 캐릭터의 결과 품질은 별도 검증 대상이다.
