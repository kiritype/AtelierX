# 실사용 준비도 검토

2026-09-13 코드·자동 검사·로컬 파일럿 증거를 기준으로 한 검토다. 달력 일정이나 완료율을 추정하지 않는다. 여기서 "실사용"은 사용자가 결과와 오류를 보며 자신의 로컬 PC에서 제작하는 경우와, 수천 장을 무인으로 신뢰성 있게 처리하는 경우를 구분한다.

## 현재 가능한 사용 범위

**감독하는 개인 소규모 제작은 가능하다.** 준비된 Anima 환경에서 조각 기반 계획을 만들고, 시작·상태 조회·취소·단일 검사·묶음 검사를 사용하며 결과를 사람이 검토하는 흐름이다. 실제 파일럿은 조각 두 개를 1024px Anima 생성과 1536px UltraSharp 후처리로 실행했고, 두 단일 검사는 통과했다. 묶음 검사는 완료됐지만 `failed`였으며, 이 결과를 합격으로 바꾸지 않았다. 근거는 [global-fragments-production-plans.md](global-fragments-production-plans.md)와 `artifacts/fragment-plan-*.json`이다.

이 판단은 다음 구현·시험으로 뒷받침된다.

- 계획과 항목은 SQLite에 고정 저장되고, 항목은 8개 실행 창으로 보낸다. 계획 전체 수는 코드상 제한하지 않으며 항목·계획 페이지 조회가 있다. [core_production_plans.py](../../src/atelierx/core_production_plans.py)
- 3,000개 저장·페이지 조회, 계획 생성 중 오류의 트랜잭션 롤백, 재시작 후 중복 방지, 취소 및 32개 단위 묶음 분할은 mock 자동 검사로 확인했다. [test_production_plans.py](../../tests/test_production_plans.py)
- Core → Generation → ComfyUI → 이미지 저장 → Validation → Core 저장의 실제 실행과 여러 후처리 조합은 19건의 REST 실행으로 확인됐다. 전체 자동 검사·실제 실행의 구분은 [full-test-report-2026-09-13.md](full-test-report-2026-09-13.md)에 기록돼 있다.
- 재시작 시 중복 ComfyUI 접수를 피하는 Generation 복구 경계와 파일 해시 재확인은 자동 검사로 확인했다. [backend-recovery.md](backend-recovery.md), [test_backend_recovery.py](../../tests/test_backend_recovery.py)

그러나 이는 **장시간 무인 대량 생산의 준비 완료 선언이 아니다.** 3,000개는 데이터 저장과 상태 전이의 mock 근거이고, 3,000개의 GPU 생성·후처리·실제 VLM 호출·복구를 연속으로 실행한 근거는 없다. VLM도 제한된 이미지와 조건에서만 평가됐으며, 파일럿의 묶음 결과 자체가 불합격이었다.

## 지금의 운영 기준

개인 작업에서는 작은 계획부터 시작하고, 각 묶음 결과와 저장 이미지·디스크 여유를 확인한 뒤 다음 계획을 시작하는 것이 적절하다. 자동 재생성은 비용과 결과 수를 늘리므로 파일럿처럼 해당 계획 snapshot에서만 필요에 따라 제한하고, 전역 값을 시험 용도로 바꾸면 즉시 원복 여부를 확인한다. 묶음 `failed`·`incomplete`·`error`는 작업 완료와 품질 합격을 구분해 사람이 처리한다.

수천 장 무인 실행은 P0 네 항목을 통과하고, 목표 구성으로 중단·복구를 포함한 대표 규모의 실측 실행을 재현할 때까지 보류한다. 코드의 8개 창과 32개 비교 분할은 동시성·요청 크기를 제한하는 장치일 뿐, GPU·VLM의 장기 안정성이나 품질을 보장하는 처리량 약속은 아니다.

## 수정한 결함과 남은 검증

[후속 장기 큐·복구 검증](production-plan-recovery-tests.md): 1,024개 항목을 처리하며 실제 SQLite를 네 차례 다시 열고 중복 없이 완료하는 테스트, 단일/묶음 검사 취소 대기 및 저장 중단 경계 테스트를 추가했다. Provider는 대체 구현이며 실제 GPU 장애 시험은 아직 남아 있다.

계획 오류 뒤 활성 작업을 추적하지 않던 결함은 수정하고 장애 주입·저장소 재연결 테스트를 추가했다. 이는 실제 GPU 실행 중 강제 종료 시험과 구분한다. 모듈 수준에서 복구를 확인했으나 장시간 무인 운영 게이트 전체를 통과한 것으로 표시하지 않는다.
