# 작업실 분류 편집·조회 개선 — 2026-09-22

사용자 요청에 따라 추가·수정 혼동, 계층 구분과 화면 전환 지연을 수정한다. Terra 서브에이전트에 구현·회귀 검사를 분담하고 주 에이전트가 통합·브라우저 검증 후 PR과 develop squash 병합을 수행한다.

## 수정 계획

1. 선택 상태와 편집 대상/모드를 분리한다. 새 항목은 POST, 기존 항목은 해당 id/revision의 PATCH만 사용하고 부모 경로·유형·버튼 문구를 명시한다. 미저장 입력과 중복 제출을 보호한다.
2. 작품 > 캐릭터 > 의상 트리에 일관된 아이콘과 계층 표시를 적용한다. 각 행의 항상 접근 가능한 더보기 메뉴와 PC 우클릭은 같은 동작을 제공한다. 모바일에서도 추가·수정·보관에 접근할 수 있어야 한다.
3. 삭제는 기존 Core 보관 계약을 사용한다. 영구 삭제·연쇄 삭제는 도입하지 않으며 과거 그룹·이미지·작업 이력을 보존한다.
4. 분류 탐색은 해당 자식 목록만 조회하고 생성 설정과 다중 그룹 목록은 필요할 때 조회한다. 재방문에는 기존 화면을 먼저 표시하고 적절히 갱신한다. 실행 상태·검사 기준 revision 및 멱등 접수는 캐시 최적화를 이유로 생략하지 않는다.
5. 실제 격리 Core/SQLite와 브라우저에서 CRUD 대상 정확성·메뉴·반응형·재방문을 확인한다. 자동 회귀와 요청 수 측정을 수행하며 실제 원격망·물리 모바일·GPU 실행 여부는 별도로 기록한다.

Google OAuth 운영 기록의 미커밋 변경은 보존한다. 사용자의 후속 지시로 `/`·`/ui`에서 고정 상대 주소 `/ui/`로 이동하는 리디렉션도 이번 범위에 포함한다. GET/HEAD 진입만 허용하고 API 인증 경계는 유지한다.

## 검증 결과

- 자동 회귀: Python 전체 252개 통과. Frontend 전체 34개 통과. 로그는 Git 제외 경로 `artifacts/full-suite/tree-python.log`, `tree-node.log`에 저장한다.
- 실제 실행: 격리 Core·SQLite에서 브라우저로 기존 작품을 선택한 상태의 새 작품/캐릭터/의상 추가, 부모 연결, 새 작품 이름 수정, 트리 메뉴 표시를 확인했다. 운영 DB와 GPU는 사용하지 않았다.
- 모의 API 회귀: 실제 Frontend 로더에 요청 기록용 API를 연결하여 초기 작품 목록만 조회, 선택한 자식만 조회, 같은 분류 재선택 시 캐시 재사용, 생성 단계 설정의 지연 조회와 늦은 응답 방어를 확인한다. 브라우저 기준 기존 초기 조회는 12건이었으나 최종 동일 조건 비교 측정은 완료하지 않았으므로 실측 성능 개선 비율로 보고하지 않는다.
- 리디렉션: `/`·`/ui` GET/HEAD가 `/ui/`로 이동하고, 외부 URL 쿼리로 목적지가 변경되지 않으며 REST 인증이 유지되는 자동 검사를 통과했다.
- 미검증: 최종 보관/복원 확인창의 브라우저 재검사, 모바일 실기기 및 최종 반응형 전체 조합, 실제 원격망 지연. 기존 네이티브 확인창을 띄운 검증 탭 이후 브라우저 입력 도구가 시간 초과되어 추가 시각 검증을 완료하지 못했다. 보관 확인은 화면 내 명시적 확인/취소로 변경했다.
- 운영 반영: 큐·ComfyUI·Discord 대기 검사 후 재시작 도우미를 실행했으나 서비스 프로세스 식별 보호 검사에서 중단됐다. 운영 서비스와 Tunnel은 중단하지 않았다. 병합 후 사용자가 파일럿을 재시작해야 새 정적 모듈 허용 목록과 리디렉션이 적용된다.
