# 작업 환경 이전 및 문서 검토 기록 — 2026-09-12

현재 저장소 문서를 기준으로 작업을 이어가기 위한 인계 기록이다. 아키텍처 승인이나 구현 착수 기록은 아니며, 현재 결정 상태는 관련 ADR과 요구사항 문서를 따른다.

## 현재 환경

후속 사용자 보완: Validation Backend 설계와 ComfyUI Custom Node 개발을 병행하기로 했다는 이전 논의가 저장소에 누락되어 있었다. 2026-09-12 현재 대화에서 전달받은 방침은 [개발 문서](README.md)에 기록했다. 아래 검토·미실행 기록은 인계 당시 상태이며, 이 병행 방침 이전의 일괄 구현 보류를 현재 전체 작업 범위로 해석하지 않는다.

- 사용자가 앞으로 이 환경에서 AtelierX 작업을 계속한다고 전달했다.
- 현재 작업 환경은 Windows / PowerShell이다.
- 사용자 제공 정보: Stability Matrix가 설치되어 있으며 NVIDIA RTX 4090 GPU를 사용해 실제 동작을 확인할 수 있다.
- Stability Matrix·ComfyUI의 버전과 설치 경로, 설치 모델·Custom Node, GPU 드라이버·런타임 및 ComfyUI 실행 상태는 이번 작업에서 확인하지 않았다. 설치 가능 환경과 개별 Workflow의 검증 완료를 구분한다.
- 이 환경 정보는 개발·검증 대상에 관한 사실이며 제품의 지원 OS, 필수 GPU, 설치 도구 또는 최소 사양을 확정하지 않는다.

## 검토 범위와 진행 상태

저장소의 작업 규칙, 기여 안내, 문서 목차, 아키텍처 개요, ADR 0001~0003·목록·절차·backlog·템플릿, 요구사항·기능 대조표·로드맵, 모듈 책임 및 개발 안내를 검토했다. 외부 공유 대화와 참고 저장소는 이번에 재검증하지 않았으며, 원문 요구의 출처 분류는 저장소 기록을 기준으로 읽었다.

| 영역 | 현재 상태 | 이어서 다룰 범위 |
| --- | --- | --- |
| 개발 운영 | ADR-0001은 부분 결정이 있는 Proposed | 미정 세부만 후속 검토. 리뷰·보호는 최초 릴리즈 이후 검토 |
| Custom Nodes | ADR-0002 Accepted, N-01~N-17 검토 완료 | Node 구조·Preset 저장·모델 호환성·출력 계약 등 상세 미정 |
| Generation | ADR-0003 Accepted, G-01~G-10 및 관련 교차 서비스 책임 반영 | 접수·Queue 복구·파일 전달·SSE 등 상세 계약 미정 |
| Core | 주요 책임은 확정, C-01~C-19 개별 기능 검토는 미완료 | 도메인 관계·Prompt 조합·AI 작성 범위·Version 등 |
| Validation | 검증·재생성 변경값 반환 책임은 확정, V-01~V-16 개별 검토는 미완료 | 검사 범위·불확실성·오류 정책·Provider 설정 등 |
| 나머지 기능 | Frontend·CLI·SDK·모델·파일 관리 등의 개별 검토 미완료 | 대조표의 원문 요구·AI 제안·미정 설계를 구분해 검토 |

검토 시작 시 로컬 브랜치는 develop이고 작업 트리에 변경은 없었다. 원격 상태를 새로 조회하거나 동기화한 것은 아니다.

## 문서 해석상 주의점

Accepted ADR과 현재 아키텍처 개요 사이에서 결정을 뒤집는 직접 충돌은 발견하지 않았다. 다음은 남은 설계와 문서 읽기상의 차이다.

1. **대조표의 과거 비교 상태**: `기존 문서 대조` 열은 최초 커밋 `ab7365c` 기준이다. X-01의 ‘확정 반영 없음’, S-07의 ‘미확정’ 등을 현재 결정으로 읽으면 ADR-0003과 어긋나 보인다. 현재 상태는 근거·확인 열과 ADR을 함께 확인한다. 과거 비교 기록은 유지한다.
2. **검토 순서의 차이**: 대조표 말미는 Generation 다음 Core를, backlog의 다음 논의 후보는 Validation을 먼저 권한다. 두 순서 모두 미확정 권고이므로 필수 진행 순서로 해석하지 않는다. backlog의 ADR-0001 우선 문구도 현재까지의 부분 결정 및 ADR-0002·0003 완료 상태와 함께 읽는다.
3. **아직 복원 검토가 필요한 요구**: C-06~C-10의 Prompt 포함 옵션·조합·자연어·AI 데이터 작성, M-02~M-03의 모델 탐색·다운로드, F-08~F-10 및 A-02~A-03의 Metadata 열람·경로 설정·삭제는 대조표를 함께 봐야 구체 요구가 드러난다. 이번 분석으로 일괄 확정하지 않는다.
4. **저장 책임과 실행 복구**: Node 설정 저장에 SQLite를 허용한 표현과 Queue 복원 요구가 Generation의 DB 직접 접근을 허용하지는 않는다. Core 소유 원칙을 만족하는 저장·복구 계약이 필요하다.
5. **이미지와 Metadata의 일관성**: Generation 영역 파일과 Core Metadata를 연결하는 등록·삭제·실패 복구 계약이 남아 있다. 단일 PC의 로컬 경로 접근만으로 분산 배치 요구까지 충족했다고 간주하지 않는다.
6. **재생성과 오류 복구의 구분**: 이미지 검증 불합격에 따른 새 시도와 실행 오류에 대한 재실행·중단 정책을 구분해야 한다. Validation이 사용할 수 없는 상황의 처리도 후속 설계에서 확인할 질문이다.

## 다음 작업 제안 — 미확정

후속 진행: 아래는 인계 당시 제안이다. 이후 사용자 논의로 [ADR-0004](../architecture/adr/0004-validation-outcomes-and-errors.md)를 확정했으며 이미지·생성 Prompt 입력과 실행 오류의 자동 이미지 재생성 금지·수동 재생성을 기록했다. Prompt 없는 외부 이미지의 일치 검증은 현재 범위에 포함하지 않는다. 현재 다음 후보는 에러코드·응답 Schema 및 남은 Validation 검사 범위 검토다.

우선 **Validation의 첫 항목 V-01**을 검토하는 것을 권한다. ADR-0003에서 넘겨받은 검증 입력·결과와 오류 정책을 이어서 다룰 수 있다. 최초 질문은 ‘Core가 생성한 결과 외에 기존 이미지·외부 이미지의 독립 검증도 제공할 것인가’다. REST 접근 원칙은 이미 확정되어 있으므로 재승인하지 않고, 검증 대상과 결과 이력의 연결 범위를 확인한다.

이후 V-02부터 검사 범위와 실패 의미를 항목별로 검토하고, 관련 주제가 정리되면 ADR 초안을 작성해 하나씩 논의한다. Core를 먼저 검토하는 대조표 순서도 유효한 대안이며, 이 제안 자체로 순서를 확정하지 않는다.

## 실제 동작 검증 준비 — 후속 실행 후보

실행 검증을 진행할 때는 다음 정보를 먼저 확보하고 검증 결과와 함께 기록한다. 현재는 준비 목록이며 설치·실행 절차나 Test 정책의 확정이 아니다.

- Stability Matrix와 ComfyUI 버전·경로, 설치 모델·LoRA·Custom Node 및 실행 Endpoint.
- GPU 드라이버·사용 가능 VRAM과 실제 실행 런타임.
- Anima / SDXL 각각의 최소 생성과 선택적 후처리, PNG·WebP·Alpha 출력 확인.
- Generation과 Local VLM의 개별 VRAM 사용·실행 시간 및 모델 해제 동작. 같은 GPU에서의 동시 실행 가능성은 측정 전 가정하지 않는다.
- 취소·중단 확인과 ComfyUI 재시작 후 작업 상태 확인. 제품 Queue 복구 검증은 해당 계약과 구현 이후 별도로 수행한다.

각 실험에는 사용 모델·버전·Workflow·입력·결과·실패 원인을 남겨 후속 설계의 근거로 사용한다. 이번 작업에서는 제품 코드, 의존성, 실행 환경 또는 CI를 추가하지 않았고 GPU 실행 검증도 수행하지 않았다.
