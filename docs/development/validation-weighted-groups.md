# 가중치 묶음 분리 — 평가 방식 v3

2026-09-13 사용자 지시에 따라 가중치로 묶인 Prompt의 검사 단위를 분리했다. 생성 Prompt를 수정하거나 가중치 값을 변경하지 않는다.

## 구현

`(eyeglasses, dangling earring:1.2)`를 다음 두 시각 요구로 보낸다.

1. `eyeglasses`
2. `dangling earring`

각 항목은 독립 ID로 판정되며, `result.evidence`에는 다음 출처가 연결된다.

- `source_clause`: 원래 묶음 표현
- `source_weights`: 바깥쪽부터 안쪽까지 명시된 가중치 문자열 목록
- `source_groups`: 원래 괄호 묶음 경로
- `requirement`: 분리된 시각 요구

원본 요청의 Positive/Negative Prompt는 그대로 저장한다. AI에는 ID·Positive/Negative 구분·시각 요구만 보내며, 가중치 문법을 눈에 보이는 대상처럼 해석하게 하지 않는다. 원문과 가중치 metadata는 Validation이 보존해 결과에 연결한다. 불합격 finding의 `prompt_excerpt`는 원래 묶음을 가리킨다. 하나의 하위 항목이라도 누락/불일치이면 기존 기준대로 불합격이다.

중첩 `( ... :가중치)`에서도 가중치를 곱하거나 의미를 바꾸지 않고 문자열 경로로 보존한다. 예를 들어 `((blue eyes, silver hair:1.2), hat:0.8)`의 눈·머리 항목에는 `["0.8", "1.2"]`, 모자에는 `["0.8"]`가 연결된다. Negative에도 같은 분리 규칙을 사용한다.

이번 분리는 전체를 둘러싼 정상 괄호 묶음과 쉼표·줄바꿈 목록에 한정한다. `shirt and brooch` 같은 일반 문장은 자동으로 의미 분해하지 않는다. 잘못 닫힌 괄호·대괄호 전환 문법 등은 임의로 해석해 누락시키지 않고 원문 항목으로 유지한다. 이스케이프된 괄호/구분자는 리터럴로 다룬다. 과도한 중첩은 64단계 이후 원문으로 유지한다.

평가 버전은 3으로 올렸다. 이전 평가 버전으로 접수된 대기 작업을 몰래 새 방식으로 실행하지 않으며, 완료 이력은 변경하지 않는다.

## 실제 LM Studio 회귀 검증

평가 v2에서 사용한 이미지 두 장과 사전에 정한 조건 9개를 그대로 재실행했다. Provider 모델·이미지·기대 결과는 바꾸지 않았다.

| 조건 | v2 | v3 |
| --- | --- | --- |
| 원래 생성 Prompt 2건 | 모두 합격 | 모두 합격 |
| 개별 안경·긴 귀걸이 | 합격 | 합격 |
| 가중치로 묶은 안경·긴 귀걸이 | 불합격 오탐 | **합격** |
| 없는 모자·다른 머리색 | 모두 불합격 | 모두 불합격 |
| 가려진 눈·화면 밖 부츠 | 모두 불합격 | 모두 불합격 |
| Negative 파란 의상 위반 | 불합격 | 불합격 |

이번 실행은 **9건 모두 기대 결과와 일치**했다. 이는 같은 이미지/조건 세트의 회귀 결과이며 일반적인 정확도 보장이 아니다. 작은 장식에 대한 시각 판단과 자연어 복합 문장은 여전히 추가 평가가 필요하다. 요청당 약 2~12초였으며 모델 캐시·상주 상태의 영향을 분리하지 않았으므로 처리속도 개선으로 단정하지 않는다.

실제 테스트 중 새 이미지 생성·자동 재생성은 실행하지 않았다. 다음 평가 범위는 전신·측면과 배경이 복잡한 이미지다.
