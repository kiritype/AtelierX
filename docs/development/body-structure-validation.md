# 신체 구조 검사 — 2026-09-21

## 범위와 판정

ADR-0014의 선택 검사 `hands`, `face`, `limbs`를 단일 Validation에 연결한다. Core Profile API와 설정 화면에서 부위별로 선택하며 기본 빈 목록은 유지한다. Prompt에 요청된 요소가 보이는지 확인하는 검사와 분리하고, Metadata 검사는 이번에 구현하지 않는다.

- 보이는 부위에 명확한 구조 이상이 있으면 `body_structure_anomaly`로 불합격이다. 판단 근거와 부위를 기록한다.
- 정상으로 평가할 수 있는 보이는 부위는 `matched`, 가려짐·프레임 밖 등 평가 대상이 안 보이면 `not_visible`로 기록한다. 안 보이는 부위를 추측하거나 단순한 스타일 차이를 이상으로 판정하지 않는다.
- 신체 `not_visible`은 해당 부위 통과도 불합격도 아니다. 별도 Positive 요구가 누락된 경우는 기존 Prompt 누락 불합격 규칙을 유지한다.
- 신체 외의 수행 검사도 없고 선택 부위가 전부 안 보이면 `VAL_NO_ASSESSABLE_CHECKS` 오류로 종료한다. 출력 조건 등 다른 검사가 실제 통과하면 그 범위의 종합 통과는 가능하되 건너뛴 신체 근거는 남긴다.
- 보이는 근거가 불확실하면 `VAL_PROVIDER_INCONCLUSIVE` 오류다. 오류에 자동 재검증·재생성을 붙이지 않는다. Provider 누락·중복·잘못된 응답도 명시 오류이며 합격으로 보정하지 않는다.

위 상태 매핑과 오류 코드는 기존 합의의 구현 상세다. 가려진 부위를 실패시키지 않으면서 수행하지 않은 검사를 통과로 표시하지 않기 위한 것이다. 새 ADR을 Accepted로 변경하지 않는다.

## 이력·설정·운영

이미 접수된 Profile snapshot과 완료 결과는 보존한다. 평가 버전 변경은 실행 전 대기 요청의 구 계약을 묵시적으로 새 판정으로 바꾸지 않도록 기존 `VAL_EVALUATION_CHANGED` 경계를 사용한다. 운영 반영 전 큐와 GPU 상태를 확인해야 한다. 이 문서의 구현 완료와 실행 중 파일럿에 적용된 상태는 별도로 기록한다.

## 작은 실제 VLM 평가의 준비

실제 생성 이미지와 절차적으로 그린 대조 이미지를 섞어 한 가지 데이터인 것처럼 보고하지 않는다. 기존 Anima 이미지의 보이는 얼굴·머리카락에 가려진 눈·프레임 밖 손을 직접 확인하고, 별도 빈 캔버스에 5개와 6개 손가락 그림을 만들어 이상 유무 대조군으로 사용한다. 정답·예상 상태는 모델 호출 전에 고정한다.

단순 손 그림의 개수 판정은 실제 생성 이미지의 손·사지 해부학 품질을 대표하지 않는다. 이 소규모 평가는 전송·판정 분리와 명확한 대조 사례에 대한 탐색이며, 대표 제작 데이터의 오탐/미탐률이나 장기 처리량을 확정하는 시험이 아니다.

첫 호출 약 11.62초, 이후 1.50~2.05초였다. 모델 준비 시간 등을 포함한 사례별 소요이며 장기 처리량을 뜻하지 않는다. 로컬 기록은 `artifacts/body-validation-20260921/cases.json`, `live/report.json`이며 이미지·로그는 Git에 포함하지 않는다. 새 clone에서는 해시가 일치하는 평가 이미지와 로컬 Provider 설정을 별도로 준비해야 한다.

자동 회귀 검증은 Python 전체 244건, Frontend 17건 통과이며 이후 추가한 평가 하네스 단위 테스트 4건도 통과했다. 이 중 Provider 모의 테스트는 상태·계약 검증으로, 위 실제 VLM 결과와 구분한다.

현재 파일럿은 재시작하지 않았다. 신체 검사 및 통합된 Alpha 요구 전달 변경은 소스에 준비됐으나 기존 실행 프로세스에는 아직 반영되지 않았다. 운영 큐를 확인하는 기존 재시작 절차로 반영해야 한다.
