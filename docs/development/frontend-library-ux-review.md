# 전역 조각 라이브러리 UX 검토

## 사용자 확정 — 2026-09-22

- 전역 프롬프트 조각은 캐릭터 작업실과 별도인 관리 화면에서 생성·편집한다.
- 조각은 태그 대신 카테고리로 분류한다. 사용자가 제시한 예시는 표정, NSFW다.
- 조각 번호는 전체 조각에서 중복 없이 사용한다. 카테고리별 번호 재시작 방식이 아니다.
- 번호와 출력 이미지 파일명을 연결할 장기 의도가 있으나 파일명 구조는 보류한다. 후속 사용자 실행 승인으로 번호 자동 부여·불변·재사용 없음, 사용자 관리 단일 계층 카테고리, 기존 결과 기반 이미지셋 조회를 구현 기준으로 확정했다.

## 참고 구조

[ComfyUI-AssetManager 화면](https://github.com/kiritype/ComfyUI-AssetManager/blob/master/web/index.html)과 [라이브러리 코드](https://github.com/kiritype/ComfyUI-AssetManager/blob/master/web/js/library.js)를 확인했다. 프롬프트 라이브러리는 작품/그룹 트리, 검색 가능한 조각 목록, 선택한 세트 조합의 세 열 구조다. 그룹 선택과 조각 선택 상태를 분리하고 그룹 이동·정렬 및 검색을 제공한다.

## 화면 방향 — 사용자 승인, 상세 구현 전

- 전역 조각 관리: 왼쪽 카테고리 탐색, 가운데 번호·이름·본문 요약 목록, 오른쪽 선택 조각의 상세 편집.
- 캐릭터 작업실의 조각 선택: 같은 카테고리와 목록 탐색을 재사용하되, 오른쪽은 이번 생성에 선택한 조각 목록과 총 이미지 수를 표시한다. 원본 편집과 이번 생성 선택은 구분한다.
- 체크박스는 일괄 작업 또는 생성 대상 선택에 사용하고, 행 클릭은 상세 열기에 사용해 두 동작을 혼동하지 않게 한다.
- 화면 정렬 순번과 조각 식별 번호를 시각적으로 구분한다. 검색·정렬·카테고리 전환 시 동일 조각의 번호 표기를 유지한다.
- 참고 프로젝트의 작품 종속 조각 분류와 직교곱 생성은 가져오지 않는다. AtelierX의 전역 공유 조각, 선택 조각 하나당 그룹 이미지 한 장 정책을 유지한다.

2026-09-22 사용자는 조각 관리 → 캐릭터·의상 → 생성 준비 → 진행 상황 → 검증 결과 → 이미지셋의 시안을 구현 방향으로 승인했다. 실사용 불편은 건별로 수정하며, 구현·테스트는 Terra 서브에이전트를 활용하고 주 에이전트가 통합 검토한다. 전체 스타일을 모던하게 정리하고 외부 접속 시 모바일에서도 사용할 수 있도록 한다. 후속 실행 지시로 테스트·PR 생성·develop 병합까지 승인했다. 새 파일 보관 API와 파일명 구조는 이번 범위가 아니다.

## 모바일 및 사전 확인 — 2026-09-22

현재 `frontend/styles.css`에는 720px 이하 단일 열 전환과 갤러리·작업 목록 반응형 규칙이 있다. 기존 [검증 기록](frontend-accessibility-recovery.md)은 320/390/768px의 정적 DOM 표본 12개에서 가로 넘침을 검사했다. 터치·가상 키보드·모바일 브라우저에서 전체 작업 흐름을 검증한 기록은 아니다. 이번 검토에서는 실제 모바일 기기 검증을 실행하지 않았다.

### 구현 수용 기준 제안

- 데스크톱은 카테고리 / 목록 / 상세의 3열을 유지한다. 모바일은 목록을 중심으로 카테고리 선택과 상세 편집을 별도 패널 또는 하위 화면으로 연다. 세 열을 그대로 축소하거나 긴 세로 화면에 모두 쌓는 방식은 피한다.
- 조각 선택 화면은 모바일에서 선택 개수와 생성 확인 진입을 쉽게 찾을 수 있게 한다. 선택 목록은 펼쳐 확인하며 카테고리를 변경해도 유지한다.
- 터치로 모든 기능을 사용한다. 우클릭·hover·드래그·Shift 선택만 가능한 필수 동작을 두지 않는다. 주요 터치 영역은 44px 이상을 목표로 한다.
- 320/360/390/430/768/1024px 및 데스크톱에서 긴 한글 이름·조각 번호·오류 메시지·프롬프트가 화면 밖으로 넘치지 않아야 한다. 글자 확대와 세로/가로 전환도 확인한다.
- 가상 키보드와 기기 안전 영역 때문에 입력창·저장·생성 확인 버튼이 가려지지 않아야 한다. 좁은 화면에서 입력 글자를 줄여 해결하지 않는다.
- 상세에서 뒤로 돌아왔을 때 카테고리·검색·선택·목록 위치를 유지한다. 브라우저 뒤로가기와 미저장 입력 보호를 함께 점검한다.
- 재로그인·화면 복귀 후 Core의 작업 상태를 다시 조회한다. 접수 응답 유실을 실패로 단정해 생성 요청을 자동으로 재전송하지 않는다.
- 이미지 목록은 필요한 범위부터 로드하고 상세 이미지는 선택 시 조회한다. 현재 갤러리의 Blob 조회와 다량 이미지 메모리 사용을 점검한다.

### 검증 구분

반응형 실제 DOM 자동 검사, 브라우저 상호작용 검사, 실제 모바일 기기의 터치·키보드·Access 로그인 검증을 구분해 기록한다. 화면 폭만 바꾼 검사로 모바일 전체 흐름 완료를 보고하지 않는다. 기존 서비스 재시작과 GPU 실행은 사전 검토의 일부로 수행하지 않는다.

### 코드 대조 결과

- `core_fragments.py`에는 UUID·이름·본문·상의/하의 포함·revision·보관 여부만 있다. 카테고리와 전역 표시 번호는 Core 저장 및 API 확장이 필요하다. 기존 조각과 과거 snapshot을 보존하는 마이그레이션이 선행되어야 한다. 목록 순번을 고유 번호로 사용하지 않는다.
- 초기 사전 검토 뒤 사용자 실행 지시로 번호는 자동 부여·변경 및 재사용 없음, 카테고리는 사용자 관리 단일 계층으로 확정했다. 파일명 설계는 보류한다.
- 별도 `image_set` 저장 엔티티는 없다. 기존 group은 의상 revision을 고정하고 production plan은 생성 대상과 단일/묶음 검사 결과를 연결한다. 우선 이미지셋을 캐릭터/의상별 기존 결과의 조회 화면으로 구성하는 것을 권고한다. 새 수동 컬렉션·파일 이동·복사·자동 보관 정책을 시안에서 추론하지 않는다. 현재 유효한 단일/묶음 판정을 구분한다.
- 제작 계획 상태·항목·비교 API는 존재한다. 실행 완료와 품질 통과를 구분하고, Node 내부 진행률을 임의로 표시하지 않는다. 현재 의상 원본과 과거 고정 그룹을 구분한다.
- `app.js`의 상세 선택 상태는 메모리에 있고 hash는 상단 메뉴 중심이다. 모바일 상세 뒤로가기·재로그인 복귀·초안 유지 경로를 보완해야 한다.
- `gallery.js`는 `loading=lazy` 이미지에도 목록 렌더링 시 Blob 요청을 시작한다. 모바일 데이터·메모리 절약에는 실제 이미지 요청 지연/동시성 관리가 필요하다.
