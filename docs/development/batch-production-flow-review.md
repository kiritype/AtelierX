# 대량 제작 flow 재검토

2026-09-13 최신 사용자 정정: 조각 기반 제작에서는 **외형을 항상 포함**한다. 전역 공유 조각은 본문과 **상의·하의 포함 여부만** 저장하며 appearance 선택 필드는 두지 않는다. 아래 과거 조각별 외형 선택 설명을 대체한다. 전역 Positive + 외형 + 선택한 상의/하의 + 조각 본문, 전역 Negative + 캐릭터 Negative를 사용한다. 구현·테스트를 계속 진행하도록 승인됐다.


## 최우선 확정 — 전역 공유 조각과 조각별 포함 영역

2026-09-13 사용자가 조각별 외형·상의·하의 포함 여부와 작품/캐릭터/의상으로부터 독립된 전역 공유 조각을 확정했다. 이 절은 아래 이력의 캐릭터 연결 조각 및 별도 공통 Prompt 권고를 대체한다. 현재는 문서 반영이며 코드 구현 완료가 아니다.

- 조각은 전역 라이브러리에 저장하며 특정 작품·캐릭터·의상을 필수 소유자나 필수 연결 대상으로 두지 않는다. 모든 제작 대상에서 같은 조각을 선택할 수 있다.
- 조각은 이름, 사용자 작성 본문, `include: {appearance, upper, lower}` 세 bool을 가진다. revision·보관 등 저장 상세는 기존 데이터 관리 관례를 따르는 구현안이다.
- 구도·표정·자세/동작·상황·배경은 조각 본문에 함께 작성한다. 별도 공통 Prompt나 독립 축 조합을 기본으로 두지 않는다.
- 사용자는 제작할 작품/캐릭터/의상 그룹을 선택한 뒤 전역 조각을 체크한다. 한 대상 그룹에서 선택한 조각 하나가 하나의 이미지 변형을 정의한다. 여러 줄이나 쉼표를 별도 후보로 분리하지 않는다.
- Core Positive = 전역 품질 + 선택 조각이 포함하도록 지정한 고정 의상 그룹의 외형·상의·하의(이 순서) + 조각 본문. 포함 여부는 실제 선택 조각에서 가져오며 모든 의상 요소를 무조건 넣지 않는다.
- Negative = 전역 Negative + 대상 캐릭터 Negative. 조각을 공유해도 캐릭터별 Negative를 다른 캐릭터에서 가져오지 않는다. 전역 Negative는 생성용, 캐릭터 Negative는 금지 요소 검증용이라는 기존 책임을 유지한다.
- 제작 계획에는 조각 ID/revision/본문/include와 대상 그룹, 전역 설정·캐릭터 Negative·생성/검사 설정을 고정한다. 전역 조각 편집이 이미 접수한 다른 캐릭터의 작업이나 과거 결과를 바꾸지 않는다.
- 예: 조각 `상반신 놀람`의 본문 `upper body, surprised, hands raised, white background`, include는 외형=true, 상의=true, 하의=false. 같은 조각을 다른 캐릭터에 사용하면 각 대상 의상의 외형·상의와 각 캐릭터 Negative가 적용된다.

갱신된 흐름은 **전역 조각 작성 → 대상 의상 그룹 선택 → 조각 체크 → Core 최종 Prompt/수량 미리보기 → 개수 상한 없는 논리 Queue 접수 → 생성·단일 검증 → 그룹별 동일 기준 묶음 검증**이다. 내부 분할·영속 계획·재시작·취소 요구는 유지한다. 다음 계약 정리 대상은 전역 조각 CRUD와 이 snapshot을 사용하는 제작 계획 API다.

## 최신 조합 정정 — 2026-09-13

사용자는 기본 구도 1개, 표정·동작은 한 묶음으로 사용한다고 명시했다. 구도/표정/동작 분류를 없앤 단일 Prompt 조각 모델도 허용했다. 수천 개 이미지를 한 번에 논리적 Queue에 접수할 수 있어야 하며 32개 제품 제한은 해제한다. 아래 이전 권고 중 독립 축을 기본으로 곱하는 단계 3~4와 3×5×4 예시는 이 정정으로 대체된다.

**갱신 권고안:** 조각은 유형을 강제하지 않는 이름+본문으로 저장하고 캐릭터에 연결한다. 제작 시 공통 Prompt 한 곳에 기본 구도·배경 등을 입력하고, 사용자가 표정+동작(+필요한 상황)을 함께 작성한 조각을 체크한다. 체크한 조각 하나가 이미지 한 장의 변형을 정의한다. 한 조각의 줄·쉼표를 다시 나누거나 표정과 동작을 독립적으로 곱하지 않는다. 공통 Prompt는 조각의 필수 분류가 아니라 해당 제작 계획의 공통 입력이다. 공통 구도가 필요 없는 작업에서는 각 조각에 구도까지 작성할 수 있다.

예: 공통 `upper body, white background, simple background`; 조각 A `surprised, hands raised`; 조각 B `embarrassed, looking away`; 조각 C `smiling, waving`. A/B/C를 체크하면 같은 캐릭터·의상 그룹에 이미지 3장을 계획한다. 별도의 반복 수나 여러 의상 전개는 명시적인 추가 선택으로만 취급하며 이번 조합 규칙에 암묵적으로 추가하지 않는다.

최종 Prompt 조합은 Core가 전역 품질 + 고정 의상 구성 중 포함 영역 + 공통 Prompt + 선택 조각 본문 순으로 수행하는 것을 권고한다. 기존 전역/캐릭터 Negative 책임은 유지한다. 공통 Prompt와 조각이 충돌하면 자동 덮어쓰기하지 않고 확인 가능한 충돌을 preview에서 표시한다. 공통값·선택 조각 revision·포함 영역·Seed·검사 설정은 접수 계획에 고정한다.

**Queue 의미:** 사용자가 3,000장을 접수하면 전체 3,000장의 계획과 대기 상태를 Core가 영속적으로 수락·표시해야 한다. 실행 직전의 소수 항목만 전체 계획인 것처럼 표시해서는 안 된다. 화면 페이지 크기·전송 청크·실행 워커 수에는 기술적 경계가 있을 수 있으나 전체 생성 개수 제한이 아니다. ComfyUI/GPU에 대한 동시 실행은 자원에 맞춰 공급하고, 나머지 대기 항목도 조회·취소·재시작 복구할 수 있어야 한다. 모든 Task의 큰 snapshot을 단일 HTTP body/JSON 문서로 보내는 구현은 피한다.

**검증 보강:** 3,000개 선택 계획의 총수·대기 표시, 체크 항목과 생성 항목의 일대일 대응, 표정·동작 묶음 보존, 공급 전 대기 항목 취소, 분할 공급 중 재시작·응답 유실, 32개 초과 묶음 비교를 확인한다. 3,000은 시험 규모이며 제품 상한이 아니다. 현재 코드는 아직 32개 제한을 포함한다. 이번 작업은 요구·flow 문서 정정이며 제한 해제 구현 완료가 아니다.

## 확정된 사용자 요구

- 캐릭터별 수십 장 이상 생성할 수 있으며 제품 차원의 생성 개수 제한을 두지 않는다. 32개 초과를 지원한다.
- 사용자가 입력한 Prompt 조각을 체크하여 가져온다. AI의 자동 조각 생성이나 무작위 조각 선택을 요구한 것이 아니다.
- 구현 전에 현재 생성·검증 flow와의 호환성을 재검토한다.
- 기존 작품 > 캐릭터 > 의상 분류, 단일/묶음 검증 분리, 오류 시 자동 이미지 재생성 금지, 설정 가능한 자동 재생성 상한 기본 5회는 유지한다. 생성 개수 무제한과 이미지별 재생성 상한은 별개다.

이 요구는 최초 검토의 32개 초과 거절 권고를 대체한다. 아래 조합 UX·내부 처리 방식은 재검토 권고안이며 구현 완료나 사용자 승인된 신규 정책으로 기록하지 않는다.

## 권고하는 사용자 흐름

1. **조각 작성·연결:** 사용자가 이름과 본문을 작성하고 구도·표정·자세/동작·상황별로 저장한다. 여러 줄도 하나의 조각 본문이다. 캐릭터에 사용할 조각을 연결하되 체크 전에는 생성 Prompt에 자동 삽입하지 않는다. 외형·복장은 기존 의상 데이터가 담당한다.
2. **제작 대상 선택:** 제작 화면에서 작품·캐릭터·의상을 선택한다. 대량 편집도 제작 화면에 두며 작업 현황은 실행 후 조회·취소·복구를 담당한다. 여러 의상을 선택하는 확장은 의상별 고정 이미지 그룹으로 구분해야 한다.
3. **체크로 가져오기:** 해당 캐릭터에 연결된 사용자의 조각을 표시하고 구도·표정·동작·상황별 후보를 체크한다. 조각 전체가 후보이며 본문의 줄·쉼표를 후보 경계로 취급하지 않는다.
4. **조합 확인:** 권고는 같은 항목에서 체크한 조각은 대안 후보, 다른 항목끼리는 조합하는 방식이다. 구도 3 × 표정 5 × 동작 4 × 상황 1이면 60장이다. 한 이미지에 함께 넣을 `upper body, white background, simple background`는 하나의 구도 조각에 작성한다. 같은 항목의 여러 조각을 한 이미지에 합치는 방식은 후보 조합과 구분해 명시적 UI로 제공해야 하며 자동으로 추측하지 않는다. 선택 없는 선택 항목은 빈 본문 한 가지로 처리하고, 필수 구도·신체 영역은 미리보기 전에 확인한다.
5. **Core 제작 계획:** 선택 조각과 revision, 의상 그룹, 포함 영역, 생성·검사 설정, 최종 Seed를 고정한다. Core가 조합 수와 페이지별 최종 Prompt를 제공한다. 전체를 한 응답으로 전송하지 않는다. 사용자에게 표시한 계획을 실행하며 조각 편집은 이미 접수한 계획을 바꾸지 않는다. 계획 고정 시점과 실행 사이의 변경·stale 처리는 명시적인 계획 식별자/hash로 검증한다.
6. **실행:** 하나의 논리적 제작 작업으로 접수한다. Core가 저장된 순서와 고유 항목 키를 따라 필요한 만큼 생성 요청을 공급한다. 내부 묶음 크기는 메모리·GPU·요청 크기를 위한 처리 단위이며 사용자의 총 생성 수 상한이 아니다. 여러 조각을 임의로 제외하거나 작업을 임의로 잘라내지 않는다.
7. **단일 검증:** 각 결과와 실제 생성 Prompt로 검증한다. 불합격의 자동 재생성은 기존 설정 범위에서 처리하고 오류는 에러코드와 수동 처리 대상으로 남긴다. 실패 한 장 때문에 전체 조합을 다시 생성하지 않는다.
8. **그룹 검증:** 동일 작품/캐릭터/의상 그룹의 계획 항목이 종료되면 통과 결과를 모은다. 기존 기준이 없거나 변경되면 기존 기준 선정·확인 경계를 유지한다. 대상이 많으면 동일한 대표·보조 기준 및 revision으로 비교 대상을 내부 분할한다. 내부 묶음마다 독립 기준을 선정하지 않는다. 전체 결과는 논리 그룹 단위로 집계하며 부족·오류·미검증이 남으면 전체 합격으로 표시하지 않는다.
9. **결과·복구:** 작업 현황에서 총 계획·대기·생성·단일 검사·묶음 검사·실패를 구분한다. 취소는 신규 항목 공급을 멈추고 기존 결과·이력을 보존한다. 재시작 시 확정 계획·Seed·진행 위치·멱등성 키를 복원해 중복 생성하지 않는다. 일관성 문제가 있는 이미지의 선택 재검증·교체는 기존 정책을 따른다.

## 구현 전에 검증할 시나리오

- 60개와 1,000개 계획을 잘림 없이 계산·페이지 조회하고 모든 항목을 정확히 한 번만 공급한다. 이는 시험 규모이며 새로운 제품 상한이 아니다.
- 조각 여러 줄은 한 후보로 유지하고 체크 해제 조각은 Prompt에 나타나지 않는다.
- 접수 후 조각·의상·설정 편집에도 계획과 과거 결과가 바뀌지 않는다.
- 내부 분할 경계에서 재시작·응답 유실·취소가 발생해도 중복/누락이 없다.
- 32개를 넘는 통과 결과도 그룹 검증이 끝나며, 모든 내부 요청이 같은 기준 revision을 사용한다.
- 기준 교체·부분 오류·비교 부족을 전체 합격으로 집계하지 않는다.
