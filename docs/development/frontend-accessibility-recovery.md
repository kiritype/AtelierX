# Frontend 배치·접근성·오류 복구 검증

2026-09-13, [선택 교체 검증](frontend-pilot-refinement.md) 후속. 확정된 파일럿 기능 범위 안에서 Terra 서브에이전트가 API·갤러리 회귀를 보완하고 주 에이전트가 통합·브라우저 검증을 수행했다. Backend 서버 재시작이나 GPU 생성은 수행하지 않았다.

## 발견한 문제와 변경

- 작업 현황의 상태 배지가 긴 Task/Batch ID를 한 줄로 유지해 320px 배치에서 가로 넘침을 일으켰다. 해당 배지는 줄바꿈과 단어 분할을 허용한다. 링크와 버튼 역할 요소의 키보드 초점 윤곽도 명시했다.
- 갤러리에서 이전 상세의 비동기 registry·그룹·검사 결과가 새 상세에 추가될 수 있었다. 상세 세대 확인을 일관되게 적용한다. 상세 이미지 조회 실패에는 `이미지 다시 불러오기` 버튼을 제공하고 교체된 Blob URL을 해제한다.
- API timeout이 응답 헤더 수신까지만 적용되던 문제를 수정했다. JSON·이미지 본문 수신까지 타이머를 유지하고 본문 수신 중 abort도 `CLIENT_TIMEOUT`으로 반환한다.
- 이미지 응답의 Core 인증 오류 코드와 HTTP status를 보존한다. JSON·binary 읽기 실패, 직렬화 불가 요청, 잘못된 경로는 클라이언트 오류로 구분하며 생성 요청 자동 재전송은 추가하지 않는다.

## 실행한 검증

실제 파일럿 브라우저에서 잘못된 토큰 제출 → `CORE_UNAUTHORIZED` 표시 및 연결 버튼 재사용 → 올바른 토큰 재연결을 확인했다. 재연결 후 갤러리 카드에 Enter 키를 보내 실제 이미지 상세가 열림을 확인했다. 제작·작업 현황·설정의 열린 화면과 갤러리 상세에서 검사한 input/select/textarea는 모두 label 또는 aria-label이 연결되어 있었다.

모바일 배치는 실제 앱에서 렌더링된 네 화면 DOM을 복사하고 실행 스크립트를 제거한 임시 검사 페이지에서 검증했다. 현재 CSS를 적용한 iframe 폭 320·390·768px, 총 12개 조합에서 최종 document scrollWidth가 clientWidth를 초과하지 않았다. 스크롤바가 있는 경우 실내용 폭은 지정 폭보다 15px 작다. 수정 전 작업 화면 320px에서는 client 305 / scroll 331이었고 수정 후 305 / 305였다. 320px 갤러리와 작업 화면은 스크린샷으로도 확인했다.

이 검사는 **정적 렌더링 표본의 반응형 배치 검사**다. 모바일 브라우저의 실제 터치 입력·가상 키보드·모든 폼 상태·스크린리더 적합성을 검증한 것으로 간주하지 않는다. DOM 표본은 입력의 현재 property 값이나 이벤트 핸들러를 재현하지 않으며 생성/저장 요청도 보내지 않는다.

Node API·작업 현황·갤러리·설정 테스트와 JavaScript 구문 검사, diff 검사가 통과했다. API 회귀에는 오프라인 POST 1회 전송, 401, malformed JSON, 직렬화 실패 무전송, 이미지 오류, 헤더 수신 후 JSON/blob 본문 timeout이 포함된다. 갤러리 회귀는 상세 세대 판별을 포함한다. Blob 오류 후 재시도 버튼의 실제 통신 장애 브라우저 시험은 이번 범위에서 수행하지 않았다. Backend 변경이 없어 Python 전체 테스트는 재실행하지 않았으며 직전 결과는 174개 통과다.

배치 측정 원본: `artifacts/frontend-pilot/responsive-report.json`. 렌더링 표본과 검사 페이지: `artifacts/frontend-pilot/responsive/` (제품 배포 파일 아님). 검사 서버는 파일럿과 별도로 localhost 8192에서 사용 후 종료한다.

## 다음 검증

실제 모바일 입력·스크린리더와 이미지 조회 장애 후 브라우저 복구 검증이 남아 있다. 모델 목록·작품/캐릭터/의상 ID의 이름 탐색, 설정 충돌 차이 비교 UI도 후속 파일럿 개선 대상이다.
