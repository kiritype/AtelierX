# 작업실 UI·모바일 대응 — 2026-09-22

사용자가 승인한 [조각 라이브러리·제작 흐름](frontend-library-ux-review.md)을 구현했다. 개인 제작을 기준으로 조각 관리 → 캐릭터 작업실 → 작업 현황 → 이미지셋을 나누고 설정을 별도 메뉴로 유지한다.

## 구현

- 전역 조각은 사용자 관리 단일 계층 카테고리로 분류한다. Core가 전체 고유 번호를 자동 부여하며 변경·재사용하지 않는다. 기존 UUID와 과거 revision/snapshot은 보존한다. 파일명 규칙은 아직 정하지 않았다.
- 조각 화면은 카테고리, 검색·페이지 목록, 편집·이력으로 구성한다. 모바일에서는 카테고리를 접고 목록과 상세를 전환한다. 미저장 입력을 보호하고 현재 브라우저 탭의 화면 이동에서 초안을 유지한다. 새로고침 이후 초안 영속 저장 기능은 아니다.
- 작업실은 작품 > 캐릭터 > 의상 준비와 생성 준비를 분리한다. 조각을 여러 페이지에서 선택해도 선택을 유지한다. 조각 CRUD는 조각 관리에서 수행하며 고정 계획·프롬프트 합성·실행은 기존 Core API에 맡긴다.
- 이미지셋은 기존 캐릭터·의상별 결과 조회다. 별도 수동 컬렉션이나 파일 복사 기능은 추가하지 않았다. 단일 통과와 그룹 일치 필터를 함께 제공하며 기준 이미지와 검사 오류를 품질 통과로 합치지 않는다.
- 갤러리 미리보기는 화면 근처에서 요청하며 동시 Blob 조회를 3개로 제한한다. 상세에서 과거 프롬프트와 설정을 접어 확인한다.
- 일관된 어두운 색상, 간격, 메뉴와 입력 요소를 적용했다. 좁은 화면의 작업실 분류/편집 및 갤러리 목록/상세를 분리하고 안전 영역·움직임 줄이기를 반영했다.

브라우저 fixture는 별도 임시 DB, 31개 조각과 테스트 작품/캐릭터/의상을 사용했다. 테스트 전용 인증 주입으로 로컬 화면을 검증했으므로 실제 Cloudflare Access 인증 성공으로 해석하지 않는다. 갤러리 초기 화면은 빈 목록이며 다량 이미지의 실제 네트워크·메모리 사용량은 후속 검증이다. 35개 초기 화면 검사는 모든 오류/상세 상태를 포괄하지 않는다.

로컬 로그: `artifacts/full-suite/studio-python.log`, `studio-node.log`, `studio-responsive.json`. 로그와 fixture·DB는 Git에 포함하지 않는다.

## 실사용 적용 및 남은 확인

기존 Core/Generation/Validation·ComfyUI·Discord 큐 확인 후 파일럿 재시작을 시도했으나, 프로세스 명령행을 식별할 수 없어 기존 도구가 `Unexpected service process. Restart skipped.`로 중단했다. 서비스 강제 종료나 권한 우회는 하지 않았다. 코드의 원격 병합과 실사용 서비스 재시작은 별개다.

서비스를 시작했던 권한의 PowerShell에서 기존 `.atelierx/discord/restart-pilot.ps1`을 실행해야 새 Core API와 정적 모듈 허용 목록이 반영된다. 도구의 큐 확인을 유지하고, 실행 중인 작업이 있으면 완료 후 재시작한다. Tunnel 변경은 필요 없다. 새 clone에는 이 로컬 스크립트·토큰·DB가 없으므로 저장소의 파일럿 실행/원격 접근 문서대로 별도 구성해야 한다.

다음 확인은 사용자의 실제 휴대전화에서 조각 편집 → 캐릭터 준비 → 소규모 생성·검증 → 이미지셋 조회다. 새 UI로 실제 생성·VLM 품질까지 검증했다고 보고하지 않는다. 불편함은 실사용 사례별로 보완한다.
