# 다른 이미지·구도에서의 Validation 평가

2026-09-13 사용자 진행 지시에 따라 평가 방식 v2를 바꾸지 않고 이전 평가에 쓰지 않은 생성 이미지 2장에 대해 9개 조건을 실행했다. Provider는 LM Studio의 `qwen3-vl-8b-instruct-abliterated`다. 실제 이미지·Prompt를 사용하는 순차 요청이며 새 이미지 생성, 자동 재생성, 외부 API 호출은 하지 않았다.

## 평가 자료와 기대값

기존 Generation REST 결과 `artifacts/generation-rest/20260913-033051`에서 두 이미지를 사용했다.

- `anima-base.png`: 안경·긴 귀걸이·주황/갈색 머리·짙은 재킷의 상반신 인물.
- `anima-multi-lora.png`: 밝은 머리·파란 겉옷·흰 상의의 허벅지 부근까지 보이는 인물. 앞머리가 한쪽 눈을 가리고 있다.

시각 검토를 통해 각 조건의 기대 결과와 이유를 실행 전에 `cases.json`에 저장했다. 이는 소규모 에이전트 검토 기준이며 독립 전문가 평가 데이터는 아니다. 원래 생성 Prompt 두 건은 당시 Job에서 읽었고, 나머지는 진단용 입력으로만 사용했다. Core의 원래 생성 이력은 수정하지 않았다.

## 남은 문제

가중치로 묶은 요구에서 모델은 안경은 있다고 했지만 긴 귀걸이는 없고 작은 귀걸이만 보인다고 주장했다. 이미지에는 긴 귀걸이가 보이므로 오탐으로 기록했다. 동일 이미지에서 항목을 따로 요구하면 합격했으나, 이것만으로 가중치 문법을 원인으로 확정할 수 없다. 복합 항목에서 작은 장식의 시각 판단이 달라지는 문제다. 결과를 맞추려고 이번 평가 도중 지침이나 정답을 수정하지 않았다.

항목 ID의 완전성과 판정 집계는 보장하더라도 모델이 잘못된 시각 근거를 반환하는 문제까지 제거되지는 않는다. 다음 보완 대상은 원문·가중치 연결을 보존하면서 복합 요구를 더 작은 검사 단위로 분리하는 방법과 작은 장식 평가다. 전신, 측면/후면, 배경이 복잡한 이미지, 다른 모델/seed의 반복 평가는 아직 남아 있다.


이번 변경은 평가 스크립트와 기록 추가이며 제품 판정 코드는 변경하지 않았다. 이전 [항목별 근거 검증](validation-element-evidence.md)의 구현·회귀 테스트와 구분한다.
