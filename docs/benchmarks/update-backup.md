# 업데이트 백업과 시작 대기 측정 (#323)

2026-11-14, Windows 개발 PC의 같은 로컬 C: 볼륨, Python 3.12, 파일 캐시를 비우지 않은 조건에서
합성 데이터로 3회 측정했다. 정책 순서를 회차마다 바꿨다. 표는 중앙값이며 실제 사용자 설치의 소요 시간은 아니다.
탐색은 대상 목록 작성, 쓰기는 ZIP 압축·디스크 쓰기를 포함한다. 네트워크와 앱 전체 시작 시간은 제외했다.

재현: `uv run python tools/benchmark_update_backup.py --parent notes/benchmark --rounds 3 --cleanup`.
새 시험 폴더만 만들고 보존한다. 모든 ZIP 항목을 읽어 원본과 SHA256을 비교한다.

## 텍스트·이미지 혼합

633개 파일, 71,187,145바이트: 텍스트 600개, 설정 1개, 1024×1024 PNG·JPEG 각 16개.
백업 제외 캐시 4,000개를 함께 둔다. 이미지는 고정 난수로 만들어 재현 가능하다.

| 정책 | 탐색(초) | 쓰기(초) | 합계(초) | ZIP(바이트) |
|---|---:|---:|---:|---:|
| 기존 전체 탐색 + deflate 6 | 0.2248 | 1.6798 | 1.9046 | 65,563,209 |
| 제외 폴더 가지치기 + deflate 1 | 0.0099 | 1.5985 | 1.6082 | 65,591,864 |
| 채택: 가지치기 + 압축 파일 저장 + 나머지 deflate 1 | 0.0099 | 0.2083 | 0.2182 | 65,601,935 |

채택 정책의 시간은 약 88.5% 감소, ZIP은 약 0.06% 증가했다. 모든 복원 해시가 일치했다.
이미 압축된 PNG/JPEG/WebP/ZIP/GZ/7Z/MP4는 저장만 하고 나머지는 빠른 압축을 적용한다.
백업에 포함하는 파일 범위는 기존과 같다.

## 텍스트만 있는 경우

같은 명령에 `--images 0 --excluded 0`을 지정한다. 601개, 5,727,017바이트의 반복 텍스트·설정이다.
기존은 0.1499초·111,806바이트, 채택 정책은 0.1186초·137,943바이트였다.
시간은 약 20.9% 감소하고 ZIP은 26,137바이트(약 23.4%) 커졌다. 모든 복원 해시가 일치했다.
텍스트 비중과 반복 정도에 따라 공간 손해가 더 두드러질 수 있다.

## 구버전 정리

2KB 파일 2,000개로 기존 동기 삭제와 새 준비 기록·이동을 비교했다.
시작 전 정리 단계 중앙값은 0.2600초에서 0.0091초로 줄었다.
새 방식의 재귀 삭제 0.3736초는 창 로드 후로 이동한다. 삭제 자체가 빨라졌다는 의미는 아니다.
화면 로드 이벤트 전에는 작업을 시작하지 않는 대역 테스트와 종료 시 중단·다음 실행 재시도 테스트로 순서를 확인했다.

실제 배포 패키지의 창 표시까지 걸리는 시간과 실제 사용자 파일 구성에서의 성능은 별도 측정이 필요하다.
실제 Windows PowerShell 교체·롤백은 기존 테스트로 검증하며 외부 릴리스를 설치하는 실서비스 시험은 수행하지 않았다.
