# JSX 사용 규칙

챗봇 화면용 JSX 컴포넌트를 쓰고, 챗봇이 응답에 컴포넌트를 넣도록 프롬프트용 문구를 만들 때 따르는 규칙이다. 플랫폼마다 다르므로
플랫폼 프리셋에 같은 이름의 파일을 두고 고쳐 쓰는 것을 권한다.

## 실행 환경

- 컴포넌트는 채팅 플랫폼의 샌드박스에서 실행된다. 부모 문서, 쿠키, `localStorage`·`sessionStorage`·IndexedDB 같은 저장소에 접근하지 않는다.
- `fetch`·`XMLHttpRequest`·`WebSocket` 같은 외부 통신을 쓰지 않는다. 외부 CSS 라이브러리와 패키지를 가져오지 않는다.
- 오디오·비디오 자동 재생이나 외부 미디어 제어에 기대지 않는다.
- HTTPS 이미지·폰트는 플랫폼이 허용하는 범위에서만 쓰고, 없어도 필수 기능은 동작하게 한다.
- 훅과 전역 함수는 플랫폼 프리셋에서 허용한 것만 쓴다. 훅은 `React.useState`가 아니라 `useState`처럼 바로 부른다.
- 파일 하나에 함수 컴포넌트 하나. 플랫폼이 함수를 그대로 평가하므로 `import`·`export`, 렌더 루트, 앱 시작 코드를 넣지 않는다.
- 스타일은 인라인 스타일이나 반환하는 트리 안의 `<style>`만 쓴다.
- 플랫폼이 제공하는 함수(메시지 보내기, 알림 등)는 렌더 중에 부르지 않는다. 클릭·제출 같은 사용자 행동에서만 부른다.
- props가 없거나 형식이 틀려도 깨지지 않게 기본값을 둔다. 긴 문자열과 줄바꿈은 `whiteSpace: 'pre-wrap'`, `overflowWrap: 'anywhere'`로 표시한다.
- 앱의 미리보기에서 그려져도 실제 플랫폼에서 한 번 더 확인한다.

## 데이터 설계

- AI가 매 응답 만드는 고정 구조의 목록은 객체마다 같은 키를 되풀이하지 않도록 `data` 속성에 JSON 배열과 순서가 정해진 튜플을 우선 쓴다.
  - 예: `[{"name":"서윤","hp":80},{"name":"도윤","hp":65}]` → `[["서윤",80],["도윤",65]]`
- 튜플의 자리 순서·타입·길이는 메인 프롬프트(또는 관련 로어북)의 출력 양식에 적고, 컴포넌트의 인덱스 매핑과 늘 맞춘다.
- 루트는 객체로 두고 수치 묶음·사건·반복 목록처럼 순서와 길이가 고정된 부분만 튜플로 바꾼다. 선택 필드가 많거나 항목마다 구조가 다른 데이터는 객체로 둔다. 토큰 절감보다 형식이 정확하고 복구할 수 있는 쪽이 먼저다.
- 튜플로 바꾸는 것은 줄어드는 키 토큰과 늘어나는 순서 설명·예시 토큰을 함께 따져 실제로 줄어들 때만 한다.
- 화면 안에서만 쓰는 ID와 목록 키는 컴포넌트가 순번이나 내용으로 만든다. 응답 사이에서 같은 항목을 이어 추적하거나 사용자 명령의 대상을 가리킬 ID만 AI가 출력한다.
- 기준 필드 하나에서 정해진 방법으로 계산할 수 있는 값은 AI가 따로 출력하지 않는다. 기준이 없거나 틀리면 컴포넌트가 분명한 기본 표시를 보인다.
- 응답에 남겨 다음 턴의 상태·키워드로 이어 쓰는 값(지속 토큰)을 설계할 때, 늘 하나만 있는 분류 값과 개수가 바뀌는 값을 한 문자열에 섞지 않는다. 분류는 고정 길이 튜플, 바뀌는 값은 별도 배열로 둔다.
- 컴포넌트는 배열 입력을 렌더링 전에 이름 있는 내부 객체로 바꾸고, 길이·타입이 틀리거나 빈 배열이면 방어한다.
- 객체 형식을 배열 형식으로 바꿀 때, 이미 배포한 챗봇이면 컴포넌트가 옛 형식도 읽게 하되 프롬프트 예시는 새 형식 하나만 쓴다. 배포 전이면 새 형식 하나로 정리한다.

## 응답에 넣는 방식

- 컴포넌트 태그는 코드 블록이나 백틱으로 감싸지 않고 일반 텍스트로 출력한다. 감싸면 화면에 그려지지 않는다.
- `<컴포넌트이름 속성='값' />` 형태로 넣는다. 속성 값의 표기(문자열, JSON 등)는 플랫폼 프리셋을 따른다.
- 문자열 안의 줄바꿈·따옴표는 플랫폼의 표기 규칙을 따른다.
- 한 응답에 같은 컴포넌트를 몇 번 넣을지, 어디에 넣을지(예: 맨 끝에 한 번)를 정한다.

## 프롬프트용 문구

- 문구에는 차례로 넣는다: 언제 출력하는지, 출력 양식(자리표시 값), 각 필드의 뜻과 값의 범위, 언제 값을 바꾸는지, 실제 값을 넣은 예 하나.
- 양식 줄의 자리표시는 무엇이 들어갈지 알 수 있게 쓴다("장소", "HH:MM"). 튜플이면 자리마다 뜻을 순서대로 적는다.
- 예는 실제로 읽히는 형식으로 쓰고, 태그를 코드 블록으로 감싸지 않는다.
- 필드가 많으면 바뀌는 필드만 쓰게 할지, 매번 전부 쓰게 할지를 문구에 분명히 적는다.
